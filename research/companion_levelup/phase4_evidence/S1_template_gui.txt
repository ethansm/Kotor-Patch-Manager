## Template recommendation (for Mod 3 style createLabel: new 0x148 + CSWGuiLabel ctor 0x419740 + InitControl(panel, ctl, CExoString(tag), addToList=0, scale=1); template tag must exist in THE SAME panel's layout, here character_p.gui)
Mod 3 used LBL_QUEUE1 (type 4, white dialogfont16x16, align 9, BORDER corner/edge/fill all empty, FILLSTYLE 2, 20x20, text '') (live mipc28x6_p.gui) and LBL_MOULDING3 (framed). Native character-screen equivalents:
- **Plain text/icon label: LBL_EXPERIENCE_STAT (id 25)** - type 4, BORDER corner/edge/fill empty, FILLSTYLE 2, DIMENSION 0 (identical border block to LBL_QUEUE1), no strref, literal text '0,000,000', font dialogfont16x16, align 18 (centre), text colour (0.102, 0.698, 0.549) = the screen's green stat colour, extent [60,449,108,18].
  Our createLabel overrides rect (vt[1] SetRect), text (0x416E30), font (0x416DE0), alignment (0x416FA0) and optionally fill (border+0x74) - same as Mod 3, so the template only contributes colour + the empty border. Consequence: text is GREEN by default (matches the page); Mod 3 has no text-colour setter (set TEXT colour only if wanted, I).
  The bound original (panel member at the ctor bind) is rewritten every tick by SetStats with the XP number - irrelevant, our label is a separate object cloned from the layout struct (InitControl with addToList=0 does not touch the panel list / member pointer, per doc 07 Phase R).
- **Framed background: LBL_XP_BACK (id 3)** - corner uibit_brdr_16wct, edge uibit_brdr_16wet, FILL uibit_fill_2wt, FILLSTYLE 2, DIMENSION 16 (native framed panel analogue of LBL_MOULDING3); createLabel keeps an existing fill ("template already has a fill, keeping it").
- Avoid: LBL_MORE_BACK (id 2; FILLSTYLE 0 + corner/edge frame), LBL_STR..LBL_CHA (stat numbers with literals), strref labels (LBL_STRENGTH ... carry strref text), LBL_FORCEMASTERY (id 68, added by the user's mod, not vanilla), LBL_3DCHAR (bound to the 3D scene view, I).
- Sentinel check from createLabel (ctl+0x54 == IdSentinel after InitControl -> tag missing) works unchanged; if the live .gui ever drops LBL_EXPERIENCE_STAT, fall back to LBL_XP_BACK then skip.
- Ids: the live layout has gaps (42-51, 62-64, 67) and goes to 150; the panel control list is indexed by id with padding (InitControl pads via 0x83EA60), so createLabel's "append at the panel count, id = index" convention (Panel_CtlCount read at runtime) stays correct; never reuse a gap id by hand (I).
