## InitControl facts (U1_raw_decomp_load.txt:307-396; DB row 0040f620)
- 0x40F620 thiscall(panel, ctl, CExoString* tag, addToList, scale) RET 16: 0x418DF0(ctl) stores ctl+0x38 = *(panel+0x30) (the layout GFF), scans panel+0x34 CONTROLS list for the tag and calls ctl vtable[0x48] (label: 0x4198D0). Extent scaled by screen/800x600 (if scale!=0), ctl vt[1] SetRect. ONLY if addToList: `list[id] = ctl` (id = ctl+0x54 from the GFF "ID"); when id >= count it pads with 0x83EA60(0) then appends; when id < count it OVERWRITES list[id].
  So with addToList=0 InitControl never touches panel+0x24 (C).
- HAZARD (C from the decompile): if we append our own control to panel+0x24 BEFORE Mod 14's hook runs, count may be < 69 -> our entry sits at an index Mod 14 later overwrites (list[69..150] = its controls) or shifts what "id == expected" means. Therefore: create at ctor time with addToList=0, append later.

## Fallback (a): re-open the layout from SetStats 0x84E6F0 / Update tick
- StartLoadFromLayout 0x40EE40 thiscall(panel, CResRef*, int scaleW, int scaleH) RET 0xC (U1_raw_decomp_load.txt:35-175, disasm U1_raw_ctor_tail_disasm.txt:321-357): returns immediately if (panel+0x48 >> 1)&1 (layout-open flag); else new(0xA0) layout object (ctor 0x716FD0(0x7FF, vtable 0x987478, resref)) -> panel+0x30, parses COLOR/BORDER/BACKGROUND/ALPHA (rewrites panel +0x54..+0x5C and the border object at +0x60) and CONTROLS list -> panel+0x34, sets flag bit1, then SetRect virtuals (panel vt[1], border vt[1]) with the panel extent; with scaleW/scaleH != 0 it multiplies the extent by screen/800x600 (I: decompiler shows _ftol of FPU values) -> re-opening with (1,1) would RESCALE the panel again (compounding); (0,0) should be neutral.
- Needs: CResRef built via 0x710840(ECX=buf, "character_p"); then InitControl calls, then StopLoadFromLayout 0x40F5A0 (fastcall panel; clears bit1, frees layout via vtable delete, +0x30=0, calls 0x40FB70 which walks panel+0x24 and re-links neighbour pointers of controls whose vt[0x4C] is non-null (listboxes/sliders)).
- Cost: a resource lookup + GFF parse of character_p.gui each time (do once per panel, cache controls). Risk: panel colour/border/rect rewritten, StopLoad re-link walk over the whole list incl. Mod 14's controls, bit1 state confusion if a tick lands mid-way. VERDICT: feasible but invasive; only if the ctor hook is rejected.

## RECOMMENDATION
Hook **0x84D82C** (push imm, panel = [ebp-0x254]) in OUR mod: create the label(s) with new(0x148) + 0x419740 + InitControl(panel, ctl, tag, addToList=0, scale=1) using the existing layout templates (LBL_EXPERIENCE_STAT id 25 plain / LBL_XP_BACK id 3 framed in the live character_p.gui; check the id sentinel ctl+0x54), stash the objects keyed by panel pointer, and DO NOT append yet. Fallback order: (b) template-less if the tag is missing, (a) only as a last resort.
