# Raw facts
- SetExperience(newXP, flag): newXP<oldXP -> error "Cannot reduce XP". Stores XP (+0x68). If flag!=0 and delta>0: loop { CanLevelUp(0x6B9790) && (total level(0x6A4E00) <= list.count(+0x2C)-1) } -> rec = list(+0x28)[totalLevel] (rec!=0) -> LevelUp(rec, 0) [param_3=0 => rec NOT re-appended to list]. Total level rises inside LevelUp (class level +1 via 0x6B6A20), so the next iteration uses index level+1: each stored rec applied at most once per upward pass, in order, one rec per loop iteration (not one per call).
- Stored list is only populated by (1) 0x6B9640 ValidateLevelUp -> LevelUp(rec,1) which appends rec via 0x83EA60 (0x6B9870:+~0x0A) and (2) GFF load "LvlStatList" (0x6AFED0:1316, only when stats+0x6C != 0 = player/has-client flag). For companions (stats+0x6C==0) the list normally holds count==level entries, so the replay condition (level <= count-1) is false at current level: replay only fires after a level-DOWN (0x6B9D80 path in SetExperience delta<0 branch) followed by XP regain. => replay and AutoLevelup never both fire for the same level in normal play; if both could, replay runs first (inside SetExperience/AddExperience 0x58A9F0 call) and AutoLevelup gate (after it) sees CanLevelUp false/level raised.
- AutoLevelup 0x6BEDF0 loop: per iteration key = 0x6A4E00(0)+1 (local_52) recomputed from the live class levels; class idx fixed once before loop (stats+0x8D count-1); LevelUp via 0x6B9640 (re-tests CanLevelUp; on success rec is appended to list = owned, on failure rec freed). total level increments in 0x6B9870 (0x6B6A20(classIdx, classLevel+1)) before next iteration => keys sequential L+1, L+2, ...
- HAZARD (confirmed in asm): loop body tail 0x6C0114 JMP 0x6BEED7 ignores 0x6B9640's result. If 0x6B9790 returns 0 while XP >= table[level] (hold veto placed inside CanLevelUp, level cap < XP table, debilitated) the loop never terminates (hang). A hold veto MUST be at the callers' gates (0x5FD7CE/0x5FE2A3/0x66C95C/0x5FEE32 + 0x74F3E9 + button), never inside 0x6B9790 or 0x6B9640.
- 0x6A4E00(0) = sum of class levels; only for creatures with +0x250 level-mult byte !=0 (scaled enemies) it adds a multiplier term: irrelevant to party members.
