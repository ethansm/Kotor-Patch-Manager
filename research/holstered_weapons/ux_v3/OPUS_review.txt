HolsterLogRate.h + Holster.cpp quiet mode (log_verbose=0 is the DEFAULT)
- BUG (high, logging correctness): HolsterCombat quiet gate counts EVERY call per creature (keyBump before the old/new read) and keeps
  calls 1-3 then every 10th. The comment says "first 3 edges per creature", but the counter is per call, and most 0x7682B0 calls are
  edge=0 (LOG: 1653 COMB lines, only ~27 edges). So after a creature's third call, a real combat enter/exit edge is logged only when its call
  number is a multiple of 10: ~90% of edges are dropped. holster_log_check.py's "COMB edges per creature" report (lines 192-202) and the
  combat-edge work the G-design depends on (P0 probe, owner/COMB matching) silently under-count.
  Fix: read +0x138 first, always log when old != new (edge), rate-limit only edge=0 lines.
- BUG (medium): KeyCounts<256> never evicts. Past 256 distinct creatures in one game run (several area loads), keyBump returns 0 and that
  creature's COMB/ATTACH lines are NEVER logged, edges included. Same for ATTACH with creature == nullptr (key 0 -> never logged).
- Medium: PlaceTable kCap 64 gobs, no eviction. After area changes, new gobs fall into the overflow path (every 200th placement overall,
  no sig/delta change lines), and a reused gob address inherits the old count (no first-3 lines). RefuseTable pairs cap 64 likewise.
- OK: no WARN/ERR goes through the new gates (HolsterCombat/Attach/AnimResolve/refuse/PLACE are INFO). n= in PLACE and PLACEREFUSE stays the
  running count, so holster_log_check.py and holster_place_verdict.py still parse (17/17 tests pass).
- Stale doc: holster_log_check.py:356 docstring "the DLL logs the first 5 then every 500th" is now only true with log_verbose=1.
- holster_place_verdict.py mean_move per segment is now computed over a change-biased sample (first 3 + changes + every 200th): the mean
  is no longer an unbiased per-frame mean. Tolerable for a verdict, but document it.
- Test gap: holster_lograte_test.cpp covers the pure helpers only; nothing pins "edges always logged" (the gate lives in Holster.cpp).
  Move the COMB decision into a pure function (old, new, count) -> bool and test it.

GuiKit.h buttonFillOk / setButtonFill / setButtonFillStyle
- Memory safety: all reads via saferead rd/rd32, all writes via probeWrite-guarded wr; Steam-only gate; both border vtables checked before
