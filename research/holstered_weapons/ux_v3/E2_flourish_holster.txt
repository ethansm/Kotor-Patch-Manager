- Existing mod hooks on 0x79F430, 0x7408A0, 0x7B12C0, 0x8993F0, 0x57A560: none (rg over patch_manager_mods/*_src). ActQueue.h is not involved.

Q4. Interception options and what draw means (no code written)
- Option A: detour entry of 0x79F430. Single caller 0x7408A0. Prologue PUSH EBP / MOV EBP,ESP / SUB ESP,0x40 is 6 bytes, the same shape as H1. Also detour VM 0x66B8A0 for scripted flourish.
- Option B: detour 0x7408A0 (covers both input callers, 22 bytes).
- The combat entry is inside the flourish (DUMP :74). A pre-hook cannot stop it without suppressing that call or 0x57A560. That is server-side and riskier.
- "Stop drawing the holstered copy": holster_src has no separate copy. The weapon Gob is one object. In the HW7 design (handoff :105) "draw" = stop the H7 pose override (hooks.toml:98, 0x504EF5) for that Gob so the rhand/lhand pose applies. That needs bone_test off, because the global repoint is what pins weapons to the hip. Re-attach on combat edge is unproven (ux_v2/H3.md:7).
- Re-holster timing: the FSM stows kStowDelayMs = 1500 ms after the combat flag clears (HolsterLogic.h:182-212). So re-holster follows the vanilla combat timeout, not the flourish end.
- Stance after the flourish is the wield-row ready idle. HW7 unarmed hook 0x0086367C (handoff :115) would fix the stance while holstered. It does not touch the +0xC5 gate, which reads the real byte (DUMP :44).
