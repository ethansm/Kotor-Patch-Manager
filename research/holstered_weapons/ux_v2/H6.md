## Clamp check (holster frame: offset x right, y forward = depth, z up = height)
| Value | Live (= shipped example) | Gemini limit | Fits? |

- Shipped globals are 0,0,0 (`holster.ini:32,34`). Category values exist only as commented examples (`holster.ini:40-51`). So "category default" = 0 or value at first open, not a shipped number.
- Parser hard limits: offset |v| <= 3.0 m, rotation |v| <= 720 deg (`HolsterTune.h:7-8`, `:347`).
- Gemini's "Depth (Z)" mislabels: Z is height in this frame; depth is Y. Rotation index 0 = about x (tilt), 1 = about y (roll), 2 = about z (turn).

## Feasibility per control
- AddButton readout + tick drag scrub: HIGH. No new ABI needed. Use guikit clickEdge/cursorEngine, Shift x0.2 (`HolsterEditor.cpp:910`), Ctrl 1 cm snap (`:912`).
- Own slider drawn from EditKit math: MEDIUM. Needs draw code (none wired) and hit tests.
- Engine CSWGuiSlider via AddCustom: LOW for v1. Needs Steam ctor/Initialize/value getter RE, manual construction (panel only binds tagged controls, per `01_inventory_3d_viewport.md:114`), and a k2.menuui struct growth.
- Engine CSWGuiEditbox (typing): LOW. Focus and key capture conflict with Esc and hotkeys. Defer.

## Recommendation
1. v1 = scrub box + per-row reset (reset = delete override, matching existing Reset Scope). No slider or typing in v1.
2. Range per row: window [v0 - W, v0 + W], v0 = 0 or value at first open, W_pos = 0.30 m, W_rot = 180 deg. Allow scrub past the window up to parser limits (3.0 m, 720 deg), pinning the bar at its end.
3. Raise `mui::kMaxItems` (24) in mod-config (internal, no ABI change; also sizes `kMaxOwn` at `ModConfig.cpp:74`). Hiding items still counts them.
4. Labels in fixed order: Slide (x), Depth (y), Height (z); Tilt (x rot), Roll (y rot), Turn (z rot).
5. Weapon button text: show display name, not resref, and clamp to the half-strip width. Width in px is UNSURE until one live check; add a pending row to `patch_manager_mods/PLAY_TEST_QUEUE.md`.
