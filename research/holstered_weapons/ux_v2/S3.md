## 2. H5 shared lastMouse + stale flags: PARTIAL
- Shared lastMouseX/Y: CONFIRMED in code (Editor fields HolsterEditor.cpp:165; LMB writes 900-901/920-921, RMB 937-938/953-954, MMB 878-879/885-886).
- Can LMB and RMB drags be active in one tick? YES: pressed/pressedRmb/dragging* are independent per-button, no mutual exclusion (894-960). Only when the user holds both buttons (a chord) inside the view.
- Starvation: LMB block runs first; when it moves it sets last=cur, then RMB block computes dx=dy=0 and does nothing. So with both held and the mouse moving, LMB translation wins and RMB rotation is starved (and vice versa for MMB vs LMB). Single-button use is unaffected. Severity: low (chord only), real.
- Stale flags in enterEdit/exitEdit (541-590): NOT reset. Real consequences are narrow:
  - pressedRmb is only updated in WEAPON mode (NAV branch never touches it). If RMB is released while in NAV after being down at last WEAPON tick, pressedRmb stays true; first RMB press after re-entering WEAPON gives rmbBegan=false, so that press is ignored until released and re-pressed. REAL but minor.
  - draggingLmb/Rmb/Mmb are reset only by cbLeave (615-630) or by the button being up in a WEAPON tick; exitEdit while a drag button is still held (member prev/next 672-690 need a click so LMB only) leaves a stale drag with old lastMouse -> one jump on re-entry if still held. Hard to hit.
  - pressed (LMB) is maintained in both modes (895, 975/988): no stale issue; intended "click that entered edit doesn't start drag" works.
  - cbLeave/cbDestroy do reset everything.
