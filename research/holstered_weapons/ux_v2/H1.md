## Risks
1. Install: a new hook is REINSTALL, not hot-swap (`patch_manager_mods/BUILD_AND_INSTALL.md:61`). New DLL imports also force reinstall (:62). Resolve GL via GetProcAddress as Gui2D does to keep imports unchanged.
2. Address: 0x480385 is mid-function, not a prolog. Steam DB rules assume prolog rows (`.claude/skills/kotor2-address-db/SKILL.md:17`). Mid-function hooks already exist (`buff_duration_hud_src/kotor2-steam-aspyr.hooks.toml:6,30,40`). Check with `ghidra_knowledge/tools/static_facts.py addr 0x480385`; `query_ghidra.py` is GOG-keyed.
3. Detour semantics: a detour runs our code first, then the original bytes (`02_buff_duration_hud.md`, "skip_original_bytes=false"). A post-draw hook needs the 5 original bytes (33 d2 c1 e2 02) and must not clobber EAX/ECX/EDX expectations.
4. GL state: the pass sets GL_POLYGON_MODE (decomp :108-109) and never restores it. It has no glPushAttrib. Gui2D CapGuard covers only 9 caps (`Gui2D.h:223`), not line width, color, depth mask/func, blend func, or matrix mode. Use glPushAttrib(GL_ALL_ATTRIB_BITS) plus matrix push/pop.
5. Engine edge: the off-screen early return (decomp :121-126) skips both pops, leaking two matrix pushes. Pre-existing, reachability UNSURE.
6. Framebuffer: no FBO bind in the pass (callgraph 11811-11820). Scene draw callee unknown, so UNSURE. glViewport (:128) clips drawing to the view rect. ReShade was the opengl32.dll proxy on 09-24 (`18_mouse_camera_investigation.md:18`), current state unverified.
7. Thread: main thread only (`_shared_src/Preview3dApi.h:13`). Overlay gate: DAT_00A32A48 holds the camera during the pass (decomp :328, cleared :335).
8. Frame order: SwapBuffers call at 0x408434 in main loop 0x407920 (imports.tsv:6497). Pass-to-swap ancestry not traced.

## Verdict basis
Feasible at the engine level: post-draw point 0x480385 runs in 3D state with the preview's camera. Not "~40 lines, no risk": needs a new hook (reinstall), GL resolver, state guards, address rows. No existing mod draws GL.
