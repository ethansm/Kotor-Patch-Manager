=== 2. The rule (V, asm) ===
0x72B830 bind(mgr, id, ctx): returns 0 (refused, nothing changes) when:
  a. ctx >= 6, or table[id] == NULL.
  b. bit id already set in the ctx bitmask (0x72B3E0 != 0).
  c. key1 = entry+0x1C != 0x86 AND 0x72B300(mgr, key1, device=entry+0x18, ctx) != 0.
  d. vfunc1(entry) != 0 AND key2 = entry+0x30 != 0x86 AND 0x72B300(mgr, key2, device, ctx) != 0.
  On success: entry+8 += 1, entry is added to the registry list for (ctx, device) at mgr+ctx*0x40+0x14+device*4 (device -1 uses entry+0x10 instead), and the ctx bit is set.

0x72B300 conflict scan (V): returns 0 at once if key >= 0x86, device not in 0..9, or ctx not in 0..5.
  Otherwise it walks the registry list for (ctx, device) and returns the first registered entry S where S.key1 == key, or (vfunc1(S) != 0 AND S.key2 == key).
  Decompile note: the .c shows FUN_0072b300(piVar2[7], piVar2[6], param_3). The asm shows ECX=mgr and 3 pushes (key, device, ctx), so the .c first argument is not the this pointer.

Consequences for ICPC (ctx 0):
  - Key K is refused for row R iff K < 0x86, R's device is 0, and an already-registered ICPC row on device 0 has key1 == K. Only one entry per key can sit in the list, so the first registrant wins. List order does not change this.
  - Registration order: (1) literal id 80 (0x50) registers ctx 0 with key 38 (DAT_0099C934 = 38) in the literal block around 0x785DF0 L176-181, before any 2DA row; (2) ids 200..269 ascending; (3) ids 280..286.
  - Every 2DA row (200..269, 280..286) is built on device DAT_0099C884 = 0 (V). So all K4 rows share the same ICPC list.
  - Types 0/1 (all 200..269 rows) use the base vtable 0x99C7EC. Its vfunc1 = 0x4558A0 = "return 0" (V). So the key2 branch never fires for them. Key2 only matters for type 3/4 objects (280..286 A/B pairs, 0x785DF0 L567-569); their vtable was not checked.
  - Loader pass 2 has a "claimed key" array local_430[256] (0x785DF0 L140, L267, L372/414/567). It is memset to 0 and never written (V), so the load-time key check is a no-op. The only key-conflict check is inside 0x72B830 at ICPC bind time.
  - A refused row keeps its table entry, its ini value, and its other ctx bindings. It is only missing the ctx-0 bit, so it is not polled in ICPC (G: no code path removes the entry).
  - Correction to S1 "G: no other action already bound in that context": the scope is same ctx AND same device, earlier registrants only, and key2 only when vfunc1 != 0.
