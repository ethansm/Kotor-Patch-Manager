=== 2. Hostile check and throttle ===
Call (H3 sec 2, V decomp mods678_research/dump_excerpts/0057c990.c; typedef = companion_ai_src/CompanionAI.cpp:76 and :83):
  using NearestFn = int(__thiscall*)(uintptr_t self, float range, int exclude, int ref);   // 0x0057C990, RET 0xC
  nearest = fn(S /*server creature = ECX*/, R = 30.0f, 0x7F000000 /*exclude*/, 0x7F000000 /*ref: always INVALID*/);
  hostile = (nearest != 0x7F000000 && nearest != 0).   // 0x7F000000 = OBJECT_INVALID = "none" (V); CompanionAI treats 0 as none too.
  Range is a hull-gap distance (centre distance minus both radii), world units = metres (G). 30.0 = the engine's own "enemy within 30" probe (0x57DC20, AI2.md:137).
  Candidate must be seen (perception bit), alive, reputation==2 (H3 filters 1-7), so unseen enemies do not count: fail-safe direction is wrong only for unperceived enemies, acceptable.
  PC as self has vanilla precedent (AI2.md:135). Companions as self: CompanionAI uses it on party attackers (G).
Guards before the call (a null deref crashes, H3): readAt(S,0x380,&pi) != 0 and readAt(pi,8,&f) ok; only from the game thread inside the detour/tick; wrap with saferead::beginScope().

Throttle and when to call (stateless, bounded):
  Trigger gate (read-only fields, V decomp lines 144-152): [S+0x520]==1 && [S+0x528]==0 && [S+0x524] > 0 && [S+0x524] <= 8000 - exit_ms.
    8000 is the literal written at 0x57A64F/0x57A655 on every SetCombatState(state!=0) (V S1; mov [eax+0x524],0x1F40). So `8000 - [S+0x524]` = elapsed ms since the last refresh (G on the unit: +0xD0 is elapsed ms, K5 GUESS; consistent with observed 8.0-8.5 s).
    While a real fight is on, the PC/AI refresh keeps +0x524 at 8000 each tick (S1: 0x8C9750 refresh), so the gate is false and the hostile call is NEVER made during active combat. It is only evaluated after exit_ms of silence.
  Per-slot throttle: static DWORD nextCheck[3]; run only when GetTickCount() - nextCheck >= 0.
    no hostile found -> write [S+0x524] = 0 (probeWrite first), expiry fires at the engine's next AIUpdate pass (0x5698F6 JG fails, 0x569923 CALL 0x57A560(0,[+0x11E8],0)); no further checks needed, +0x520 becomes 0.
    hostile found   -> nextCheck = now + hostile_backoff_ms (1000), leave the timer alone.
    gate false      -> no call at all.
  Worst case cost: <= 3 calls/s per party member (1000 ms back-off); the base period is 250 ms only after "no hostile" is impossible (the write ends it). Cost per call is unmeasured (H3 O2, linear in area objects + LOS rays) -> log the first 20 durations (QueryPerformanceCounter) in the CONFIG/TOGGLE channel.
  +0x528 guard: S1 says "+0x528 must be 0". Decompile: expiry (`+0x524 < 1`) does not test +0x528, only the decrement does. The guard is conservative (keep it for the automatic shortening, drop it for the explicit toggle press).
  Flourish-only (S1 (c), K6): [S+0x520]==1 && [S+0x11E8]==2 && client flag==0 && (8000 - [S+0x524]) >= flourish_exit_ms (the flourish body anim 0x27AE is 1500 ms, K6 S6). Same hostile check, then [S+0x524] = 0. No timestamp needed, the elapsed time is encoded in +0x524.
  Window of the write: the detour runs before the countdown block, so a write lands in the same pass. A tick-side write lands one pass later (ms). Same helper function serves both; the detour is justified mainly by running in the server loop on the server thread; see OPEN 3.

  Set by the toggle: g_holdOwner = cli[0] (or the owner HolsterPlace saw, see sec 1 identity note), g_holdUntil = now + draw_hold_ms. Clear by a second press: g_holdUntil = now (immediately inactive).
  The stance/anim is NOT changed: no engine call, +0xC5 and +0x520 untouched; the weapon snaps from hip to the engine's native hand node (the visual is "weapon in hand, normal out-of-combat idle", no draw animation). A real draw animation would need the vanilla flourish 0x0079F430 (K6; sets server combat 8000, param_3=2) which then interacts with B; not in v1 (OPEN 5).
  Interaction with real combat: while client combat flag != 0 the hold is irrelevant (hip=false anyway). When combat ends and the flag returns to 0 the hold keeps the weapon in hand until it expires, so reset g_holdUntil = now on the combat 0->nonzero edge in HolsterCombat (H1, Holster.cpp:330) if a "combat takes over" behaviour is preferred (G, optional).
  Toggle decision (visual state, V from sec above): drawn = holdActive || client flag != 0. Press when holstered -> start hold (no checks). Press when drawn -> clear hold; if client flag != 0 and a fresh hostile check (no throttle) says none: write [S+0x524]=0 for the controlled server creature (probeWrite; works even with +0x528 != 0); a refused stow (hostile near) is logged and the key does nothing else.
