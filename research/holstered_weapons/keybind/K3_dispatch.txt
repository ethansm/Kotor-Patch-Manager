## 3. Read path (the dispatch)
- Thin wrapper FUN_0072f9d0 (size 32, ret=8): calls FUN_0072c320(id, slot). Args on stack; ECX (CExoInput this) passes through.
- FUN_0072c320 (size 449): requires -1 < slot < 6, validates via FUN_0072b3e0, fetches event via FUN_0072b280, then switch(event+0x14) (decomp line 'switch(puVar2[5])'). Returns float10.
- Model: POLL, not push. Callers ask for the value of a fixed id each frame and decide behaviour themselves.
- No central switch on action id. The switch is on event type. Behaviour lives at each call site.

## 6. Can a mod DLL add a new action id?
- Partly. Two gaps block a clean row:
  a. Row creation is hard-coded in FUN_00900d40. A new row needs an extra FUN_00900940 call there, or a detour of FUN_00900d40 (size 234).
  b. The engine event array at CExoInput+0x188 must have an entry for the new id (count +0x18c). The allocation site was NOT found. OPEN.
- Behaviour hook: FUN_0072f9d0 is a 32-byte wrapper with stack args and ECX passing through. A 5-byte JMP detour fits. It can return 1.0 for a new id when its key is held. That covers the consumer side only if the event slot exists (gap b).
- Feasible detour sites: 0x0072f9d0 (poll), 0x00900d40 (row builder), 0x00902800 (persist).
