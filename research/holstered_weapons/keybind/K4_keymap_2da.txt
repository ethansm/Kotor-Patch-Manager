K4 - keymap.2da: what the real table contains, and whether an Override copy can add a row
Source: read-only extraction from the Steam install (game dir not modified). Question owner: K4 (holster keybind).

## 1. Where keymap.2da lives
- Not a loose file. In chitin.key (KEY V1, 18439 keys) it is resref 'keymap', restype 2017 (2DA), in data/2DA.bif (the game dir also has Data -> data symlink), resource index 155 inside 2DA.bif, size 6892 bytes.
- Format: binary '2DA V2.b', 23 columns, 81 rows. Layout: NUL-terminated TAB column names; u32 row count; TAB-terminated row labels; u16 cell offsets (row-major); u16 data size; string pool. Decoder check: all 1863 offsets land on string starts (score 1.0).
- Engine strings present in swkotor2.exe: 'keymap', 'KEYMAP', 'KeyMappings', 'KeyMapping_p', 'KeyMapButton', 'Keymapping'.
- GUI: optkeymapping_p and optkeyentry_p are in data/Gui.bif (restype 2047). The game dir ALSO has override/optkeymapping_p.gui (ultrawide GUI copy), so any new row must also be reflected in that override GUI, not only in the 2DA.
- Live bindings: swkotor2.ini [Keymapping], keys Action<row-label without 'action', uppercased>. Suffix A/B = two bindings for rows 280-286 (e.g. Action280A=ActionUp W, Action280B=ActionDown S).

## 2. Columns (header names as written in the file)
0 disabled (1 = row not bindable; all 17 disabled rows have no ini key)
1 actionstrref  2 descstrref  (strref; ***** = none)
3 language0 = DEFAULT KEY CODE (misnamed header). Every ini ActionNNN value equals this column.
4 character = key label text shown (e.g. 30=Tab, 67=Q, 51=A, 73=W, 9=UP, 31=Escape)
5 page (0/1/2; MG* rows and PauseMinigame are page 2)
6 sortpos  7 name (internal action name, e.g. SelectPrev, ActionUp)
8 remappable  9 forcedisplay  10 icpc  11 icminigame  12 icpcgui  13 icdialog  14 icfreelook  15 icmovie  16 repeatable  17 repeatwait  18 repeatrate  19 scale  20 scalemag  21 scaleexp  22 eventtype
Key codes are the engine's own table, NOT DirectInput: 67 is Q, 30 is Tab (DIK would be 16 and 15).

## 5. Would an Override/keymap.2da be honoured?
- Likely for the file lookup: keymap is a normal chitin 2DA, so the standard Override-first lookup applies. Repo prior art for Override-first 2DA: action_hotbar_src/README.md lines 27 and 178-183 (override/spells.2da read before chitin.key -> data/2da.bif); build_ranged_kite_2da.py writes Override/aiscripts.2da as binary V2.b; K1_ENGINE_BUGS_IN_K2.md line 36 says normal override tables are binary.
- Caveat: the spells.2da evidence is the mod's own reader, not the engine's keymap screen. Not tested in game.
- Row count is NOT proven: optkeymapping_p / optkeyentry_p (Gui.bif) were not parsed, so a fixed list of GUI entries may cap how many rows show.
- New binding needs its own ini key (Action<label>) or a default from the 2DA column; not verified.
