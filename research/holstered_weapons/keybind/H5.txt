H5 - How a Patch Manager mod ships a data file (keymap.2da) into Override/
Source: read-only recon (repo + KPM checkout ~/Games/KOTOR2_Mod_Workspace/tools/kotor-patch-manager + game dir listing). Nothing modified.

## 1. Short answer
- There is NO manifest.toml key that deploys files. The KPM manifest schema (KPatchCore/Models/PatchManifest.cs) has only: id, name, version, author, description, requires, conflicts, kind, provides, requires_interfaces, url, license, supported_versions. No files / assets / extras table.
- The kpatch contains only manifest.toml, *.hooks.toml and binaries/*.dll. Verified by listing members of Patches/NpcDiversity/NpcDiversity.kpatch and Patches/ActionHotbar/ActionHotbar.kpatch: manifest.toml, kotor2-*.hooks.toml, binaries/windows_x86.dll (and gog hooks for npc-diversity). No override/ member.
- Nothing in the KPM install path writes into Override/. Install writes gameDir/patches/, patch_config.toml, addresses.db, the patcher module and sqlite3.dll only (PatchApplicator.cs:502, 584, 693, 706; sqlite3 copy 756-757).
- Uninstall never touches Override/. PatchRemover.cs:147-160 removes patches/ modules; :228 removes only manager-owned module files in the game root.
- kpm_hotswap --apply writes only the DLL: kpm_hotswap.py:298-337 (write_dll at :337 on p["dll"] only). It does not deploy any asset.

## 2. Source-path convention that exists in the repo (no KPM effect)
- Put the file at patch_manager_mods/<mod>_src/override/<name> (prior art: npc_diversity_src/override/, 73 files incl. appearance.2da, heads.2da, N_*.tpc, llk_*.mdl).
- kpm_hotswap.py:213-230 mirror() recurses into override/ and copies it to Patches/<X>/override/ (confirmed: Patches/NpcDiversity/override exists with 73 files). create-patch.py never packs it (create-patch.py:853 manifest, :855 hooks, :866-870 binaries/* only).
- kpm_status.py:160 drift check uses src.iterdir() (top level only), so a changed override/ file never produces MIRROR or REBUILD. Changes to override/ are invisible to the gate.
- Real manifest snippet for a data-carrying mod (no file key): patch_manager_mods/action_hotbar_src/manifest.toml:1-9 ([patch] id/name/version/author/description, requires, requires_interfaces). The 2DA is not listed anywhere in it.

## 3. How override files actually reach the game (all manual or script, user-gated)
- npc-diversity: override/*.2da generated by scripts/generate_diversity_2da.py (default out-dir = npc_diversity_src/override, line 53). Live Override/appearance.2da replaced by hand: patch_manager_mods/34_npc_diversity_dispatcher.md:274. Doc 34 also notes P_TwiH* heads exist only in live Override (drift, line 257).
- ranged-ai: scripts/build_ranged_kite_2da.py:14-16 writes <out>/Override/aiscripts.2da to a STAGING dir; copying into game Override is "a separate, user-gated step".
- action-hotbar: does NOT ship spells.2da. ActionHotbar.cpp:114 reads "override/spells.2da" first, then chitin.key -> data/2da.bif (README.md:27, 178-183; CHANGELOG.md:7 "no longer has to be in override/"). Shows Override-first lookup with fallback.
- Textures/data embedded in the DLL instead: action_hotbar_src/HotbarTextures.inc (generated, scripts/gen_hotbar_textures.py:10 "nothing is installed into override/"); docs/RuntimeGuiControls.md:117 "Textures from DLL memory (no override/ files)".
- asset-vfs (k2.assetvfs@1): in-memory 2DA row splicing with zero Override/*.2da files (patch_manager_mods/44_in_memory_asset_vfs_and_character_library.md:40, 68). Splice keyed by resref: AssetVfsProvider.cpp:463-475 VFS_On2DaServiced -> buildTwoDaSpliced(resref) (:507-517). Adds virtual rows; no keymap-specific gate seen.
- holster_src / holster_editor_src: no override files. Config is hand-placed in game dir: holster.ini and kplog.ini (42_holstered_weapons.md:74; master plan HW4 row: "no holster.ini in game dir yet"). Byte patches go via code_patches.toml (holster_src/code_patches.toml), not files.

## 4. Conflict check
- keymap.2da in any repo mod source: 0 hits (rg -i keymap over patch_manager_mods/*_src). KPM Patches/ExpandedKeyboardControl: 0 hits.
- Repo mods that ship a *.2da into Override: only npc_diversity_src/override/appearance.2da and heads.2da. action_hotbar_src/testdata/spells_fixture.2da is a test fixture, not shipped.
- Live game dir: Override is a symlink to override (same dir; `stat` type symbolic link). Path: ~/.steam/steam/steamapps/common/Knights of the Old Republic II/override
- keymap.2da in live override: ABSENT. keymap-related file present: optkeymapping_p.gui (ultrawide GUI copy; K4 section 1 and 6 say it must be kept in sync with any new keymap row).
- Live *.2da names (37): aiscripts alienvo ambientmusic appearance autobalance baseitems camerastyle chemicalcreate classes cls_st_jmaster cls_st_sithlord effecticon feat featgain forceadjust genericdoors globalcat heads itemcreate itemcreatemira loadscreens loadstoryhints modulesave movies musictable placeables planetary poison portraits regeneration soundset spells traps upgrade visualeffects weapondischarge weaponsounds (.2da)
- Vanilla keymap: chitin.key resref keymap, restype 2017, in data/2DA.bif (K4 section 1; binary 2DA V2.b, 81 rows, 23 cols).
- Consequence: an Override/keymap.2da is a WHOLE-TABLE shadow. It must be a complete V2.b copy of the vanilla 81 rows plus the new row(s), not a partial table. No collision with another mod today.

## 5. Doc drift (fix only if asked)
- BUILD_AND_INSTALL.md:157 says production files are only .cpp .h .inc .def, manifest.toml and *.hooks.toml. Code (kpm_status.py:36, 44-49) also includes .ini .toml .tpc .mdl .mdx .2da .tga. Doc is stale.
- BUILD_AND_INSTALL.md:54 "all extras" means binaries/ extras only (create-patch.py:866-870), not data files.

## 6. Recipe for keymap.2da (what the repo's own patterns imply)
- Option A (matches repo practice for aiscripts/appearance): stage at <mod>_src/override/keymap.2da (binary V2.b, full table). Copy to <G>/override/keymap.2da by a user-gated step, after backing up the vanilla-equivalent. Uninstall does not remove it: delete by hand. kpm_hotswap --prepare/--apply will not copy it.
- Option B (no loose file): asset-vfs row splice (requires_interfaces = ["k2.assetvfs@1"]). Only if the keymap loader reads through CRes2DA and the splice can add the new row. Unverified.
- Option C: keep the new binding in the DLL (hook the key poll), no 2DA. Outside this recon.
- Any option: rebuild the kpatch with create-patch.py for the DLL part; the data file is a separate deploy.
