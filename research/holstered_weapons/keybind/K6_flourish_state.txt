4. WHERE THE CHARACTER IS STUCK AFTER A FLOURISH
- Server combat flag +0x520 = 1. Written by S4. No clear in the flourish path. Clear path: GUESS.
- Server combat timer +0x524 = 8000 (units presumably ms, GUESS). Expected clearer: vanilla server combat timeout (GUESS). Conflict: E1:23 says the timer "does not auto-clear"; E3:9 says it counts down. Both GUESS. holster.ini:28 says "~8 s after combat ends", which fits 8000 but is a note, not a trace.
- Client combat flag +0x138 = 0. Flourish never sets it, so H1 never sees an edge and the holster FSM never draws. VERIFIED.
- Stance idle: 0x2711 (alias 0x27A4) is the ready/holding idle, resolved by 0x00863650 using wield byte +0xC5. Wield 1->0x5C, 2->0x85, 3->0xAE, 4->0xD7, 5->0xDF, 6->0xED, 7->0xF5, 8->0xF9 (0x217 if +0xD4 != 0), 9->0xF5. VERIFIED from c6_unarmed_anim.md:6-7 and d_resolver_caller.md:30,34. "0x2711 is the holding idle" is GUESS (c6:15).
- Combat entry does not rewrite +0xC5 (c_readers_combat.md ordering hint). The stance therefore persists until the wield byte changes.
- Who clears: no mod code. Only H1 reads 0x007682B0. The GameAddr.h:75 entry is a constant. Nothing in patch_manager_mods writes +0x520, +0x524, +0x138 or the stance. The vanilla server countdown is expected to clear it (GUESS, not traced).

5. IMPLICATIONS FOR THE HOLSTER GOAL
- The FSM (HolsterLogic.h:193-199) runs only on +0x138 edges. A flourish gives no edge, so the FSM never draws or stows for it.
- Stow after real combat: 1500 ms (kStowDelayMs, HolsterLogic.h:172) after the client flag returns to 0. The 8 s figure is the server timer, not the mod's.
- Under the live config (probe=1, bone_test=1, place=1, per E2:9), drawgate writes the hip pose whenever +0x138 == 0. So a flourish-only event leaves the weapon on the hip from the mod side, while S3 shows it in the hand from the engine side. Does not match the user report exactly. In-game check needed.
