(a) What is left in HolsterEditor.cpp worth extracting. R1 is right that the pure maths is header-only already. Left inside the 2770-line cpp (rough, est, from R1 line ranges):
    selection look and selectors HE:1338-1475 (about 140 lines) -> CMP7;  caption fix HE:1598-1682 (about 85) -> CMP6;  icon art and fills HE:2299-2391 (about 90) -> CMP7;
    scrub plumbing HE:1777-1938 (about 160, part holster-only) -> CMP8;  layout and PaneRect HE:518-644, 1518-1580 (about 110) -> CMP5 layout / PaneLayout;
    client copies and connect HE:2738-2767 (about 30 plus the 4 template copies) -> CMP3;  hit lists 1763-1802 and text cache 1318-1333 (about 55) -> CMP4/CMP5;
    ini line parser 321-378 (about 58) -> extend IniKit.h (K3);  log plumbing, two-click guard, input reset (about 110) -> EditKit.h utilities.
    That is roughly 600-650 lines of generic code. Holster-only stays: 3D preview, HolsterApi calls, bone/stance/row tables, weapon gestures, PI_* page table.
    Dead/prune (phase 1b): EditKit (6 fns), HseView (about 11 helpers), HseLayout.h (93 lines + test), SliderArt/ResetIcon extras (about 12 fns), and the log-only probes
    (about 500 lines; keep or remove is Q4). Do the prune BEFORE extracting so nothing dead gets copied into a shared header.
(b) Provider vs header. Provider-side only CMP1 and CMP6 (both need the provider's tick/SetRect loop). Everything else is a consumer header. Stepper and toggle = CMP5 rows
    (zero ABI). Slider = CMP8 with polling (zero ABI, K2). Paging = not built (no page needs it). Reason: each K2MenuUiApi slot costs edits in API, MC, mod-config contract test and the
    pins in holster-editor and enemy-effects-strip contract tests (R2 Q1 list), and a missed initializer silently zero-fills.
(c) Priority by demand. 12 toggles + 3 enum cycles + 1 pair = 16 of 19 rows fit CYCLE (n>=2 presets, preset may write 2 keys). 1 stepper (combat BtnPx, plus the strip's numeric rows already in tree).
    The 2 "sliders" fit CYCLE presets. So order: CYCLE/TOGGLE first, STEPPER second (strip is the live consumer), CUSTOM third (strip tier ordering), slider never in the generic layer.
(d) INI writer. Recommend ONE: text rewrite (IniWrite.h from HolsterIniWrite.h), per key, atomic, section optional. Reasons: (1) pure and host-testable, WritePrivateProfileStringA is not;
    (2) no new kernel32 import, so hot-swap keeps working (K7); (3) the same code handles the flat files (holster, inv3d, equip3d, queue-hud) and [Section] files (strip, combat, sort, action), which the Win32 API
    cannot do for flat files; (4) comments, order and unknown lines are copied byte for byte by contract, whereas R3 itself says it did not verify comment handling on this Wine build; (5) atomicWrite keeps the
    old file on failure. Cost: about 80 lines to add section awareness. Action-hotbar keeps its own writer through onChanged.
(e) 500 ms bounce. Minimal reorder: change MC:1263 so the watchdog fires only when the panel is not shown. Concretely, replace
    `if (gap > kTickGapMs) resetPages("tick gap");` with `if (mui::tickResetDue(gap, flags48, lmbDown)) resetPages("tick gap");` where, for a shown panel (flags48 & 0x40),
    due = gap > 5000 and !lmbDown (long backstop, not removed); for a not-shown panel due = gap > 500 (current behaviour). Equivalent literal form: move MC:1266-1269 above MC:1263 and
    drop the watchdog for shown panels; the pure function is preferred because it can be host-tested and keeps the backstop.
    Risk: the two comments at MC:1258 and MC:1264 disagree on whether a hidden panel is drawn. If a panel closed by a path other than Esc is NOT drawn while hidden, its first draw on reopen has
    0x40 set and gap over 500 ms, and with the fix it would reopen on the stale mod page (the Esc key edge at MC:1260-1262 covers only Esc). Mitigations: the 5000 ms backstop; the existing HIDDENDRAW
    log (cap 32, MC:1254-1256) will show the gap and flags48 of a reopen. Collect that log from one non-Esc close (Back button, game-menu key) BEFORE shipping. Not verified: whether a gap over 500 ms
    really occurs while shown other than the one 1.1 s hitch R4 cites (RFC:123).
(f) holster-editor ClientS connect. CONFIRMED (C4): connects once at HE:2748, no retry. Because the manifest hard-requires mod-config, a missing provider is a configuration error and the existing
    `REGISTER fail why=noapi` log (HE:2749-2751) is sufficient. If init order cannot be guaranteed by `requires` (unverified), the fix is NOT 15 lines: holster-editor is hookless (no per-frame callback
    before the page exists), so a retry needs a frame source, e.g. a k2.hud@1 hook like ES (ES:1305-1306) plus `requires = ["hud-host"]`: about 25 lines in HE and a manifest change (reinstall, not
    hot-swap). With CMP3 the retry is a 3-line call instead. Recommend: verify KPM init order for `requires` once; if guaranteed, do nothing in phase 1.

======================================================================
4) INTERFACE POINTS FOR THE TOML SESSION
======================================================================
This session does not design the schema or parser. It defines what the parser's OUTPUT must be so a TOML loader and a hand-written C++ table are interchangeable.

I1 Output type. A plain-old-data PageSpec built from fixed arrays and static strings, no heap, no STL (DLL rules in this repo), with `struct_size` first so it can be versioned like K2ModConfigEntry (API:67-83).
   PageSpec { struct_size, id, title, desc, ini {path, dialect = FLAT | SECTIONED, section}, rows[], rowCount, hooks }.
I2 RowSpec fields (all static strings): id (stable, for logs), label, desc, kind (TOGGLE | CYCLE | STEPPER | CUSTOM), restart (static bool; dynamic predicate via hook), keys[1..2] each
   {key, type = BOOL | INT | FLOAT | ENUMSTR}, presets[] each {valueLabel, writes[1..2] values} for CYCLE (a TOGGLE is two presets), range {min, max, step, sentinel value + label} for STEPPER, default per key,
   clamp policy = CLAMP_TO_BOUND | RESET_TO_DEFAULT | WARN_KEEP (three policies exist in tree, R3 D; a loader that picks one silently changes inv3d/equip3d behaviour).
I3 Caps agreed in advance: rows per page, presets per row, string lengths. Provider truncates silently at text 95 chars, desc 191, title 63 (MC:570-575, :1031, :1058). The loader should lint and fail the page loudly,
   and respect the 80-item page cap (MenuUiLogic.h:37): TOGGLE/CYCLE 1 item, STEPPER 3 items.
I4 Hooks a pure TOML page cannot express (function pointers in `hooks`, null allowed): onChanged(rowId, presetIndex or value) for live apply (strip pool rebuild), validate(rowId, candidate) for cross-field rules
   (strip tier ordering ES/EnemyStripLogic.h:287-288), restartPredicate(rowId) (strip Enabled), previewPaint(page) (strip 12 owned labels, SetDescSplit 750, ES:985-1109). Specs with hooks=null are the "simple page".
I5 Ini contract: path is relative to the game dir; flat vs sectioned is explicit; the write is per click, through IniWrite.h (CMP2), atomic, never at page leave; Reset writes explicit values (R3 finding 3);
   the reader stays in the mod (readers differ: 3 clamp policies, 4 duplicated clamp helpers). The loader does not read mod ini at startup; it only reads the current value to show the row text.
I6 Live-apply contract (needs a decision, Q2): 5 of 7 target mods re-read their ini by mtime poll (action-hotbar about 1 s, combat-hotbar ReloadPoll, inv3d/equip3d mtime stamp, sort on refresh), so an ini write alone is enough for them.
   Queue-hud reads once at load (QueueHud.cpp:2114), the strip applies in-process: those need onChanged or a restart marker.
I7 Where the runtime lives. Today the whole page runtime would be a consumer header (CMP5) compiled into each mod, so the spec is passed by pointer in-process. If the owner wants TOML-hosted pages read by mod-config itself
   (mods ship no page code), the PageSpec must cross DLL boundaries, so it must be a C struct with struct_size and static pointers, delivered through a NEW interface (e.g. k2.modconfig.spec@1) or a new K2ModConfigApi slot.
   That is a provider-side ABI addition and a decision for the owner (Q2). Also open: whether KPM can ship a .toml next to the DLL at all (memory: KPM cannot ship Override files; a game-dir file may differ).
I8 Provider must expose to either route: nothing new for the in-DLL route (existing 12 slots suffice, K2/K5). For the provider-hosted route: Register-with-spec, a per-page ini path resolver, and onChanged delivery.
I9 Strings and fonts: no font control in the spec (setFont crash, C3); text colour/align from the constants block of CMP4. Glyph-only captions are not allowed in the spec until C6 is resolved (stepper must offer a cycle-on-click
   rendering as an alternative).
I10 Errors fail soft: an invalid row is dropped with a WARN, an invalid page stays inert, and the mod keeps working (matches ES behaviour, ES:1189 "page left inert").
