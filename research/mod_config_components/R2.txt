==========================================================================================

Pinning of struct growth:
  - Provider table is positional and sized by sizeof: MC:1164-1165 ({sizeof(K2MenuUiApi), &muiNewPage, ... &muiSetDescSplit}).
    A new slot must be appended to the struct AND to this initializer. If it is missing, the slot is silently zero (no compile error by default).
  - Header hard asserts: offsetof per slot (API:159-170), sizeof == 12 pointers (API:171). A grown struct fails API:171 until edited by hand.
    K2ModConfigApi = 3 slots (API:151). K2ModConfigEntry = 10 slots (API:146).
  - Consumer gates: MenuClient::usable needs only up to Control (API:245-248). hasDescSplit = struct_size >= offsetof(SetDescSplit)+sizeof and non-null (API:251-254).
    A new slot needs a new hasX in the same style (copy of API:251-254).
  - MCT: stubs 20-32; positional tables 34-36; size pins 61-70 ("12 pointer slots" at MCT:67, "SetDescSplit at slot 11 (the last field)" at MCT:68);
    too-small gate 114-135; grown table 137-143; null checks 146-159; SetDescSplit compat 161-189.

Q2. Item model
==========================================================================================
Two parallel tables per page:
  - g_mc.pt: mui::PageTable of mui::Item {kind, ctl, flags, rect, visibleInPage} (MUL:272-278, :285-305). Filled at MC:1039.
  - g_mc.items[k][i]: ItemX (MC:107-119). Fields: ctl, isButton, nofree, listed, unlinked, latched, hasRect, hasText, Target tg {ctl, Rect r, applied, gaveUp},
    text[96], desc[192]. About 330 bytes each (estimate).
  - addItemCommon (MC:1035-1043) writes both. pt rect is always zero (r0 at MC:1038). pt ctl duplicates items ctl (MC:1039 vs MC:1041).
    unlinkOwn updates only items (MC:971-973), so pt and items can diverge.
  - McState (MC:121-156) holds items[8][80] plus root, back, title and list[8]. Roughly 210 KB, reset by placement-new (MC:161, MC:1192, MC:1355).
Caps:
  - kMaxEntries = 8 (MUL:37). Registry full: Register returns 0 (API:87, MC:981-984).
  - kMaxItems = 80 per page (MUL:37). Enforced in AddButton (MC:1050) and AddLabel (MC:1073). NOT checked in AddCustom (MC:1089-1099);
    addItem returns -1 silently when full (MUL:310).
  - kMaxPages = 10 (MUL:37). kMaxOwn = 651 (MC:75). kMaxTargets = 32 (MC:67). kMaxVanilla = 64 (MC:66).
  - The 80-item cap is not in the header. Consumers infer it from version (holster_editor_src/HolsterEditor.cpp:10, :548).
Creation (which vanilla control is cloned):
  - root = clone BTN_GAMEPLAY (MC:1202). List rows = BTN_GAMEPLAY each (MC:1210). Back = BTN_EXIT (MC:1214). Title = LBL_TITLE label (MC:1215; kLabelTemplate at MC:71).
  - Entry AddButton = BTN_GAMEPLAY (MC:1054). Entry AddLabel = LBL_TITLE label (MC:1077).
  - cloneEntry falls back to a label if the button clone fails or button_clone=0 (MC:201-224).
  - Clones are created hidden and click-through, not in the panel list (_shared_src/GuiButton.h:54-58, :88-95; _shared_src/GuiKit.h:173-175, :203).
  - If the root clone fails, entries are not built (MC:1216-1219).
AddCustom adoption:
  - Stores the raw pointer and the nofree flag (MC:1096-1097). Appended in firstTick via appendItem (MC:584-599).
  - MUI_NOFREE that is already listed (id equals list index) is not appended twice (MC:587-594). Otherwise guikit::appendToPanel.
  - If the append fails and the item is not nofree, the provider drops its pointer (MC:598), which leaks the control.
  - CUSTOM items have no desc. descFor returns null for them (MC:846-856). Descs come only from AddButton (MC:1058).
Who frees, and MUI_NOFREE:
  - McDestroy order (MC:1327-1356): leave callback (MC:1335), restoreDescRect (MC:1336), unlinkOwn (MC:1338), entry destroy() (MC:1340-1341),
    then provider-owned frees (MC:1344-1352).
  - unlinkOwn (MC:932-975): drops engine refs (MC:941), truncates the list only if canTruncate passes (MC:960), then marks items unlinked (MC:971-973).
  - Frees: only items that are not nofree, and only if clean && freeLabels && unlinked (MC:1347). freeCtl calls vt[0] only for label or button vtables (MC:912-917).
  - MUI_NOFREE: listed and shown/hidden with its page, never freed by the provider (MC:1346). Control() goes null after unlink (MC:1158-1162).
    The consumer frees it after destroy() sees Control()==null. If the unlink is refused (clean=false), no frees happen and pointers stay (MC:1338, :1347).
  - ini free_labels=0 disables provider frees (MC:258, :1347).

Q3. Tick path, kTickGapMs watchdog, the 0x40 guard, fragile spots
==========================================================================================
McTick = CSWGuiPanel::Draw 0x40EC90 (MC:1233-1234; hooks toml). Per draw, in order:
  MC:1235  [ECX] == Options vtable, else return. Raw deref, not saferead.
  MC:1240  panel bound check.
  MC:1246-1247  clear every entry-item latch.
  MC:1248-1250  gap = GetTickCount delta vs lastTick (0 on first draw; lastTick reset in resetState, MC:161, MC:1192).
  MC:1251-1252  flags48 at ctlFlagsOff.
  MC:1260-1262  Esc key edge: any non-MAIN page -> resetPages("esc key").
  MC:1263       WATCHDOG: gap > kTickGapMs -> resetPages("tick gap"). kTickGapMs = 500 (MC:69).
  MC:1266-1269  0x40 GUARD: appended && !(flags48 & 0x40) -> if not MAIN, resetPages("panel hidden"); return.
  MC:1270       firstTick() once (MC:602-688).
  MC:1271       applyTargets(e,false): drift re-apply of fixed targets (root, list, Back, title, moved rows).
  MC:1272       syncDescSplit("tick").
  MC:1273-1277  drift re-apply of entry-item rects while ENTRY is shown.
  MC:1280-1286  cursorEngine, lmbDown, hitItem, overBack, hoverStep (hover enter -> writeDesc, MC:870-873).
  MC:1293-1294  ClickTracker (release edge) for main and back.
  MC:1300-1314  dispatch: MAIN item 0 -> LIST; LIST -> entryClicked (push ENTRY); ENTRY -> latch for Clicked (MC:1307-1308); Back on ENTRY -> back(); Back on LIST arms leaveAt = now+100 ms (MC:1313).
  MC:1316-1319  leaveAt fires once LMB is up.
  MC:1320-1323  ENTRY: g_ent[k].tick(2+k,user), called last.

What resetPages does (MC:811-814 -> MUL:192-204 -> applyEvent MC:734-798):
  - LEAVE ENTRY: calls leave(), then syncDescSplit("leave"), then hides items.
  - ENTER MAIN: restoreVanilla, or defers it via restorePending while LMB is down (MC:745).
  - pageChange also clears hover, click trackers and leaveAt (MC:800-809).
  - NOT reset by the watchdog: restorePending, prevDown, prevEsc, lastFlags48.

The 0x40 guard exists already (MC:1264-1269). Its comment (MC:1264-1265) says 0x40 is the shown bit, from live logs 10-17, and bit 0x2 is clear in both states.
  It needs, to be authoritative:
  (a) to run BEFORE the watchdog at MC:1263 (or the watchdog must be skipped when 0x40 is set). Today a visible panel with a >500 ms gap is reset to MAIN.
  (b) to keep the appended==false exemption (MC:1266 comment), so the first draw always reaches firstTick.
  (c) a host test or probe. The bit is evidenced only by a log comment. HIDDENDRAW (MC:1254-1256) logs flags48 changes, capped at 32.
  Hidden draws already return before applyTargets, so no SetRect re-apply runs while hidden.

Other fragile spots:
  - kMaxReapply = 8 (MC:68) never resets for fixed targets: applyOne (MC:283-291), addTarget (MC:300-315). Entry items reset on enter (MC:781-785) and on SetRect (MC:1121).
  - Clicked() latch is set only on ENTRY pages (MC:1307-1308) and cleared at the start of each tick (MC:1246-1247). Consumers must read it inside tick() (MC:1322) or in the same tick.
  - Hover desc is not cleared on leave (MC:870-873 writes only on enter; MC:875 writes the list blurb only on LIST).
  - describe() calls vanilla 8A2320 on every hover enter (MC:396-420, MC:872). That rewrites the LB_DESC rect, and syncDescSplit repairs it (MC:435).
  - muiSetDesc ignores the page (MC:1128-1131) and writes into whatever page is shown.
  - Silent truncation: text 95 chars (MC:570-575 via MC:1056, :1079, :1112); desc 191 chars (MC:1058); page title 63 chars (MC:1031).
  - McTick raw vtable deref (MC:1235). fopen("mod_config.ini") is relative to CWD (MC:236).

  - paneViewRect and paneStatusFloor are not host-tested. No test file references them.
Paging or scrolling beyond 8 rows:

  - PageTable::setVisible (MUL:325-329) and hitTest (MUL:331-340) exist and are host-tested (MUT:353-403). The provider never calls them. Hit tests use guikit::hit (_shared_src/GuiKit.h:484-486) via overCtl (MC:564). Show/hide uses setShown (MC:560-562).

==========================================================================================
VERDICT
==========================================================================================
  - Attach stepper and toggle rows as consumer compositions now. Zero ABI change.
  - Slider needs 2 append-only slots (SetItemDesc, Held). Paged column needs 1 (SetVisible). Item cap query is 1 more slot. Ini service is a new interface, not a slot.
  - Do NOT build slider or paging until the 0x40 guard runs before the 500 ms watchdog (MC:1263 vs MC:1266). Otherwise a visible page can be reset by a hitch.
  - Any new slot: follow the Q1 file list (API, MC, MCT, holster and enemy pins). Missing a positional initializer zero-fills silently.
