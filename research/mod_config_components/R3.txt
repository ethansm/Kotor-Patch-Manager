## A. Row-type census (7 planned entries, 21 rows)

Types: TOGGLE = 2 values (button flips). ENUM = 3+ named or preset values (button cycles). STEPPER = one numeric key, uniform step or a sentinel, shown as label + "<" ">". SLIDER = wide numeric range wanting fine control. OTHER = multi-key pair, hotkey, or text.
Tag = KEEP/WEAK from audit sec 3. Preview: STRONG = effect only visible on a 3D model; HELPFUL = effect only visible in a HUD strip or target menu; N = none needed.

## C. Which mods need a live preview in the right pane

- Enemy Effects Strip: has one (0.4.1). Uses SetDescSplit + PaneRect(MUI_PANE_PREVIEW) + AddCustom(MUI_NOFREE). Provider already supplies all three (ModConfigApi.h: MUI_PANE_PREVIEW=6, split clamped 600..850).
- Holster Editor: largest consumer. 3D view as AddCustom in MUI_PANE_VIEW (HolsterEditor.cpp:598), SetDescSplit 850 (:591), preview_3d client (g_p3, :2675). Complexity ceiling for the shared layer (70 widgets, 6 sliders, 5 bones).
- Inventory 3D (rows 13-15) and Equipment 3D (rows 16-18): STRONG. Effects show only on a 3D model. Neither uses the preview_3d provider today (they draw in their own panel code, Inventory3DViewport.cpp and EquipCharPreview.cpp). Row 17 is labelled "on preview". Preview_3d API (Preview3dApi.h): CreateView, Bind, SetView, PlayAnim, ViewControl.
- Combat Hotbar (rows 6-7) and Queue HUD (rows 19-21): HELPFUL. Button grid / strip mock only.
- Action Hotbar and Inventory Sort: no preview needed.
Shared layer must leave PANE_PREVIEW (or a VIEW pane with AddCustom) in the layout; a 3D preview needs ViewControl placed there.

## Findings to act on (5 max)

1. queue_hud.ini is 5011 bytes (audit sec 6 says 4718, stale). Reader fread stops at 4095. companions (byte 4289), strip_icon_px (4455), strip_side (4776), strip_max (4829) are past the cut. All four are commented defaults, so shipped behaviour is unchanged, but a menu write to companions is invisible until the reader is fixed (QueueHud.cpp:122-123).
2. Rows need three control types the enemy page lacks: ENUM cycle (4 rows), SLIDER (2), pair (1, row 18: flourish_min_s + flourish_max_s, one row for two keys).
3. Inventory sort: missing keys read OFF (InventorySortFilter.cpp:124-126) while the shipped ini sets sort, tint and cycle ON. A menu Reset must write explicit values (matches audit bug 4).
4. Three clamp policies and four duplicated clamp helpers. Any shared clamp must carry a per-row policy, or the inv3d/equip3d reset-to-default rule will silently change for other rows.
5. Enemy strip's tier-ordering rule (sanitize 287-288) and the holster slider rows show that cross-field rules and custom sliders stay in consumer code or in a slider type; the shared spec should not try to express them.

Not verified: live game-dir ini copies; whether WritePrivateProfileStringA keeps comments on this Windows build; inv3d and equip3d key-to-menu mapping was checked by key name only, not by in-game effect.
