Claims in the draft that look wrong:
- Section 3.1 L0, "writes atomically (temp file, then rename)": the existing per-call writer is not atomic (record_run.py:182, 186). The atomic pattern exists in dr.py:113-118 and must be reused, not assumed.
- Section 3.1 L0, "enforces a per-call and per-stage budget": per-call is the --max-budget-usd flag (run_map.sh:170). Per-stage is checked only between waves (run_map.sh:292-294) and the approved ceiling is not read at runtime (dr.py:733 sets it; no engine script reads it).
- Section 3.4(c), "verdict field last" as a structural guarantee: the validator checks no key order (record_run.py:31-62). It is a prompt-level hint only.
- Section 3.4(d), cache key: omits the system prompt (run_map.sh:175), tool list and permission mode (run_map.sh:170-173), settings file hash, and CLI version.
- Section 3.4(d) vs 3.4(f): a content cache and a 5% re-run determinism sample conflict unless the sample bypasses the cache.
- Section 3.5, "Cache: identical call inputs are never re-billed": no input-hash cache exists. The existing skip is per packet id (prep.py:896-901).
- Section 3.5, "Cost is taken only from the CLI result": true for the source, but missing cost is coerced to 0 (record_run.py:150; prep.py:1154). Gap, not a violation.
- Section 3.5, "UNSURE" on prompt caching: record_run.py:65 already captures cache_read_input_tokens per turn, so the answer can be read from existing run JSON with zero spend.
