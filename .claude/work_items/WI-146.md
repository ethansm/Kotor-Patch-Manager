## Goal
`readItemName` (InventorySortFilter.cpp:151) runs for every buffered row (:362), calling GetString 0x7356B0, whose side effects REA 20261015 marks UNSURE (cache insert, dirty flag at container +8, gender write into the talk manager +0x3C). `before()` (SortLogic.h:36) needs the name only when two rows tie on isNew, usable and baseItem. Read names lazily at flush for tied rows only, and fetch the client language once per populate.
## Steps
1. SortLogic.h: add a pure helper `template <typename F> int fillTiedNames(Entry* e, int n, F readName)` that leaves `name` empty for rows whose (isNew, usable, baseItem) key is unique in the buffer and calls `readName(e[i])` for the rest. Returns the call count. O(n log n): sort an index array by the key with std::sort, then walk runs of length >= 2.
2. sort_logic_test.cpp: 4 rows with keys A, B, B, C. Expect readName called exactly for the two B rows, and the sorted order the same as when all names are filled (empty names only on unique keys never change the order, because the name key is reached only inside a tie).
3. InventorySortFilter.cpp: remove the per-row `readItemName` call (:362). In SortFilterFlush (:391), before `sortEntries`, compute the language once (the GetClientLanguage block at :155-157 moves into a `clientLanguage()` helper that returns -1 when unavailable), then `fillTiedNames(g_buf, g_n, [&](isf::Entry& e){ readItemName(e.item, lang, e.name, sizeof e.name); })`. readItemName takes `lang` as a parameter and returns early when lang < 0.
4. Item pointers are still valid at flush: the rows are created from the same pointers in emitBuffered (:277) right after. Note this in a comment.
5. Add `names=%d` (call count) to the `sort timing` line.
