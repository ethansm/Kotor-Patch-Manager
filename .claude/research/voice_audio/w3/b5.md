## Q: can a model licence permit shipping generated audio inside a free mod?
- YES in principle: Apache-2.0 and MIT carry no output clause. Ship the audio, not the weights. Conditions: Kokoro CC BY voices need credit; Maya1 s4 misuse bar; no voice that resembles a real actor.
- NO / treat as NO: F5-TTS (NC; whether NC reaches outputs is unresolved, u09 OPEN 1), XTTS (CPML), IndexTTS-2 (s1.5/s3.4 until read in full), kNN-VC (clause), Fish/Higgs (research/NC), ElevenLabs cloud output (credit + commercial-tier rules, ban risk if actor audio uploaded).

## Routes

### R1 Fully original designed voices (Qwen3-TTS VoiceDesign -> Base clone prompt; Kokoro and Maya1 as fallbacks)
- Pipeline: `generate_voice_design(card text)` -> 10-20 s reference -> `create_voice_clone_prompt` (Base) -> `generate_voice_clone` for all lines.
- Licence public: YES (Apache outputs; Maya1 s4 bar). Private: YES.
- Watermark: none in qwen-tts package (weights not audited). Kokoro none in package. Maya1 README silent.
- Quality risk: MEDIUM. Designed timbres read as synthetic; long lines weaker. Unmeasured for 5070.
- Per-line cost: local GPU wall time only (unmeasured). Cloud comparison: ~$0.008/line v3 or ~$0.004 Flash at 100 chars (200 lines ~ $1.60 / $0.80).
- 200-line consistency: reuse one clone prompt. No seed in package, so drift is UNTESTED. Spike measures it.
- Emotion: VoiceDesign `instruct` is free text but Base clone takes no instruct (u09 fact 4), so emotion and identity lock conflict. Maya1 tags with a fixed description are the alternative (untested). Kokoro: no emotion control.
- Batch tooling: `pip install qwen-tts` (batch generate_voice_clone); kokoro pip; ffmpeg.

### R2 User's own voice + speech-to-speech into a designed target (RVC MIT; Seed-VC GPL-3.0 archived; kNN-VC avoided)
- Pipeline: user records 200 lines -> RVC infers toward a target model trained on R1 (Apache) clips, never on actor audio.
- Licence public: YES on RVC MIT, subject to a VCTK base-data licence check. Private: YES.
- Watermark: none found in README; RVC code not audited.
- Quality risk: MEDIUM-HIGH. STS artifacts on 10 min data; output tracks the user's acting ceiling.
- Per-line cost: user time ~17 min raw speech for 200 x 5 s lines, roughly 1 h with retakes. GPU per-line and RVC training time unmeasured (u10 OPEN).
- 200-line consistency: STRONG. One checkpoint.
- Emotion: STRONGEST. User performance carries prosody; RVC keeps the source pitch contour (known behaviour, untested here).
- Batch tooling: RVC CLI/WebUI infer; shell loop; ffmpeg for resample.

### R3 Helmet / droid / radio FX chains over TTS (R1 or user audio as input)
- Pipeline: ffmpeg chain (highpass 300, lowpass 3400, acrusher, compressor; ring mod 140 Hz for droid; rubberband formant=preserved for sound-alikes). K2 header fix `tail -c +59`.
- Licence public: YES (FX create no licence; ffmpeg/rubberband are GPL tools, output unrestricted). Private: YES.
- Watermark: none added. Inherits the base TTS (R1 clean).
- Quality risk: LOW. Robotic is the goal. u10 helmet band (centroid 1500-1700 Hz, RMS -19.9 to -23.4 dB) sits close to vanilla K2 samples (1564-1754 Hz), not a verified radio match.
- Per-line cost: ~0 (CPU ffmpeg).
- 200-line consistency: DETERMINISTIC chain. Identity still needs R1 lock.
- Emotion: LIMITED to base TTS plus effects.
- Batch tooling: ffmpeg filtergraph loop; aeval/acrusher/tremolo/aecho confirmed in local build (u10).

## 1-week spike plan (5 days, about 25 h total, $0 cloud)
1. Day 1 (4 h): scratch venv, torch cu128 or cu130, `pip install qwen-tts==0.1.1`. Generate 1 designed voice + 20 lines. Log s/line and peak VRAM (`nvidia-smi`). Pull raw LICENSE from Qwen3 and Maya1 HF repos. GATE: runs under 12 GB VRAM, RTF under 1.0.
2. Day 2 (5 h): 200 lines of original text (never K2 text). One `create_voice_clone_prompt`, 200 generations. Speaker-embedding cosine vs reference (ECAPA, licence to check) against 3 same-speaker re-renders as baseline. GATE: median cosine within baseline margin, define margin from baseline data.
3. Day 3 (4 h): emotion A/B. Qwen VoiceDesign instruct vs Maya1 tags, 10 lines each. User listens blind (10 min). GATE: user picks a route.
4. Day 4 (4 h): R3 chain on Day 1 output (helmet, droid). Compare band to u10 vanilla. User listens to 3 clips. GATE: intelligible and mechanical.
5. Day 5 (6 h): R2 mini. User records 20 lines (about 5 min with retakes). RVC trained on 10 min of Day 1 clips; log training time. GATE: training under 2 h and STS intelligible. Same day: sound-alike screen of any design against private actor references, reject closer than baseline.
