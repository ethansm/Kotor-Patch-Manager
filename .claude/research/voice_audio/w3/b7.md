# b7 persona cards tied to texture variants (lens: persona cards)

Design only. Nothing installed. Eight sample cards: `.claude/research/voice_audio/w3/b7_persona_cards.toml` (text only).

## Idea: texture-keyed persona card
- Player experience: a generic commoner variant on 302NAR keeps one look, one name and five barks on every visit.
- Look: texture variant `texa` + `%02d` (doc 34 sec 1.1, loose files load, fallback 01). Proven delivery.
- Name: inline FirstName (doc 35 plan). UNVERIFIED in game.
- Barks: literal text, no TLK. Native path `CSWCCreature::BarkString` 0x77B140 has no text call (W2). Text playback is E4, unknown.
- Voice: optional kit. Commoner soundsets are mostly silent (n_commm 0 of 6 files; n_commonf 3 of 4; k2_soundsets rows 11, 57).

## Card schema (TOML v1)
- `[card]` id, planet, status: `look-ready | voice-only | blocked:<why> | draft`
- `modules[]`: corrected codes only (gemini_module_claims.tsv). `never_tags[]`: 203_b4d4, 203_Lorso, 203_Chano, 202_Falt (doc 34 sec 7 item 8).
- `replaces_generic`: census name and count (placement_census.tsv).
- `species`, `body` (texa or model), `appearance_row` (doc 35 table, or probe), `look` (catalog cid + canvas), `texture_var` (B6 allocator).
- `name_pool`, `name_example`, `display = inline | tlk:<strref>`.
- `voice = silent | soundset:<name> | avo:<pool> | synth:<local id>`, `lip = generated | none`.
- `barks[]`: 5-10 lines, 12 words max. `pairs[]` (card ids), `events[]`, `weight`, `cooldown_visits`.

## Pipeline: texture -> persona -> voice -> casting
1. Look: recipe from catalog P/K ids, written as `texa NN` via B6. Gate T1 vs parent. Never edit vanilla 01.
2. Persona: template plus name pool filtered by species, gender, planet. RNG seeded by look id, so reruns match. One Haiku worker per card.
3. Voice: kit chosen by species. `.lip` from the python writer (W1: round trip on 677 files). Kit files stay local, with licence tag.
4. Casting: on area entry or encounter start (doc 40 sec 4). Pick by module, cooldown and pairs. Exclusion list (doc 34 sec 3.3) always wins.
5. Gate: schema lint, module codes vs K2 Modules, names vs named-NPC list, TLK strrefs only from ledger.

## Name and text sync (no dialog.tlk collisions)
- Default is literal: inline names, literal bark strings in a generated data file. No TLK, no collision. English only.
- TLK only when a bark must ride an SSF or SoundResRef (W1: SSF slots resolve through dialog.tlk).
- dialog.tlk is one file: one owner, a per-card strref block in `persona_strref_ledger.toml`, ranged append (precedent `scripts/append_ranged_kite_tlk.py`). Build fails on overlap.
- Never reuse 36701-36703 (n_commm grunts). Card TOML is the only writer.
