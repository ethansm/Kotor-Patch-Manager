# v07: delivery of custom audio, LIP and text (w10-voice, wave 2)

Scope: how this project can deliver custom audio, LIP and text for a KOTOR II mod. Read-only recon. Game dir K2 = `~/.local/share/Steam/steamapps/common/Knights of the Old Republic II` (`~/.steam/...` is a symlink to it). KPM checkout = `~/Games/KOTOR2_Mod_Workspace/tools/kotor-patch-manager` (called KPM below).

## Delivery mechanism

F1: A kpatch carries only `manifest.toml`, `*hooks.toml` and `binaries/*`. No Override, .wav, .lip, .tga, .2da or TLK. KPM `Patches/create-patch.py:842-870` writes exactly those; `KPatchCore/Managers/PatchRepository.cs:254-271` and `:331-358` extract only `binaries/<dll>` and hooks. Installer steps 1-4 (`PatchApplicator.cs:132-397`) have no copy-to-game step.
F2: Loose files therefore land by out-of-band copy. Pattern: `patch_manager_mods/k1_port/k1_port_probe.py:9,228-230,383` copies named files into `<game>/override/`, refuses foreign files, keeps a sha manifest and save backups. Echoes compat `scripts/06_deploy_assets.py:258-285` copies the StreamVoice tree preserving relative paths (skips existing files) and deploys override files.
F3: Textures can also come from DLL memory with no files. `KPM docs/RuntimeGuiControls.md:117-140` registers a `CAurTextureBasic` by constructor. No audio or LIP equivalent exists in the repo.
F4: Nothing in the repo writes dialog.tlk from a DLL. Writes are offline pykotor scripts with backup and atomic replace: `scripts/append_ranged_kite_tlk.py` (dry run by default, `--apply` backs up and verifies) and `scripts/02_merge_2da_and_tlk.py:30,157-184` (refuses a second run). DLL code only reads TLK: `patch_manager_mods/action_hotbar_src/Tlk.h`, `ActionHotbar.cpp:114`.
F5: Live dialog.tlk: header `TLK V3.0`, lang 0, count 136540, string block at 5461620. Entries 136538 "Ranged (Kiting)" and 136539 "Ranged (Kiting) Behavior..." are the applied append from the script above, so the precedent is live. Count 136538 before append matches the script docstring.
F6: TSLRCM: no TSLRCM files were inspected. Repo mentions are only in `neocities_mods.json` and `neocities_mods_detailed.json` (`anchor: tslrcm`). Whether TSLRCM edits dialog.tlk or Override names is UNVERIFIED. Coexistence risk: any two TLK appends target the same end-of-table strref, so the second writer must re-read the live count.

## Engine lookup (what the game searches)

F7: One-shot SFX go through the resource manager. `patch_manager_mods/engine_research_findings/U2.md:56,104`: `CExoSoundInternal::PlayOneShotSound` 0x00708360 allocs a source and loads a WAV via CResWave (restype 4 is SPECULATIVE per `W7.md:185`). Override-over-chitin precedence is VERIFIED for textures (doc 38 claim 7); for WAV it is UNVERIFIED.
F8: Streams bypass the resource manager. `U2.md:44-45,104`: `StreamingSource::StartStream` 0x0070C0C0 builds STREAMSOUNDS / STREAMVOICE / STREAMMUSIC paths, and `OpenStream` 0x0070CAA0 `fopen`s up to 0x20 candidates on disk. Override is not in that list per the research. The `"*%s*%d*%d"` pattern is noted but not decoded.
F9: KPM ships a kpatch that changes this disk probe. `Patches/K2MP3PlaybackFix/MP3PlaybackFix.cpp:1-16` (v1.0.1, hook 0x0070CDCB in `kotor2-steam-aspyr.hooks.toml`): each ResType_MP3 candidate is rewritten to .wav before disk probing. Loose .mp3 is preferred over same-named .wav only with this patch. Proof that a kpatch can hook the audio path.
F10: Live StreamVoice: top level 764 .mp3 + 13 .wav (`rakahaps1.wav`, `manobeythelaws.wav`, `rakata1.wav` and others); nested 17,545 files in 79 dirs. Every nested stem starts with folder 1 and contains folder 2 (17,545 of 17,545), but no fixed split holds (3+8 fits 5,778; e.g. `906/partycages/906partycages004.wav`). Flat top-level files exist, so "TSL needs a DLG subfolder" (doc 38 claim 11) is PARTIAL. The engine's exact rule is UNVERIFIED.
F11: Live Override top level: 20,572 entries, 720 .lip, 26 .wav. `AVO_T3M4QUESS1-3.wav` match the StreamVoice/AVO/_T3M4QUE copies (same sizes). `dm_estf_*.wav`, `dr_mal02.wav`, `gui_scroll.wav` and `wk_visq_groan.wav` are not in StreamSounds or StreamVoice. `dm_estf_cl1` is absent from chitin.key. Origin of these loose WAVs is unknown.
F12: Web (community only, not primary): a DeadlyStream thread says VO is a mono MP3 with a fake WAV header and that the Steam build wants MP3, not WAV (`https://deadlystream.com/topic/4058-problems-with-audio-and-lip-syncing-tsl/`; `https://deadlystream.com/files/file/2558-k2-alternative-voice-overs`). Conflicts with F11 and is UNVERIFIED. reone and xoreos stream code was not checked (search returned no source).

## LIP, SSF, DLG, tooling

F13: No LIP writer and no SSF writer exist in the repo. `.claude/waves/w10-voice/tmp/u11/lipcheck.py` (100 lines) parses `LIP V1.0`, float length, uint32 count, and checks size = 16 + 5*count. A round-trip writer is scratch-only (W1: 677 files).
F14: TLK writer in repo = pykotor `read_tlk` / `write_tlk` (`scripts/02_merge_2da_and_tlk.py:30`). SSF writer: none (W1 u03).
F15: `patch_manager_mods/kpm_hotswap.py:45` (`DLL_IN_KPATCH`) swaps only the DLL. Override delivery has no KPM tool; it is a copy plus manifest.

## Recipe ranking (one custom bark)

A. Literal text + PlaySound(resref) + loose WAV in Override (rank 1). Needs: a short WAV named with a unique resref <=16 chars (e.g. `k2np_bark01`); an NCS script calling `PlaySound` and `ActionSpeakString` (repo script compile via `nwnnsscomp`, per memory `kotor2-script-compiler`); the WAV copied into `override/`. No TLK edit, so no TSLRCM collision. Unverified: that PlaySound resolves a WAV through the resource manager (F7 suggests yes, F8 says streams do not); that ActionSpeakString draws overhead text (W1: unknown).
B. TLK strref (rank 2). Needs: an offline append (backup + atomic replace, like `append_ranged_kite_tlk.py`) of a row with text and SoundResRef; strref = live count at apply time; BarkString by strref. Unverified: whether BarkString plays the TLK row's SoundResRef (W1 open). Collides with any other appender (TSLRCM unknown, Echoes, RangedAI rows 136538-9).
C. DLG (rank 3). Needs: a new .dlg GFF with VO_ResRef and a conversation, plus a GFF writer. Heavy for one bark. Delay -1 is a root sentinel (W1), not a wait.
(Unranked) D. DLL plays an in-memory CResWave via PlayOneShot, like RuntimeGuiControls section 6. Needs RE of the CResWave constructor and a hook; no evidence it works.
