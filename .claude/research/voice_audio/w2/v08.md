## Q4: is a soundset change at remap time required?

F14: Not for dialogue (F4). Yes only for combat grunts when the body's sex or species differs from the template's voice. Remap time is the wrong place: the remap runs client-side on appearance, while the soundset is set server-side at load (F2). A remap-time write would touch only the client copy, and its source is unmapped (`GetSoundSet(ushort)` unmapped in V6 L213).
F15: Option (a) gender-only gate: male templates keep 6 of 16 rows, female templates keep 10 of 16 (F13). It does not fix Twi'lek. Option (a) race gate drops all 10 Twi'lek rows.
F16: Option (b) offset: u03 and `.claude/research/npc_add/R2_script_route.md` have none. The only offset is V6 stats+0x10EC (F2). Client write path is unknown.

## Decision criteria
1. Audible? Play one combat on a Twi'lek look and one wrong-sex look. Human grunts on a Twi'lek or the wrong sex are a MED finding only if noticed.
2. Crossing rate: add template gender and SS row to the existing REMAP debug line (`npc-diversity_debug.txt`), then count how many remaps cross sex or species per visit.
3. Save persistence: if the save writer serialises stats+0x10EC, a load-time write bakes into saves (the failure doc 34 is built to avoid). REA check needed.
4. Client source: if the client soundset comes from the same create message as stats, one server write suffices; if not, a second write is needed. REA check on `GetSoundSetStrres` `0x00765AA0`.

Recommendation: (c) accept now with the REMAP log change (no engine write, reversible). Use (a) gender-only if criterion 1 says wrong-sex grunts are noticed. Use (b) only after criteria 3 and 4 pass, at load (`0x6AFED0`, keyed on tag), not at remap time. Do not use the race gate (drops the Twi'lek looks).
