# u02: LIP format, 16-shape table, lookup (w10-voice)

Probe script: `.claude/waves/w10-voice/tmp/u02/lipprobe.py` (run with `python3 -I`). Local LIPs read from `swkotor/lips/*_loc.mod` (K1, 18,206 LIPs) and `Knights of the Old Republic II/lips/*_loc.mod` (K2, 26,640 LIPs).

C1: CONFIRMED - 'LIP V1.0' (8 B), f32 length @0x08, u32 count @0x0C, then 5-byte {f32 time, u8 shape} from 0x10; size == 16+5n in all 44,844 non-empty payloads; reone `src/libs/graphics/format/lipreader.cpp:27-42`
C2: REFUTED - indices 0-5 right, but 9=ng, 11=m/p/b, 12=t/d, 13=sh (not M/B/P, F/V, L, T/D). Rakata "The 16 visemes" https://synchro.codeberg.page/rakata/formats/audio/lip.html ; PyKotor `pykotor/resource/formats/lip/lip_data.py:112-127` (same table)
C3: PARTIAL - Rhubarb A=MBP, C=EH, D=AA, E=AO, F=OO/W, G=FV, H=long L, X=idle map cleanly; B (most consonants + EE) is a catch-all with no single target. Source https://github.com/DanielSWolf/rhubarb-lip-sync (WebFetch summary, not raw). Never run on a real clip.
C4: UNSURE - rakata: a LIP failing the checks makes LipSync "apply nothing" (`CSWCCreature::LipSync`, 0x0070c590, "derived, not attested"). What the mouth does instead is not established. KotOR.js `src/resource/LIPObject.ts:196-224` drives the 'talk' anim only when keys exist.
C5: PARTIAL - Lookup order: Override (pass 1), patch.erf + RIMs (2-3), module .mod and `lips\<root>_loc.mod` (4); first match wins; https://synchro.codeberg.page/rakata/formats/resource_system.html ("The search order inside a key table"). Local: K1 LIPs only in `lips/` (0 in K1 `modules/*.rim`, 0 loose in K1 Override); K2 LIPs in `lips/`, 82 of 710 module MOD/ERF archives (all cases), 16 entries in K2 `.rim` (702KOR_s.rim), 720 loose Override .lip.

## Correct 16-entry table (engine index: label)
0 neutral/rest, mouth closed | 1 ee | 2 eh | 3 ah | 4 oh | 5 ooh | 6 y | 7 s/t cluster | 8 f/v | 9 ng | 10 th | 11 m/p/b | 12 t/d | 13 sh | 14 l | 15 k/g

- Index 0 is the first key of all 44,844 non-empty LIPs and the last key of 44,692 (99.7%). That makes 0 the rest shape.
- KotOR.js `LIPObject.ts:353-368` lists "ee" at index 0 and has no neutral slot. The data refutes that at index 0.
- Engine maps viseme v to (v+1)/16 of the 'talk' animation (rakata, LipSync).

## BEYOND
1. Validity gate (rakata): first key must be t=0 and last key ≈ header length, else nothing applies. Local data passes this for all 44,844 non-empty LIPs (worst gap 0.0 s).
2. Zero-byte placeholders: 3 in K2 `lips/` (e.g. `101PER_loc.mod` 101medoff013) and 43 loose K2 Override .lip (e.g. 003pcdead2001.lip). Treat as absent. KotOR.js (`LIPObject.ts:68-75`) turns an empty file into one shape-6 key at t=0.5, its own choice.
3. LIP resource type id is 3004 in ERF/MOD and RIM. Every type-3004 payload starts with 'LIP V1.0'. Do not confuse with 2010, the most common RIM type here.
4. `lips/` archive name = module root + `_loc.mod`: 117/123 K1 and 78/79 K2 match a module name. Non-module ones: K1 global, legal, localization, mainmenu, miniglobal; K2 localization.
5. Anomaly: K2 `lips/303NAR_loc.mod` resref 303FASSA041 has key times going backwards (22.12 s to 21.74 s at key 97). Only non-monotonic file in the set.
