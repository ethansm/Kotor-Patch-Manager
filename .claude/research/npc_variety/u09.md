# u09 recon: randomness and determinism

Scope read: DiversityLogic.h:14-100 and 34_npc_diversity_dispatcher.md:150-230. Hash-name grep counts only. Grep-only hits outside range, not read: DiversityLogic.h:152 (ShouldVary, HashCreatureId(oid, originalApp)), :164 (PickTextureVar, HashCreatureId(oid, finalApp)), :197, :248-283 (BandRoll call sites).

## Requirements
- R1 One creature keeps one look for a whole visit. Cache the decision per (oid, visit), or keep the hash input fixed for the visit. Reason: HashCreatureId (DiversityLogic.h:87-96) is recomputed on every call, so any changing input causes flicker.
- R2 Crowd differs per visit. Add a visit salt to the hash input: run seed XOR area-entry counter, Fmix32'd, forced nonzero.
- R3 Reproducible. Log seed and counter at area entry (KpLog). Allow a fixed seed override (ini or test). Tests pass an explicit seed.
- R4 Backward compatible. Default visitSalt = 0 skips the fold, same pattern as HashDescriptor's seed gate (DiversityLogic.h:76-81). Existing hash vectors in diversity_logic_test.cpp (26 hash-name hits) stay valid.
- R5 Exclusion (34_npc_diversity_dispatcher.md:183-187) runs before any hash draw. Named NPCs never touch the seed.
- R6 Each new decision gets a new salt (7+). Salts 1-6 are documented at DiversityLogic.h:43-47 and must not be reused.
- Current doc 34 design: Layer 2 is labelled "Deterministic" (doc:167) and keys the hash on area ResRef + tag + x,y quantised to 0.1 (doc:169-177). Same spawn point gives the same look on every visit and every load. This is the opposite of per-visit variety, so doc 34 §3.2.2 must change.
- Per-visit change list: (1) add `uint32_t visitSalt = 0` to HashCreatureId at DiversityLogic.h:87; (2) set it once at area entry in the dispatcher; (3) cache results per (oid, visitSalt).

## Edge cases / failure modes
- E1 No visit cache -> the roll changes on each engine call -> texture or body flickers while on screen -> cache per (oid, visit) (R1).
- E2 Pointer-based fallback HashSeedFallback(ptr, ret) (DiversityLogic.h:58-67) -> heap addresses differ run to run -> not reproducible -> use only for debug and log every hit.
- E3 Doc spawn hash has no Fmix32 finaliser (doc:169-180); the code comment says the finaliser is needed before a modulus (DiversityLogic.h:31-33). FNV multiply moves bits upward only -> skewed BandRoll -> apply Mix before BandRoll.
- E4 Position-keyed hash (doc:176-177) -> stacked spawns or equal tags give one identical look -> add spawn index or use oid.
- E5 Counter-based salt plus reload mid-visit -> counter moves on load; the saved appearance row does not -> body and texture disagree -> persist the seed in the save, or re-derive it from saved data.
- E6 visitSalt that folds to 0 (about 2^-32) silently drops to old behaviour for one visit -> force nonzero with `|= 1`.
