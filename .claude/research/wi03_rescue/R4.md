# R4: runtime read of baseitems.2da bodyvar for Inventory3DViewport

## Answer
No runtime 2DA reader exists in the repo. `bodyvar` never reaches the runtime. The smallest route is a generated table column, not a runtime 2DA read.

## Findings
1. Shared 2DA API: none. `rg` for Get2DA/Load2DA/TwoDA/2da in `_shared_src` and the `*_src` dirs finds only comments. The only 2DA reader is `patch_manager_mods/action_hotbar_src/TwoDA.h` (`namespace hb`, `struct TwoDA`: `Load(path)`, `Parse(str)`, `Col(name)`, `Get(row, col)`). It reads files from disk, so it is not usable against the game's baseitems.2da.
2. Data source: no `baseitems.2da` exists in the repo. Only `npc_diversity_src/override/{appearance,heads}.2da` and `action_hotbar_src/testdata/spells_fixture.2da`. `scripts/gen_inventory_3dview_table.py:23-34` reads it live via `Installation(game).resource('baseitems', ResourceType.TwoDA)`.
3. bodyvar is dropped at generation: `scripts/gen_inventory_3dview_table.py:40` only tests `bodyvar not in ('', '****')` and folds the result into category 4. `ItemModelTable.inc` (generated) emits `kItemCategory[109]` and `kItemType[109]`, with no bodyvar array.
4. Runtime id: `Inventory3DViewport.cpp:488` reads the baseitem row id from `item+0xC`, and `:493` indexes `kItemCategory[id]`. A `kItemBodyVar[id]` table would be indexed the same way.
5. Engine accessors (Steam, from `ghidra_knowledge/steam_functions.tsv` and the B0 `final_rows.tsv` notes):
   - `CSWItem::GetBaseItem` 0x006D6E30 (`_shared_src/GameAddr.h:89`): thiscall(item), returns the baseitems row pointer. Slot mask at +4, gender byte at +0xB4. No bodyvar offset recorded.
   - `C2DA::GetColumnIndex` 0x0071AEF0 (167 B). `C2DA::GetINTEntry` 0x0071BCF0 (530 B). Both are named in B0 notes only (the KB has FUN_ names).
   - GOG Win names from query_ghidra: `C2DA` 0x006207E0, `GetRowIndex` 0x00621DC0, `GetColumnIndex` 0x00620990, `GetCExoStringEntry` 0x00620A40 (overloads). The Steam GetCExoStringEntry address is not recorded.
   - Missing: the global that holds the baseitems C2DA handle at Steam, and the bodyvar field offset in the CSWBaseItem row.
6. Engine armor resolver: `CSWGuiUpgrade::GetArmorModelAndTextureResRef`, Steam 0x008CD060 (GOG 0x005BD420), `__thiscall`, `retn 20`. It clamps bodyvar to 1-14 and maps it to `modelA..N` / `texA..N` (`01_inventory_3d_viewport.md:361-364`). This is the only recorded value range. The `00_code_review_feedback_2026-09-29.md:44` signature `__cdecl(context, bodyvar, ...)` disagrees with the `thiscall` / `retn 20` in `steam_db_batches/B0/functions.csv`.
7. No recorded list of bodyvar values exists in the repo (outside `.claude/review`).

## Recommended route
1. Extend `scripts/gen_inventory_3dview_table.py` to emit `static const signed char kItemBodyVar[kItemRows]`. Parse `bodyvar` the way `itemtype` is parsed at line 49-50 (int if digit, else 0).
2. Regenerate `patch_manager_mods/inventory_3d_viewport_src/ItemModelTable.inc` with the game dir as argv.
3. In `Inventory3DViewport.cpp` `ShowItem` (line 493 area), use `kItemBodyVar[id]` for the branch-B decision. Index by the same `id` used for `kItemCategory`.
4. Runtime alternative (not recommended now): call `C2DA::GetColumnIndex` / `GetINTEntry` on the baseitems handle. Blocked by the unrecorded handle global and the unrecorded bodyvar column semantics.
