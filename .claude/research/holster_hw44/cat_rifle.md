## Checked, no defect found

- Outward side and mirror: Holster.cpp:1699 sets ouL = left ? -1 : 1 in body frame, rotated by body.q, so left and right are mirrored. Sweep kOut3 (holster_sweep_test.cpp:47) matches. The rifle is two-handed (HolsterLogic.h:92-98), so no dual rifle case is expected.
- Bump direction vs other shoulder: outward is away from the body midline, so it cannot move the hand toward the other shoulder (kShoulder x = +0.176 / -0.164, holster_sweep_test.cpp:45). Head sphere (holster_sweep_test.cpp:31, :51) is a GUESS in the sweep, so head clearance is UNVERIFIED.
- Clamp: runtime peak equals outM exactly (HolsterReach.h:658-661, max at s = 0.5). 0.20 is never clamped at runtime. The 0..0.30 clamp is parse-only (Holster.cpp:512-518, HolsterReach.h:654).
- Draw vs stow symmetry: draw clock is the residual capture window (HolsterSlide.h:340-345, capOn required). Stow clock is the path-share window (HolsterSlide.h:346-351, stowRotEff). Both return 0 at window edges, where reachViaOffset is also 0 (HolsterReach.h:661), so no bump step at window ends. Peaks happen at different times (asymmetric by design, HW42). Transition from residual to plain branch could step viaS (UNVERIFIED).
- slow_holster_x 8: residual window scales (Holster.cpp:2612 slowMs), stow path window scales with slide length, and bump amplitude is unchanged because reachViaOffset gets ms = 1 (Holster.cpp:1723). Not swept (R5).
- Absent keys: via off (Holster.cpp:109); per-category unset = global 0.12 (Holster.cpp:116-117, HolsterReach.h:654).
- Mount-bone topology: torsoUpr_g resolves via dzArm and the hinge fit, not the bone name (Holster.cpp:1698-1703), so the rifle goes HingeBack or OverBack depending on the mount height.
