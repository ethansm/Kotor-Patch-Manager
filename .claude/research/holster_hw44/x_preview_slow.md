## Checked, no divergence (anchors)

- reach_resid_ms scales in both paths: HolsterReach.h:633 (240 base), Holster.cpp:1909 (world residual), 2259 (preview presid), 2612 (world residMs from slowArm).
- Draw residual window: capture at first carry frame (Holster.cpp:1915-1923), window = min(left, resMs), so it is slow-scaled. Preview uses the same function (carryShown 2280).
- Via window: draw side uses the captured msEff (HolsterSlide.h:341-344); stow side is path-driven (slideStowFracWindow, HolsterSlide.h:309-316) in both paths. Via-out resolves through viaOutFor(cat) in both (Holster.cpp:117; 2274 preview, 2620 world). Category via classify(model/mname) in both (2215, 2410).
- HW31 extract lift and orientation: progress-based (HolsterReach.h:384 extractBump, 389-394 reachOriF, 398-441 reachPlan).
- Pole bias window: uses pathF (HolsterReach.h:175-193; Holster.cpp:1742).
- Wrist ease: weight = reach ramp times pct (Holster.cpp:1817, 1824), progress-based.
- Reach weight ramp: progress-based (HolsterReach.h:215-226).
- Stagger scaling: slowMs applied (2526). Only the preview lacks it (X1).
- Smoothing: only easeSmooth and blendQ (HolsterReach.h, HolsterSlide.h). No dt-based filter found.
- Frame-count guards (kReachHoldFrames=3 at Holster.cpp:1498; slideGraceHold 3 frames at HolsterDrawGate.h:96) are frame-based. They cover less progress at slowx 8 but do not create a pop.
- Slide::touch and pump 100 ms guards (HolsterSlide.h:136-156) are real time by design (documented at HolsterSlide.h:235). Both paths call touch.
- Slow latch: world re-latches slowArm on direction change (Holster.cpp:2531); preview re-latches at each toggle (3046). A running slide keeps its armed factor in both; a reversal re-latches in both.
- Slide ends: draw end returns the engine hand pose in both (world 2570-2575; preview 2265-2278). Stow end: carryW is 0 in release, so the branch is ResidNone (HolsterSlide.h:321) and carryBlend (Holster.cpp:1898) keeps the weapon on the mount in both.
- Preview lock and residual state from a closed editor: apiSetPreviewDraw resets all g_prevLock entries on a slide from rest (Holster.cpp:3052). Stale per-Gob state does not survive the next Draw toggle.
- Numeric precision: slowMs rounds once (HolsterSlide.h:245-248); frac, residual and via windows are float over at most about 5600 ms. No visible error found.
- Reach target: preview passes `shown` (2276), world passes `out` (2623). Position is identical; only the hemisphere-locked quat differs, and reachArm reads only tgt.pos for the non-carry case.
- g_reachSlowX (log density only): world resets it (2572), preview sets it per frame and never resets (2275). Log-only, no pose effect (1566-1569).
