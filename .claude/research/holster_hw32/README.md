# HW32 offline slide sweep (W6b, HW32c; doc 42)

Host-only research, nothing shipped. Source: `patch_manager_mods/holster_src/holster_sweep_test.cpp`. Asserts: `python3 scripts/run_tests.py holster_sweep` (29 checks, 0 failed; with a relative `TMPDIR` the link fails, use an absolute one).
Build: `g++ -std=c++17 -Wall -Wextra -Werror -I patch_manager_mods/holster_src -I patch_manager_mods/_shared_src -I tests/include patch_manager_mods/holster_src/holster_sweep_test.cpp -o "$(mktemp -d)/sweep"`
Table: `"$SWEEP" --table [--dir draw|stow|both]`. TSV: `"$SWEEP" --tsv <path> [--dir draw|stow|both]`. `--dir draw` is the W6b shape (469 lines = header + 468 rows); the default `both` is 937 lines (936 rows). 39 families, 0 skipped, 0 NaN.
TSV columns: family mount hand via status; head and torso x tip, butt, shaft min and step (0..199); static_head, static_torso (metres); src (`log` | `quat` | `guess` for back mounts, `-` otherwise); dir (`draw` | `stow`); path (`resid` | `blend`).
`sweep.tsv` in this folder is the W6b output (old model, 468 rows). It is not regenerated by HW32c; step 5 of HW32b writes `sweep_b.tsv`.

## Read first: back numbers sit on a GUESS mount
The back mount quat is a GUESS (45 deg from +z toward +x). The static back pose already clips at rest (static -0.003 to -0.095 by category). Every back number below moves with that quat, so they are not tuning inputs until HW32b feeds the measured quat (`--mounts-json`). Hip and thigh use an identity GUESS too; only their sign and structure are meaningful.

## HW32c revision
- Draw and stow (`--dir`). Stow is `s.target(false, ...)` from a full draw, 600 ms.
- The carry follows `carryShownBase`: the hand-frame residual (`ResidDraw` / `ResidStow`, window 240 ms, via in the hand frame as `conj(carried) * via`) when `slideResidBranch` picks it, else the world blend (`carryBlend`).
- Via clock: `slideViaProgress` (previous frame's capture). While the via is on, the aimed point moves outward by `reachViaOffset(s, 1, 0.12 m)` (body outward, `kOut3[hand]`), before the extract lift and the solve.
- Via quat: the runtime's `reachViaFor` (Holster.cpp:1480-1489, literal copy in the sweep): `arcQuat(mount-rotated long axis, world up) * mount quat`, so the mount roll is kept. The first HW32c revision used `qFromTo(axis, up)`; the R-W4 review (B1) caught it. With the fix, draw moves by at most 0.0002 and stow via-on back moves by up to 0.03 m (pistol -0.1025 -> -0.1264, rifle -0.0963 -> -0.1253, heavy -0.0940 -> -0.1238). The README numbers below are the fixed ones.
- Extract lift before the two-bone solve. The solve clamps the target to reach; the hand sits at `S + (T - S) * reach`.
- Flags: `--back-quat w,x,y,z` (normalized), `--mounts-json <file>`, `--dir`, `--pole-grip a` (0..1, hip and thigh). `--pole-grip` changes no number: the elbow is not a clearance proxy (verified: table and TSV byte-identical at `--pole-grip 1`).

## How HW32b runs
Run from the repo root. The game's holster log needs MOUNT lines (`log_mount=1` or `log_verbose=1` in holster.ini).
1. `python3 scripts/holster_log_check.py --mounts --json > m.json`
2. `python3 scripts/run_tests.py holster_sweep` (builds the binary and asserts). The binary goes to `${TMPDIR:-/tmp/claude-$(id -u)}/kotor-tests/host/`. If you set `TMPDIR`, make it absolute: a relative value fails at link time.
3. `SWEEP="${TMPDIR:-/tmp/claude-$(id -u)}/kotor-tests/host/holster_src__holster_sweep_test"`
4. `"$SWEEP" --mounts-json m.json --table`
5. `"$SWEEP" --mounts-json m.json --tsv .claude/research/holster_hw32/sweep_b.tsv`

Mount rules: `cat` in `m.json` is the Category index (0 unknown, 1 lightsaber, 2 melee, 3 qstaff, 4 pistol, 5 rifle, 6 heavy); a name is accepted too. For each back-mount category the entry with the most samples over `torsoUpr_g` / `torso_g` (case-insensitive, as `reachIsBackBone`) gives the quat (`src=log`). A category without a usable entry keeps `--back-quat` (`src=quat`) or the GUESS (`src=guess`). Hip and thigh bones are not used.

Smoke (planted file `.claude/waves/hw37b7/w4/plant_mounts.json`): a qstaff entry `rel [0.92,0,0.38,0]` on `torsoUpr_g` gives `src=log` on the four `w_qtrstaff_` back rows and the same numbers as the GUESS (the 45 deg GUESS for a z-axis shape is that quat).

## Findings (HW32c, guess back quat)
1. Static back mount clips (unchanged from W6b). Every back number depends on the GUESS 45 deg quat. Static back clips of 78 by `--back-deg` (W6b): 0: 4, 15: 48, 30: 70, 45: 76, 60: 72, 75: 50, 90: 30. Re-measure the back quat before using any back number.
2. Back via on is worse than via off on the RIGHT hand only. The draw minimum drops on 17 families, all R, and no left-hand family drops by more than 0.005: qtrstaff -0.052 -> -0.080; double-blade and force-pike families -0.025 to -0.031 (`w_dblsbr_`, `w_dblswrd_`, `w_vbrdblswd_`, `w_forcepike_`); rifle `w_ionrfl_` -0.026 -> -0.042; grenades -0.014 -> -0.028. Mechanism (not confirmed): the via bump is outward, +x for the right hand, and carries the residual weapon across the spine toward the GUESS back mount (x -0.106, on the torso surface). A scratch test with the mount moved to x = 0 gives a worse regression on both hands and moves the static pose too, so the cause is not isolated. Treat it as a play-check item for the R-hand via row, not as a number.
3. Stow clips the back for every category, via off and on: min -0.111 to -0.127 (the minimum tick falls between 97 and 123 across families, right hand, via off). The landing window (last 240 ms of the carry) moves the weapon from the hand to the back mount in the hand frame while the arm is still on its way back. At the minimum (`w_blstrpstl_`, a pistol, tick 107) the weapon is about 37% of the way from the hand to the mount. The R-W4 trace (qtrstaff, tick 100) puts the weapon centre about 0.09 m from the head centre (head radius 0.105). The formula is the runtime's; the depth depends on the hinge path (not modelled per category), the missing wrist and the GUESS mount. Play check, not a number.
4. Hip: all pistols clear, draw and stow and static (min +0.0156). Heavy `w_hvrptbltr_` L clips at rest (static torso -0.020, identity GUESS).
5. Thigh: uninformative (not a zone). Draw via on clears most thigh cases because the bump is lateral: pistol -0.057 -> +0.014, rifle -0.054 -> +0.006.

## Asserts (test mode, HW32c)
- Existing checks, not edited: qtrstaff/back/R via off, draw or static min < 0 (holds: draw -0.052); via changes the draw for that case (holds; sign not asserted); pistols on hip (CatPistol, draw rows) draw and static min > 0 (holds, +0.0156; stow hip pistols are also clear, not asserted as in W6b); skipped == 0 (holds).
- New (29 checks in total): `--back-quat` normalizes and rejects zero, NaN, wrong count and trailing junk; `--mounts-json` takes the sample shape with cat as a name or an index, drops count 0, rejects truncated input, non-array, missing rel, fractional count, a count past 1e9 and zero rel, and matches bones ignoring case; `--dir stow` gives only stow rows, half of the `both` rows.

## Recommended defaults (W7 decisions, W6b model; HW32c notes in brackets)
- `reach_via_<cat>` = 0 for every category (unchanged). [HW32c: back via on is worse on the right hand (Findings 2), on a GUESS mount. Keep the W7 play-test row (rifle and qstaff via on) so the live game decides; the sweep does not pick the via.]
- `reach_extract_pct_back` = 0.20 and `reach_extract_pct_hip` = 0.10 (plan W6, unchanged). The sweep cannot discriminate shares: 29 of 39 families have exitSign 0, and only the 10 melee families (all exitSign -1) move.
- Apply the exit offset only when exitSign != 0. For exitSign 0 (guns, sabers, staffs) skip it; no mount-out direction until the shape survey gives signs.

## Limits
- Fixed in HW32c: draw only (stow and `--dir` added); extract offset applied after the solve (now before, and the solve clamps to reach); via not modelled (now the runtime's via quat, the hand-frame residual and the lateral bump).
- Back mount quat: GUESS until HW32b (see the top). Hip and thigh: identity GUESS in the sweep, while the runtime's `reachViaFor` uses the real hip and thigh mount quats, so the via quat differs there.
- Not modelled: per-category outT / outPole (reachHinge defaults for every category); topology (reachHinge runs for every mount; the runtime uses reachCarryTarget and reachPole for hip and thigh); no wrist or twist (the sweep's carried quat is the constant `qHand`, the runtime's comes from the wrist-turned attach node); the rest elbow and hand orientation are GUESSes; the elbow is not a clearance proxy, so `--pole-grip` changes no number; the lock Slide is reset for each slide (the runtime keeps the draw's hemisphere reference; affects the nlerp sign only); the carry reversal cross-fade (`carryShown`) is not modelled (one slide has no reversal); per-category slide lengths (heavy and qstaff use the melee / rifle 520 / 600 here) and grab shares (0.3 for all).
- Outside-shoulder via placement: only the lateral bump; the via quat is the runtime's, but the mount quat it turns on is a GUESS.
