## Findings
1. MAJOR Holster.cpp:741-747 (cache-hit refresh) + HolsterHand.h:34-42 (16-slot ring) : the hit path overwrites ent->left on every frame with `handLookup(...)==HandL`, in both directions. HandNone (ring evicted) is treated as right. Scenario: bone_test_left=1, area load attaches >16 weapons (party + NPCs; ring cap 16 vs 128-entry s_cache); party member's left gob is evicted, next frame ent->left flips true->false, seq=-1, weapon jumps to right-hand placement (overlaps right weapon). Same on first cache fill if the gob was already evicted. Fix: on hit only change when hand != HandNone (sticky), and raise HandRing::kCap to >=64 (or key the cache entry's hand at fill time and never downgrade).
2. MAJOR Holster.cpp:448 handAttach still starts with `if (!g_onAttach) return;` (probe && ch_attach). handRecord at :451 is therefore skipped with ch_attach=0, so g_handRing is empty and every gob resolves right. This is the exact defect named in r13c_c22_left_hand.md section 2.1 and was not fixed. Live ini has ch_attach=1 so it works only by accident; the shipped default holster.ini has ch_attach=0. Fix: call handRecord before the g_onAttach gate (gate only the logging), and make the HolsterPlace ring read independent of ch_attach (handMapLog :470 may stay gated).
3. MAJOR (PRB1 'refused nottarget' NOT addressed) Holster.cpp:1136 / holster.ini:26: lhand weapons are refused because applyBoneTest only repoints lhand when bone_test_left=1; live ini has no bone_test_left (=0), so lhand node is still the engine "lhand" literal, nodeIsTarget false, PrNotTarget at :782 for every left gob. kWorldKnowsHand cannot affect that (r13c section 2.2). Net live effect of 04f32af = none for left hand in world until bone_test_left=1 is set; no ini/default/doc change and no play-test row came with the commit. Fix: document/enable bone_test_left=1 in the live ini and add the PLAY_TEST_QUEUE row (HANDMAP L + PLACENODE target=1 + PLACE for the L gob); verify via kotor2_logs.py.
4. MINOR Holster.cpp:895 / :1010 (previewPlace, apiBeginEdit, edReseed now use effLeft==e.left): editor preview and Save now write/show mirrored left values, but in world they apply only with bone_test_left=1 and ch_attach=1 (findings 2,3). Review F1 invariant ("editor shows what world shows") breaks otherwise: user tunes l_ keys that nothing places. Fix: gate effLeft on g_boneLeft (or log once when left preview is used while !g_boneLeft).
5. MINOR Holster.cpp:440 ("Behaviour is unchanged (kWorldKnowsHand stays false)") and :728 ("left stays false (right-hand values)") are now false comments; manifest.toml description still says "log-only probe". Also the stale Gob-pointer risk is otherwise covered: s_cache key (node,gob,handle) plus per-frame handLookup, and handRecord updates in place on re-attach (no finding).
