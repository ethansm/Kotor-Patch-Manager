## Checked and OK
- EmbedGui call conventions match the dumps. 0x716FD0 is `__thiscall(obj; ushort type, char* ext, resref)` RET 12, so callCtor's order is right. 0x712F30 really returns bool (`+0x10 != 0`) and gives the budget back on failure. The "UNVERIFIED" note in EmbedGui.h:17 can be dropped.
- EmbedGui parse-fail path: on failure 0x717300 resets +0x40 to 0 and leaves +0x44..+0x70 null (the ctor zeroes 0x40..0x78), and +0x98 stays 0. The dtor 0x7171B0 non-parsed branch then calls `delete` only on nulls, after FreeResourceData zeroed +0x10/+0x18. No double free.
- EmbedGui success path: Close restores P+0x30 BEFORE Release. 0x7130B0 takes refcount 1 to 0 and adds the object to the LRU. The dtor then runs the +0x98=1 branch, 0x717630 to 0x713010, which is null-entry safe in vanilla. That is exactly one Release and one dtor. The second Close is a no-op because the handle is cleared first.
- The P+0x34 CONTROLS handle is safe to keep across the swap. It is {root struct index, "CONTROLS" label} (0x718760), resolved by label in whatever GFF P+0x30 points at. Every accessor (0x7178E0 / 0x717770 / 0x718890) bounds-checks the struct, label and field-index counts.
- HSE_VIEW ID -1: InitControl 0x40F620 writes the list only when `addToList && ID >= 0`, so -1 lists nothing and no vanilla slot is overwritten. appendToPanel then sets ID = index. 0x418DF0 stores the panel (not the GFF) at ctl+0x38, so no control keeps a pointer to the freed CResGFF.
- Hook sites: 0x8A16FE bytes `8B 8D 54 FF FF FF` = `MOV ECX,[EBP-0xAC]` followed by a rel32 CALL at 0x8A1704. The `[ebp-0xac]` param has precedents (level_up_override, portrait_slots). 0x40EC90 and 0x8A1930 prologues match. No span collision; letterbox probe hooks inside 0x40EC90 at a later site.
- OptTick hot path: one raw `[ECX]` compare (ECX is Draw's own `this`, always valid) before any other work. Logging is capped. appendToPanel runs at Draw entry, before Draw reads the list.
- Stale panel: OptBindView resets g_ed for every new ctor. OptTick and OptDestroy act only when P == g_ed.panel, and they dereference only P.
- SRWLOCK: no nested acquire on any path. edWrite calls edReseed and loadTune, neither of which locks. apiSetScope calls edReseed. apiBeginEdit takes the lock twice in sequence. No engine call runs under the lock (gobNames, mountPose and FindPart run outside it). previewPlace's early return releases via RAII.
- g_reloadBusy: edWrite CASes it around atomicWrite / accept / publishTune. maybeReload runs only with probe=1, and its seed `g_tuneW` stays consistent. apiGetEdit's lock-free read of g_tuneW touches only the boot-constant bootBoneIdx.
- Seq-lock: loadTuneIfChanged advances lastSeq only after a clean copy. The cache's `seq = -1` sentinel never equals a real sequence, so a torn read keeps a consistent (old) s_tune / s_seq pair.
- In-world behaviour with no model or body keys is unchanged. resolveFull with right hand and no model returns type, else global, rot/off, which equals resolveTune. Its bone is the type bone or 0. 0 goes to defaultBone = bootBoneIdx, the index of bone_name itself, so the `_stricmp(mountBone, g_boneName)` skip matches the old resolveBone == null (custom bone_name: boneNameOf(0) = null, also skipped).
- scopeKeys round trip: weapon, type and body keys pass tuneParseKey before emit. Values are capped like applyTuneKey (720 / 3 m). kScopeTextMax=160 covers the worst case, about 133 bytes. setKeys/removeKeys and findModel/findBody are case-insensitive, so a model name in mixed case does not create a duplicate key. Reset sets: weapon and type give 3 unsets; body gives `place_off_body_<b>` only. Left type writes to catL / `_l_` keys.
- The `hidden` flag follows the resolveFull precedence (modelL > mirrored modelR > typeL > typeR > global). It is recomputed on every BeginEdit, SetScope and Save reseed.
- API tables: K2Preview3dApi and K2HolsterApi initialisers match the struct order (the compiler type-checks them). The Preview3dApi static asserts match (12 slots). Manifests: holster `provides k2.holster@1`, preview-3d `kind=provider provides k2.preview3d@1`, holster-editor requires both (checker PASS). On GOG, preview-3d stays inert: k2addr kGog is zero, so createView refuses before any Steam-constant call.
- preview-3d free ordering: BeforeFree fires before the weapon slot is cleared, so WeaponGob still returns the Gob. destroyCreature fires it once, then weapons, helmet and creature are freed in that order. OptDestroy calls Destroy before the panel dtor, so the creature dies while its scene/view is alive.
