# u8: swarm_run budget-cap defect (recon, read-only)

## Mechanism
1. Admission: `budget.py:132-142` reserve refuses unless `spent + reserved + usd <= cap` (reserved = open reservations + ghost). `usd` = `--cap-call` per attempt (`swarm_run.py:506`).
2. Settlement: `budget.py:145-153` settle pops the token (`actual`) or moves it to ghost (`unknown`). Actual cost reaches `spent` only via the run record (written `swarm_run.py:566`, settled `:572`).
3. `spent` = `spent_total` (`swarm_run.py:389-405`): unknown or missing cost counts +cap_call; a record with cost_known not True counts cost + cap_call.
4. Refused at attempt 0: unit deferred, no record (`swarm_run.py:532-536`). Wave loop stops when all of a wave is deferred (`:609-612`) or when records-only spent >= cap_total at wave start (`:591-593`).
5. Per-call hard ceiling is `--max-budget-usd cap_call` (`swarm_run.py:231`). Only check on the pair: `cap_call <= cap_total` (`:296-297`). No `units x cap_call` check exists.

## Why only 2-3 units finished
- A call starts only while settled spend <= cap_total - cap_call = 0.05. At constant cost c, calls admitted = floor((cap_total - cap_call)/c) + 1: c=0.02 gives 3, c=0.03 gives 2, c=0.04 gives 2.
- Scratch model (`review/out/sim_u8.py`, pure arithmetic, no swarm code run): cap 0.10 / call 0.05 completes 2-3 of 10 for every cost set tested; cap 0.50 completes 10/10.
- `--parallel 2` does not reduce the count in the model (done count identical at p=1 and p=2 in all cases). The 2nd slot of a wave needs spent <= cap_total - 2*cap_call = 0, so it is deferred (`:607-613`) and re-queued. Concurrency wastes a slot and holds 2 x 0.05 in flight; it adds no new limit.

## Suggested fixes (ranked)
1. Size the cap (no code). Safe rule, one attempt per unit: cap_total >= N_pending x cap_call (N=10, 0.05 -> 0.50). Tight estimate at observed cost c: cap_total >= (N-1)*c + cap_call (N=10, c=0.03 -> 0.32). The real-engine ceiling `REAL_MAX_TOTAL_USD=1.00` (`:47`, `:292`) caps N at 20 for cap_call 0.05.
2. Preflight in `cmd_map` after the pending list (`:665`): warn, or refuse for `--engine real`, when cap_total < len(pending) x cap_call; print the cap needed. Natural home: `check_spend_flags` (`:282-297`).
3. Report deferred units as "budget deferred" (not "no record", `:786-787`) and print the needed cap at the stop messages (`:593`, `:610`, `:745`).
4. Already in place, do not change: release on settle (`budget.py:150`, `swarm_run.py:571-572`). The defect is sizing, not reservations held after settle.
5. Clamp `parallel` to floor(cap_total/cap_call) at `:589` (low value; removes dead slots only).
Resume: pending-only resume works (`:665` pending = not complete; complete units skipped `:524-526`; `--only` takes ids). Spend is cumulative per out dir (`spent_total` reads all runs, `cmd_spent` `:858-860`), so a rerun with the same cap_total is a no-op once spent > cap_total - cap_call (`:592-594`, `:609-612`). Raise cap_total to spent_so_far + pending x cap_call.

## Other edge cases
- Retries reserve again (`:532`). A rate-limited attempt settles `actual` (`:546`), but its cost is never parsed: the record is built once from the last attempt (`:559-562`). Undercount, usually near 0 for a 429. Retries also break the N x cap_call bound.
- Timeout: no retry (`:542`), cost unknown (`run_record.py:185-186`), counts +cap_call (`swarm_run.py:400`). One timeout at cap 0.05 uses half of cap_total 0.10.
- `merge_attempts` (`run_record.py:221-225`): one unknown attempt keeps cost_known False forever, so a unit that timed out and later passed counts cost + cap_call on every later run.
- Failed record write (`:569-572`): ghost lives in-run only; the reset at `:720` forgets it, and no record holds that spend.
- Brief double count: record written (`:566`) before settle (`:572`), so spend counts twice for a moment (conservative, can cause a spurious refusal on a concurrent retry).
- Probe is $0: `claude --version` (`bin/swarm_home_probe.py:118-120`) and `claude auth status` (`swarm_run.py:300`). Not in the budget, no model call.
