## What is already handled well
- Bundle hash is re-verified on every read (:193-210); tampering exits 2.
- Unit state comes only from runner status; incomplete findings are never opened (:381-397).
- Status parsing and unit_id match fail closed (:358-368, :414-415).
- Case ground truth is dropped at read (:161-171); the forbidden check runs before any unit is written (:655-660).

## Recommendations
1. Stage writes into a fresh out/ (archive the old one), runs probe before write_units, and stamps bundle_sha256 and a claim hash into each unit; report refuses mismatches.
2. Gate decision and exit code on verify completeness; add a pre-flight n_units*cap_call <= cap_total check in cmd_verify.
3. Require non-empty verdicts for null and verify; confirm schema.json minItems.
4. Replace the substring forbidden check with normalized, joined-text, whole-word matching, applied to every unit kind.
5. Add a per-run lock and a cumulative spend ledger; enforce cap_total <= 1.00 and yes_spend >= cap_total in this file, not only in swarm_run.
