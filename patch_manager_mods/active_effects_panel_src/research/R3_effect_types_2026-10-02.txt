==== R3b addendum 2026-10-02 (Mod 14 build 4 research R-a..R-d; Sonnet Explore, key items verified on disk by Opus) ====
R-a type ids (exe bytes, VERIFIED): 0x995f1c is uint32[0x77]: table[i] == i for i 0..0x54, table[i] == i+1 for i 0x55..0x75
 (id 0x55 skipped), table[0x76] = 0xffffffff. Each Effect* impl writes (ushort)table[idx] to eff+8 after ctor 005e4920. So
 R3's ids are right, but "DAT at 0x995f1c+4*type" holds only for types <= 0x54; for >= 0x56 the DAT is at +4*(type-1)
 (ForceShield 0x6b = DAT_009960c4 = index 0x6a, decomp 674210.c:40 VERIFIED; BlasterDeflectionInc 0x5c = DAT_00996088).
 EffectIcon: R3's 67bd70 is WRONG (a get-first/next-effect helper). The writer of type 0x43 is 0x698ba0
 Global::ExecuteCommandSetEffectIcon (DB name_map), i.e. script SetEffectIcon(effect, nIcon): copies the effect
 (005e4ac0), ints[0] = effecticon row.
 ints order confirmed from decomp: 0x02 [0]type [1]amount [2]limit (674020:59-61); 0x24 [0]ability [1]amount (671820:53-54);
 0x30 [0]modtype [1]amount [5]mask; 0x0d [0]bonus ENUM 1..10 (DAMAGE_BONUS_1..5, 1d4,1d6,1d8,1d10,2d6) [1]mask;
 0x1a [0]value [1]save 0..3 [2]save type; 0x37 [0]skill [1]value (invalid skill -> type 0 written); 0x10 [0]mask [1]pct<=100;
 0x0a [0]bonus [1]modtype. Unlabelled extra byte from [0xa1b4d0]+0x122 at ints[2]/[3] for 0x30,0x0d,0x37,0x0a,0x1a (ignore).
