// Hook 2 of 2: icon-retarget + wipe splice, inside
// CSWGuiMainInterface_PortraitIconRowDraw's (0x007457e0) per-icon loop,
// immediately before the native per-icon Draw(dt) virtual call.
// RAW-DISASM CONFIRMED -- 13-byte clean instruction-boundary window,
// comfortably >= 5 bytes needed for a JMP rel32 trampoline.
constexpr int PortraitIconRowDraw_RetargetSplice = 0x00745a84;
constexpr int PortraitIconRowDraw_RetargetSpliceLength = 13; // original bytes:
    // 8b 4d e0            MOV ECX,[EBP-0x20]      (icon widget ptr, reload)
    // 8b 11               MOV EDX,[ECX]           (vtable)
    // 8b 4d e0            MOV ECX,[EBP-0x20]      (icon widget ptr, this for the call)
    // 8b 42 38            MOV EAX,[EDX+0x38]      (vtbl slot 14 = Draw)
    // ff d0               CALL EAX                (the native per-icon Draw(dt))
// At this splice point, all needed values sit in stable EBP-relative
// stack slots (function prologue spills `this` at entry, confirmed via
// raw disasm) -- no register-pressure/reload-ordering risk:
//   slotPtr (this of the whole function)   = [EBP-0x4c]
//   loop index (which icon, 0..count-1)     = [EBP-0x18]
//   icon widget ptr (CSWGuiLabel*)          = [EBP-0x20]
//   whichRow (0=debuff/RED, nonzero=buff)   = [EBP+0x10]  -- only retarget if nonzero
//   dt                                      = [EBP+0x8]
// Hook body (skip_original_bytes=false, our code runs first): look up
// creaturePtr from the item-2 side-table keyed by slotPtr; walk
// creaturePtr's active-effect array (CSWSObject_ActiveEffectArrayPtr/
// Count) filtered to buff-type effects present in the Effect ID table;
// pick the entry at [loop index] (policy: iterate
// min(engineIconCount, ourFilteredActiveBuffCount), leave native glyph
// alone for any extra engine slots); if found, retarget the icon
// widget's CSWGuiLabel_EmbeddedBorderB (self+0xd8, "TEXT") FILL resource
// via CSWGuiBorder_LoadResource to that effect's spell-ID's resref, AND
// shrink that SAME embedded border's own width/height (self+0xd8+0xc /
// self+0xd8+0x10 -- see CSWGuiBorder_WidthOffset/HeightOffset below) by
// the wipe ratio. Then the original 13 bytes run, and the native Draw
// paints the retargeted, shrunk resource.

// Wipe mechanism RESOLVED: decompiling CSWGuiBorder::Draw (0x00415300)
// showed its VERY FIRST instruction reads self+0xc/self+0x10
// (width/height) directly and gates+drives its ENTIRE layout computation
// off them -- these are LIVE fields re-read every Draw call, not cached
// or passed in by the caller. So the wipe needs no second draw call and
// no FillCenter-parameter replication: just overwrite
// self+0xd8+0xc/self+0xd8+0x10 (the retargeted FILL border's own
// dimensions) with a shrunk value before the native Draw executes.
// Because only self+0xd8 ("TEXT"/fill) is touched, not self+0x60
// ("BORDER"/frame), the decorative frame stays full-size while only the
// icon image shrinks -- the intended "cooldown wipe over the icon" look.
constexpr int CSWGuiBorder_WidthOffset = 0xc;   // self-relative, STEAM-CONFIRMED (CSWGuiBorder::Draw
                                                 // guard clause + all downstream layout math)
constexpr int CSWGuiBorder_HeightOffset = 0x10; // self-relative, STEAM-CONFIRMED (same)

// Item 2 (2026-09-29, follow-on session): multi-slot creature resolution,
// driven by the all-party-members scope decision. RESOLVED by decompile:
// full disassembly of UpdatePortraits found local_1c (the DISPLAY slot
// index, 0..2, after the raw-position swap) and local_3c (creaturePtr)
// both live right before it computes the slot pointer
// `hudThis + 0x1f34 + local_1c*0xde4` -- the EXACT same slotPtr value
// PortraitIconRowDraw (0x007457e0) will receive as its own `this` later
// the same frame (single HUD instance, same constants). DESIGN DECISION:
// key the side-table by the RAW slotPtr address itself, never by a
// derived index -- there are only 4 possible slotPtr values per session
// (3 loop slots + 1 "extra"/mirror slot), so a 4-entry linear-scan table
// needs no reverse index math and no access to hudThis from
// PortraitIconRowDraw's own call frame. BONUS FINDING: the 4th "extra"
// portrait slot (PortraitExtraSlotOffset, the larger selected-character
// card, user-screenshot-confirmed bigger) is NOT an independent roster
// position -- decompile shows it's gated on `local_1c==0` and mirrors
// WHICHEVER creature occupies display slot 0. The snapshot hook must
// therefore write BOTH (normalSlotPtr, creaturePtr) and, only when
// local_1c==0, (extraSlotPtr, creaturePtr) using the SAME creaturePtr.

};
