Caveats on the smoke results:
- ActivationFix `run` has a "real foreground check" that **fails without a display** (I first ran with `DISPLAY=` empty: 2 failures; with `DISPLAY=:1` it passes). It opens a small window on the desktop.
- The smokes load the committed `.kpatch` DLLs, not a fresh build. File mtimes show the source `.cpp` newer than the `.kpatch` for ActivationFix, EquipIconFix, TextureMemoryRelease, DialogueLetterbox, LoadHangProbe, PerfLab (all `.cpp` touched 2026-10-02 12:16, probably the Common-extraction include edit; unverified) so the tests prove the shipped binaries, not necessarily current source. Same for Inventory3DViewport and CompanionAI (no smoke exists for them).
- `smoke.cpp`, `smoke_probe12.cpp`, `smoke_probe13.cpp`, `smoke_perflab.cpp` contain no pass/fail checks (always rc 0).
- `smoke_probe12` exited 0 and printed ok-looking lines, but asserts nothing.

Gaps in the test infrastructure itself:
- No single entry point. Host tests live in 3 places (`P/*_src/*_test.cpp`, `research/companion_levelup/tools/parity/`, Wine smokes in `P/perf_lab_src/harness/` + one in `dialogue_letterbox_fix_src/`). No CI/runner invokes them; KPM CI (`.github/workflows/ci.yml`) runs only xunit + the generator tests.
- Mods' `.cpp` include `"../_shared/SafeRead.h"` / `GuiKit.h`; in `P` the dir is `_shared_src/`. The level-up harness works around it with symlinks in `research/.../parity/stub/_shared/`. Any new host test of a `.cpp` needs the same trick (or move the logic into a header).
- Static byte checkers exist only for 3 mods (`check_inv3d/equip3d/chareffects_kpatch.py`) plus research-grade `mods678_research/check_windows.py`, `engine_bug_research/tools/check_engfix_windows.py` (historical outputs under `*_output_*.txt`). There is no generic "verify every shipped hook's original_bytes against the exe and every pair of hooks for overlap" gate in `scripts/`; the overlap script below (section 4) is a throwaway.

## 5. Cross-cutting findings and recommendations (ranked)

1. **No test entry point or CI for our mods.** Three test locations, one-off build lines in file headers; KPM CI never touches them. A `scripts/run_mod_tests.sh` that runs the 5 header tests, the parity suite, the Python checkers and (optionally, display-guarded) the Wine smokes would be the cheapest gain.
2. **Highest-value new tests** (complexity x crash risk x churn): BDH (`wipeRatio`, `computeColumns`, `newCounter`, shield geometry, shared dedup with CEP), ForcePowerHotbar (`refreshEffective/recomputeBound` slot assignment, `computeCharacterKey`, request ring, `saveDirFor`, `Config::Parse` edge cases), EquipCharPreview (`loadIni`, hit tests, `chooseIdle`, menu layout, emote phase machine), then CompanionAI handler glue via an arena harness and the shared `track` LRU template.
3. **Zero-cost fixes found by reading** (not verified at runtime): `slotDigit` OOB for slot -1 (hotbar :441); BDH `ent[256]` unclamped `snprintf` accumulation :771; hotbar `strncpy` without NUL :1023; PerfLab `g_stop` never set :735/:747; `config_roundtrip_test` uses `assert`; `smoke_*` print-only files should assert or be removed.
4. **Copy-paste helpers across mods** (a single `Common/CodePatch.h` with injectable `{query,protect,flush}` would make ~25 untested units testable on host in 5 mods): `configEnabled` (ActivationFix :52, EquipIconFix :73, TextureMemoryRelease :49, Robustness :91 variant), `writeCode` (4 files, different check coverage), `patchIat` (LoadHangProbe :345 == PerfLab :234), TX cave (TexMem :69-103 == PerfLab :463-475), `isItemAbility`/`currentTime` (BDH :68 == CEP :415), `parseMask`/`inWeaponRange` (RangedAI == `cai::`), game-window lookup differs per mod (hotbar :479-483 first visible >320x240; Inv3D :452-460 largest visible; GuiKit :327-335 largest >320x240). This matches `P/COMMON_EXTRACTION_PLAN.md`.
5. **WndProc subclassing** appears in CEP :254, EquipChar :361, Hotbar :766, Inv3D :498; all restore only "if still on top", none re-subclass on window recreation. Four mods stacked on one window: the restore order matters only at process exit. `VTableOverride` is used nowhere (raw `vt[n]` casts instead).
6. `IsBad*Ptr` (Wine page-fault storm risk, SafeRead exists for this): hotbar 17, Inv3D 10, EquipChar 14; CEP/BDH/SortFilter/LevelUp/CompanionAI/RangedAI/probes use SafeRead.
7. Raw engine address literals in .cpp: hotbar 35, LevelUp 35 (+ first-bytes signatures), PerfLab ~36, EquipChar 29, Inv3D 23, BDH 21, Robustness 20, CEP 18, LoadHangProbe 19, SortFilter 15, CompanionAI 13, ~15 more small mods. Only LevelUp, Robustness, TexMem, ActivationFix, EquipIconFix, Letterbox verify bytes at the address; the 6 big GUI/AI mods call engine functions by address with no signature check (they rely on the hooks.toml `original_bytes` of their own hook sites only).
8. Smoke tests exercise committed `.kpatch` binaries, several older than the current `.cpp` (section 2 caveat). A build+smoke gate would close that.
