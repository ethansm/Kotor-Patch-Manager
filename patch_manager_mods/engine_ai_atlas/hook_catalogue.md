# Engine-AI atlas: combined hook-site catalogue (KOTOR II Steam exe, sha 6A522E71)

Date: 2026-10-02. Static work only: nothing committed, knowledge DB not written, game folder read-only.

## Header

**Method.** One catalogue of every candidate detour window from: GATE_wave1.md s5, GATE_wave2.md s5 (gate-checked), `findings/AI1..AI8.md` section (f) (batch-only), and the 10 R1 "Hook designs" windows (`mods678_research/ai_research_2026-10-02/R1_engine_followups.md`). Gate verdicts override batches. Duplicates across sources were merged to one id (e.g. P2 = AI3-H1 = R1 CA-P2; RA-D = AI4-H08; PF = AI5-H1; EV = AI7-EV; SS1/SS2 = AI8-H1/H3). Every window was then run through a single copy of the project window checker with the engine-AI atlas catalogue as its table, together with all original M6/M7/M8/CA reference rows (the shipped companion-ai windows, so new-vs-shipped overlaps and the TOML cross-check keep working). The stolen bytes in the table are the bytes the checker read from the dump `.asm`; they were also asserted equal to the bytes quoted by the source batch. Function entry = the `.asm` whose range contains the address.

**Run outputs.**
- Checker (copy, logic unchanged; paths, OWNERS `"AT": (None, None)` and the WINDOWS table differ): `engine_ai_atlas/tools/check_atlas_windows.py`
- Checker output: `engine_ai_atlas/check_atlas_windows_output_2026-10-02.txt` -> **ALL OK** (134 windows = 101 AT + 33 original reference rows; 134 `[OK  ]`, 0 `[FAIL]`, 0 `[WARN]`; live snapshot TSV 120 hooks + live `patch_config.toml` 28 ids / 153 hooks, read-only; pairwise overlap: none; TOML cross-check: all hooks match)
- Original-bytes verification vs both exes: `engine_ai_atlas/verify_atlas_windows_2026-10-02.txt` -> **ALL MATCH** (134 windows, LAA `swkotor2.exe` and `swkotor2.exe.unpatched_vanilla` identical to the dump bytes)
- Supplementary (not part of the original checker, which only scans the containing function): `engine_ai_atlas/tools/check_atlas_supp.py` = whole-dump inbound-branch scan (every direct J*/CALL/JMP/LOOP row in every `.asm`) plus jump-table scan (tables read from the vanilla exe) for every AT window: 0 problems; no window within 12 B of a live hook.

**Counts.** 101 usable windows (24 gate-checked, 77 batch-only), 2 rejected entries (1 window + 1 design variant), 4 simple patches (3 requested + AI-REPTRANSPOSE) plus 1 data lever. Collision with an installed hook: only AI8-H10 `0x544210` (live perf-lab `PerfLabEffectApply`, same address and length), rejected.

**Conventions.** All windows are `type="detour"`; stolen bytes run after the handler (lesson 271), plain detours restore every register including EAX. "consumed -> X" = consumed-exit hook (EAX excluded from the restore; the checker verified EAX dead at resume and exit, ESP depth equal). "skip-only" = `skip_original_bytes=true`. Hot = every action/event/AIUpdate (keep the handler to a few compares and test party first); warm = per script call / per approach / per round; cold = rare. `[ebp-N]` are frame locals (the sources gave `[ebp+0xffffffNN]`). Status "gate-checked" = listed in a GATE s5 table; "batch-only" = only the batch's own scan (re-validated by the checker run, but no Opus re-read of the callers).

**Reference rows.** The 33 original rows (M6/M7/M8 and the shipped/unshipped companion-ai windows incl. `CA FM3 sentinel probe (NOT SHIPPED)` `0x51DBE7`) are only there for overlap detection and are not counted above.

**Not new windows (do not duplicate):** AI1-H1 `0x55AB30` and AI1-H2 `0x55AC26` are the installed perf-lab hooks (`PerfLabPathEnter`, `PerfLabPathResult`); `0x668FD0` and `0x7022A0` are perf-lab hooked too (AI7-CMD-OUT `0x66900A` is 58 B past the `0x668FD0` entry hook): do not stack a second detour, extend `PerfLabExecCmd`; AI7-RS `0x6FD8D0` is the better place for slot attribution (the `[esp]` return address identifies the engine site) and is 8.6 KB from perf-lab `0x6FFA76`. AI8-H10 `0x544210` = perf-lab `PerfLabEffectApply`: reuse it.

**Hard rule.** `0x51DBE1` (FM3s, 6 B) ends exactly where the retired hot probe `0x51DBE7` starts: never ship both. `0x51DD33` (FM3e) is safe only because stolen bytes run after the handler (the stolen SUB makes the CF for the later SBB).

**Variants also validated in scratch (same address, one at a time):** AI3-H3 `0x579021`, AI3-H4 `0x57883F` and AI4-H04 `0x51D842` also pass as skip-only (replace) windows; FM2 `0x5C2438` also passes as a plain (non-consumed) detour and AI2-F2 `0x58F3A1` also as a plain detour (table lists the designed form: consumed, resp. skip-only).
