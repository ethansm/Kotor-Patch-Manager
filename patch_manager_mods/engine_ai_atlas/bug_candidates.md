# Engine-AI atlas: bug candidates (2026-10-02)

Every AI bug or hazard found by the review (2026-10-01), R1 follow-ups (2026-10-02) and the atlas pages/gates, in one ranked list. Static analysis only; nothing here was run in game. Evidence standard = docs 15/16 (`15_engine_bug_candidates_research_plan.md` s2, `16_candidate_register.md`): a lead is a candidate only when it is **located** (address + asm excerpt), **mechanism confirmed** statically (read from the K2 code), **user-visible** (reproduced, or provably reachable with our content; `reach` = reachable by code, not reproduced; `N` = not shown), **patchable** (a hook window with no relative branch in the stolen bytes and no overlap with live hooks, see [hook_catalogue.md](hook_catalogue.md)), and it is **killed** if the K2 code differs, the path is unreachable here, or the fix would need more than ~3 hooks for a cosmetic gain. Pages: [README.md](README.md) and AI1..AI8; verdicts: GATE_wave1/2.md.

**Ranking.** Impact (user-visible effect here, H/M/L) x safety of the fix (fix risk L=3, M=2, H=1). Group A = open with a fix path, ranked; group B = shipped in `companion_ai_src` and **live since 2026-10-01 23:36** (0.1.0 hooks.toml and `companion_ai.ini` defaults; play-test state is the lead's, see memory); group C = documented, narrowed or no fix proposed (impact shown, no rank). Fix kinds: engine hook (KPM detour), engine simple patch (bytes/data), script, data. Owner `user` = the fix changes balance or enemy behaviour. Kill thresholds (counts per second/minute, n_L) are proposals for the probe runs, not measured values. Tie-break at score 6 (REVIEW_synthesis 2026-10-02): interacts with a live hook / every fight first, so AI-A1RETARGET, AI-MEDPAC-FORCECLASS, AI-E4KEY (blocks the E4 build), AI-SPOTSIGN (user decision, stealth only). AI-AIQ impact is `?` until perf-lab measures it.

**Correction (REVIEW_synthesis 2026-10-02, Opus review).** Applied here: E1 (AI-P2: the 200 ms cadence goes to the IsPC creature, not the controlled one), E2 (`0x51C8F0` = controlled leader, section 4 party test), E5 (the Exile always, not a 'Jedi-only PC'), E6 (AI-EXIT5M mitigated live by FM4 mode 1), section 3 fix/drop decisions (AI-SEENSTAYS dropped: design behaviour, now documented-only in section 4), statuses of group B (live). Sections 4a (shipped-hook impact) and 4b (pending track C/D design changes) are new. Review: [REVIEW_synthesis.md](REVIEW_synthesis.md).

## 4b. Pending track C/D design changes (REVIEW_synthesis section 4)
- **E4 (stuck move).** GetCurrentAction reports the last reportable node of the head group: engine approach 3 (0xC group) or 39 (0x3F group), follow walk 38, MOVETOPOINT only for script move chains (lesson 325). Widening the key to {3,39} is wrong (a ranged companion shooting from one spot reports 3 and never moves). Design: (a) keep the MOVETOPOINT branch for script moves (kite, E3/E11 stand-off); (b) add 38 only when the member is farther than the follow range from the leader (e.g. > 8 m) and in the same 2 m cell for N heartbeats; (c) leave engine approaches (3/39) to the DLL FM2 fail-fast. Probes GCA and RAR confirm 3/39/38 before the build.
- **FM2 fail-fast.** Key on the 0x11 re-approach at `0x5BC5F4` per (creature, target): N (2-3) re-approaches within 12 s with no progress (3D distance shrank < 0.5 m). Act there, not only at the FAIL leg: (1) `0x53F6A0(cr, node group)` deletes the queued 0xC/0x13 of the chain (pattern `005868ac..005868b4`); (2) a **consumed exit to `0x5BC6EF`** (`MOV EAX,[0x9944b8]`, the 0x11 "done" return; EAX dead; no pending pushes at either end) ends the 0x11 without re-queuing [wait, move, 0x11]. A creature that creeps a few centimetres can loop on partial legs (result 2) with no FAIL leg, which `0x5C2438` alone never sees; `0x5C2438` (consumed -> `0x5C24C8`) stays optional, to skip the 2-4 s wait. Validate the consumed variant of `0x5BC5F4` with `check_windows.py` (EAX and stack) before the fix round. Probes FM2R/FM2F/FM2C decide which phase dominates. R1 open question 2 (target exclusion, so k_ai_master does not re-pick the same target) is still open.
- **E9 (shout reach).** A SILENT_TALK shout (35 m) reaches a listener only if it has `+0x1C0` listening and pattern 15, its perception entry for the shouter has HEARD, and it SEES the shouter or is < 10 m away; no faction filter (`0054734c..005473a7`); a stale id aborts silently (LOW). Companion perception refreshes only every 4 s (P2), so a newly arrived ally may not be HEARD yet; shouts repeat about every 3 s, so delivery is retried, not lost. R2's E9 design (non-party friendly shouter, seen live enemy within 25/15 m, member within 15 m of the leader, idle) stays valid, but **build it only after probe RS shows `S7 pat=15` deliveries from non-party speakers to party members in an allied fight**; if there are none, E9 is moot without a perception change. Keep the `GetIsFriend(oShouter)` gate (enemies in 35 m receive the same shout).
- **M8 (swap counter).** M8b decrements local 8 once per k_ai_master 2003 (EndRound). 2003 has three engine sources: EndCombatRound once per round (skipped when a move heads the queue, F2: frequent for a kiting stance-16 member), the 3 s fallback in combat without a round, and SetState removal (ungated) when a stun-like state ends. "About two round ends" means about two **slot-6 runs** (about 3 s apart), shortened by a stun ending and lengthened by F2 skips that the fallback covers. Design stays; the marker text should say "slot-6 run"; the RS probe (S6A/S6B/S6C per creature) measures the real cadence. The engine's zeroing of local 8 at combat exit (`0x57A5C1`, party) still bounds it.
- **a1_retarget_strict (2D metric).** In `CompanionAiA1Gate`, after `0x57C990` returns a candidate: compute the 2D centre dist2 from attacker `+0x94` to candidate `+0x94` (x, y only); accept only if <= (mx+0.1)^2 with mx = `[ebp-0x2C]` (the attack's own bound, which already contains the melee radii, so no false rejects); otherwise treat the candidate as INVALID (end). `a1_retarget_strict=0` = log `STRICT ... would-reject` only (probe A1X); turn it on if the play logs show any would-reject followed by `H1 end52c!=0`. A second exclude is impossible (one exclude slot). ranged-ai E-H2 has the same mismatch but its pick is vanilla code past the window: accept it (stance 16 only, log-visible) or add a post-pick window later.
- **Medpac rule (Force-class).** R4's party guard `GetCreatureHasTalent(tSpe11_05)` is FALSE for every class list without a non-Force slot (HasTalent `0x6B8840` sends Force slots only to `0x6BD9C0 && 0x6B8F40`; `006b89ce CALL 0x6f2a30` / `006b89d8 JZ` skips the item scan `0x6C0330`): Kreia (4), Visas (5) and **always the Exile** (E5). Design: party branch = `GetIsTalentValid(tSpe11_05) && GN_PartyMedpacStock() >= 1`, never HasTalent. `ActionUseTalentOnObject` reaches UseItem (`0x57D8B0` -> `0x57B4C0`) without HasTalent but tests `+0xEC` (commandable, `0057d8e3`), so keep the existing `GetCommandable()` guard. `medpac_guard_check` must accept the second, party-gated `tSpe11_05` (lesson 280).
