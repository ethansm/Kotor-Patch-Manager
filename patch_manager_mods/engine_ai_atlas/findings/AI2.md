## Summary (most mod-relevant first)
1. The round is a SEPARATE heap object (0xB2C bytes, `new(0xB2C)` at 0x562244, stored at cr+0x10DC at 0x562290), so every `+0xA84..+0xB28` offset in the review is round-relative. `+0xA9C` is the REMAINING round budget (3000 at start, shrunk by each attack's animation time with a proportional rescale of `+0xA94`), not a constant; one AIActionPhysicalAttacks call resolves ALL attacks of the round (loop in ResolveMeleeAttack 0x6DEA90) and returns 2; the damage/OnAttacked events are posted later from `UpdateCombatRoundTimer 0x571030` (SignalDamage's only callers 0x5711A8/0x5711F1), when the pause timer `+0xAB0` runs out.
2. The slot-6 (EndRound) script has exactly THREE engine sites: EndCombatRound 0x58F50F (gated by 7 conditions, quoted), AIUpdate 3 s fallback 0x569A67, and a NEW one, `OnRemoveSetStateInternal 0x59E860` at 0x59E904 (effect type 9 removal). SetCombatState(0)/death end the round with bRunScript=0 (no script).
3. Engine-side target choice: ONLY the player-controlled leader gets `CreateNewAttackActions` (EndCombatRound 0x58F5D1, gate `[ebp-0x24]`), plus the IsPC-only LOS-blocked retarget in AIActionPhysicalAttacks (0x6D7D24, needs the creature to be at the same position on two consecutive blocked checks). Companions/enemies are script-only (slot 6 -> ActionAttack -> AddAttackActions). Confirms the review; no other engine retarget exists.
4. Range semantics (one table in Q2): attack/approach test = 2D CENTRE distance^2 (z zeroed at 0x6D7E4A) vs (MaxAttackRange+0.1)^2; melee MaxAttackRange = 1.6 + HITRADIUS(att) + HITRADIUS(tgt) + 0.5 (appearance.2da column HITRADIUS, NOT PERSPACE); ranged = baseitems `+0x34` (0 -> 30.0) + stat bonus; retarget (0x57C990) = 3D distance - both pathinfo radii (`+0x380 -> +8`): the a1_retarget_strict mismatch is CONFIRMED with exact asm. The A1 retarget radius is `MaxAttackRange(self,0,1)`: 20.0 for a ranged weapon, ~2.1+2*HITRADIUS for a melee weapon.
5. New small facts: `+0xAB8` is a once-per-round action counter that makes AIActionCombat refuse a second action (0x6D96CC CMP ..,1 / JGE); `+0xA90` = cutscene-attack flag (only AddCutsceneAttackAction sets action `+0x74`=1) and suppresses slot 6 + CreateNewAttackActions; base attacks per round come from stub `0x6A7170` (returns constant 1); hit roll = d20 via `CSWRules::RollDice(1,20)` (0x6E0BD9), nat 1 auto-miss, nat 20 auto-hit, crit threat+confirm; OnDamaged (slot 4) is NOT run for the party leader (0x5959E0 @0x59666E `CALL 0x5FE3B0`).

### Q1. CSWSCombatRound field table: CONFIRMED, separate object, round-relative offsets
- Allocation: `0056223f PUSH 0xb2c / 00562244 CALL 0x00919723 / 00562263 CALL 0x0058e230 / 00562290 MOV dword ptr [EDX + 0x10dc],EAX` (creature ctor 0x561F30). Size 0xB2C. Owner back-pointer `+0xB04` (`0058e47b` ctor store, 117 readers).
- Layout: `+0x004` = 7 CSWSCombatAttackData slots of 0x17C (`PUSH 0x7 / PUSH 0x17c`, GetAttack 0x5908C0 = `round+4+i*0x17C`; ClearAllAttacks loops i<5, so only 5 are used); `+0xA68` and `+0xA74` are two 12-byte id arrays (ptr,count,alloc) built by `CALL 0x5933B0` (`0058e281 ADD ECX,0xa68`, `0058e292 ADD ECX,0xa74`); `+0xB00` is an action list head (`new(4)` + 0x722870, ctor 0x58E32F); the ctor tail does `_memset(param_1+1,0,0xa64)` so +0x04..+0xA68 start zero. SaveCombatRound 0x592310 gives 30 scalar field names and 4 list names (e.g. `FUN_007199d0(param_3,*(undefined1 *)(param_1 + 0xa84),"RoundStarted")`, `...(param_1 + 0xab4),"InfinitePause")`, `...(param_1 + 0xaa0),"OverlapAmount")`); the other fields are named from behaviour. Action-list nodes (`+0xB00`) are CSWSCombatRoundAction objects of 0x88 bytes (`new(0x88)` + ctor 0x58C7D0 in 0x590A50).
- Everything the review lists (`+0xA84 active ... +0xB20 round target`) is round-relative: CONFIRMED. Table in (e).
- Dead field: `+0xA98` is written (0x6E051A in ResolveMeleeAnimations, 0x6DC338) but has no reader in the dump (field_census: R none).

Mismatch for a1_retarget_strict (CONFIRMED, both quotes): retarget accepts by 3D `d - r_a - r_t < range` (`0057cdcf FCOMPP / 0057cdd6 JNZ`, radii = `pathinfo(+0x380)+8` of both, `0057cd80`, `0057cdc0`); the attack then tests the 2D centre `dist2 <= (max+0.1)^2` (`006d82c8 TEST AH,0x41 / JZ 0x6d8360`) and `InitializeNewAttackTarget` sets `+0x52C=1` (`006dacdb`), so the next pass ends via `006d83ea..006d840c` (EndAttackAction(1), return 3). The picker's `range` is `MaxAttackRange(SELF,0,1)` (row 9: 20.0 for a ranged weapon, ~1.6+2*HR(self)+0.5 for a melee weapon), whereas the attack test uses `MaxAttackRange(TARGET, duel, 0)+0.1`. A strict check therefore has to recompute the attack's own bound for the candidate (2D centre dist2 vs `(MaxAttackRange(cand,duel,0)+0.1)^2`), as R1 proposed; the 3D-minus-radii acceptance can exceed it by about `r_a + r_t + |dz|`-dependent amounts (pathinfo radius vs HITRADIUS relation not resolved, (d)3).
