# AI6 Faction, reputation and hostility (wave 2, 2026-10-02)

## Summary (5 lines)
1. Reputation is a pure matrix lookup (no per-creature personal list, no cache): `0x5E13C0 CSWSObject::GetReputation` = `[0xA0F6E0]` debug override (default -1) > AOE->creator swap > same id = 100 > party-flag (`creature+0x11AC`) remap in `0x5D0D00` (both flagged = 100, a flagged side's faction becomes 0) > `CFactionManager` matrix `data[row*N + col - 1]` (`0x664580`), clamp 0..100; enemy = rep <= 10, friend = rep >= 90 (`0x67C430`, `0x5E1680`). Flips (AddMember `0x6D3330`) write `stats+0x78` only; no cache to invalidate.
2. Shout path (E9) CONFIRMED end to end: `SpeakString` `0x693860` maps volume -> internal type (TALK 1, WHISPER 3, SHOUT 2, SILENT_TALK 0xD, SILENT_SHOUT 0xE) -> `0x63A5B0` -> listener broadcast `0x547100`(speaker, &string, radius, bRequireSeen): radii TALK 1000, WHISPER 3, SHOUT 250, SILENT_TALK 35 (+bRequireSeen), SILENT_SHOUT 1000. There is NO faction filter in the engine; a creature listener must have the speaker in its perception list with the HEARD bit (and for SILENT_TALK: SEEN or within 10 m); delivery = event 10 sub-type 7 posted delay 0, handled at `0x57074F`: `+0x1A0`=speaker, `+0x1BC`=pattern number, then OnDialogue slot 7 (default script `k_hen_dialogue01`) on the listener.
3. Two silent-failure paths in the shout loop: the start index comes from `0x522AF0` whose return is ignored (`local_20 = -1` stays when the X-bisection meets an unresolvable id, so NO listener is reached, `0x5471B5`), and any unresolvable id inside the scan aborts the rest of the scan (`0x547203 JNZ 0x5475E8`).
4. Flip propagation: scripts (`ChangeFaction` / `ChangeToStandardFaction`, `0x66F0A0`) do AddMember only (no perception or combat flush); the faction-modifier effect (type 115, `0x5951A0`/`0x5953E0`) and `ChangeFactionByFaction` (`0x696E10`) additionally ClearAllActions(1) and `ClearVisibleList 0x5D1510` + `UpdatePerception(0) 0x5D0F30`; Surrender (`0x5D51A0`) cancels combat of every hostile creature within 250 m (`CancelCombat 0x586750`) and joins the "neutral" faction. `ClearHostileActionsVersus 0x5867E0` only removes queued attack / cast / item-cast actions (types 0xC, 0xF, 0x2E).
5. New bug: `AdjustReputation` (`0x5D0DF0`) reads cell (row = target faction, col = own faction) but writes the transposed cell (`005d0e4b CALL 0x664580` vs `005d0e97 CALL 0x6644D0`): CONFIRMED by push order. DB name fixes: `0x67C430` is GetIsEnemy/Friend/Neutral (not GetEmotions), `0x683740` is GetListenPatternNumber (not GetMetaMagicFeat).

Conventions: ROOT = `ghidra_dumps/steam_6a522e71`; "decomp" = `decomp/<bb>/<addr>.c/.asm`; constants read from `backups/vanilla_clean/swkotor2.exe` through the PE section table (image base 0x400000; a throwaway script mapped each VA to its raw offset; values are quoted). Wave-1 facts used, not re-derived: perception entry bits (AI3: bit0 SEEN, bit1 HEARD), event 10 = `EVENT_SIGNAL_EVENT` payload word = script-event type (AI3), `0x522AF0` abort semantics (AI3 Q5), action table `0x5D7038` (AI4: type 0xC=`0x6D7390` attack, 0xF cast, 0x2E item-cast, 0x41=`0x5D29B0`).

## (b) Findings

### Q1. Faction table layout: CONFIRMED
`CFactionManager` = `new(0x28)` (`005363f7 PUSH 0x28 / 00536411 CALL 0x664280`), stored at `[[[0xA1B4A4]+8]+4]+0x10054` (`005d0df9..005d0e10`: `MOV EAX,[0x00a1b4a4]; MOV ECX,[EAX+8]; MOV EAX,[EDX+4]; MOV EDX,[ECX+0x10054]`).
- `+0x00..+0x18` seven standard-faction pointers filled by label (`0x664A00`): +0 neutral, +4 insane, +8 friendly_2, +0xC friendly_1, +0x10 hostile_1, +0x14 hostile_2, +0x18 player (strings `0x998B84/0x998B7C/0x998B8C/0x998BA4/0x998BB0/0x998B98/0x998BBC`, read from the exe).
- `+0x1C` N = number of NPC factions (excludes id 0). `+0x20` -> `CExoArrayList<int>` (12 B: `{data, size, capacity}`, `0x84A640`/`0x83EA60`, doubling from 16) holding the matrix with `(N+1)*N` cells (`00664b9d`/`00664bcd PUSH 0x64` loop `(iVar1+1)*iVar2`), default 100. `+0x24` -> `CExoArrayList<CSWSFaction*>`; faction id = index = repute.2da row (the CSWSFaction ctor appends itself, `006d3283 MOV [ECX+0xC],EAX` with `EAX = count-1`).
- Storage rule (asm): `Get(a,b) = data[b*N + a - 1]`, `Set(row,col,v) = data[row*N + col - 1]`, so cell `(row r, col c)` with `c >= 1`. Value orientation: `rep(source S -> target T) = M[row = faction(T)][col = faction(S)]` (see Q2 trace). Faction 0 (PC) is "invalid" for `GetIsNPCFaction` and is addressed through row 0 (both orders of a (0,f) pair resolve to cell `M[0][f]` via the swap at `006645ba..006645ea`), so the matrix is symmetric for PC pairs.
- 2DA load (`0x664AE0`): rows `0..R` (R+1 iterations, the last is out of range), cols `0..C-1`, `FUN_0071b8b0(row,col,&val)`, `Set(row, col, val)`; `Set` rejects `col < 1` (`006644d9 CMP [EBP+0xC],1 / 006644dd JL`), so 2DA column 0 is never read as a cell. Values clamped 0..100 (`0066450b..00664520`). Return value of `LoadReputations` is always 0 (last iteration fails) but the only caller ignores it (`0055a375 CALL 0x664ae0` then `JMP 0x55a387`). Whether column 0 is the LABEL text column or a PLAYER column is SPECULATIVE (repute.2da is not on disk; only BIF resource). Consequence if col 0 = LABEL: 2DA column `c` <-> faction id `c`.
- `CSWSFaction` = `new(0x24)`: `+0` data (member object ids), `+4` count, `+8` capacity (`FUN_006d4840` loops `*param_1 + local_c*4` to `param_1[1]`), `+0xC` id, `+0x10` parent id (-1 for 2DA rows: `*(local_30 + 0x10) = 0xffffffff` in `0x664680`; save key "FactionParentID"), `+0x14` GetFirst/NextFactionMember cursor (`0x6D4AF0`: `param_1[5] = local_c + 1`), `+0x18` CExoString name (8 B), `+0x20` "FactionGlobal" flag (1 default, `0x6D4BF0`).
- Creature side: `creature+0x1198` = stats; `stats+0x78` = current faction id (written only by AddMember `006d33c8`, personal ctor `0x6D30F0`, and non-creature types by `ChangeFaction`); `stats+0x7C` = template faction written in PostProcess (`00576a13`); `stats+0x6C != 0` = PC-controlled stats (`ChangeFaction`, `Surrender` refuse it). Non-creature faction fields: placeable `+0x27C` (vt+0x48, type 9 `DAT_00994478`), trigger `+0x2F8` (vt+0x40, type 7), door `+0x2F8` (vt+0x18, type 10), encounter `+0x26C` (vt+0x5C; ctor pushes type 0xD, `00622cbe PUSH 0xd`). AOE `+0x288` = creator (writer `0x62EE30` arg1, `0062ee3f MOV [EAX+0x288],ECX`).
- Persist: `SaveReputations` writes only cells `!= 100` as (FactionID1 = row, FactionID2 = col, FactionRep) (`00664e40`); `LoadFactions(1)` after a save load only creates the 2DA rows beyond the saved count (`local_14 = *(...+4)` when `param_2 != 0`).
- Startup: `0x5582F0` (`0055a35b..0055a382`): `if (rules 2DA ptr) { if (LoadFactions(0)) LoadReputations(); else CreateDefaultFactions(); }`. SPECULATIVE inconsistency: `CreateDefaultFactions` creates in slot order player, hostile_1, hostile_2, friendly_1, friendly_2, neutral, insane (ids 0..6) while nwscript uses FRIENDLY_1 = 2, HOSTILE_2 = 3: harmless unless the 2DA is missing.

### Q2. Personal overrides and precedence: CONFIRMED (no personal reputation list exists)
There is no per-creature reputation storage anywhere: the only writers of the matrix are `0x6644D0` (callers: LoadReputations, LoadReputationsFromSaveGame, `0x5D0DF0` AdjustReputation); `AdjustReputation` is reached only from the script command `0x66D1B0`. "Personal" behaviour is faction membership (`stats+0x78`), the party flag, and effect type 115.
Precedence in `0x5E13C0` (this = judged object T, arg1 = source id S, arg2 unused-0; result = how S feels about T):
1. `005e13c9 833de0f6a000ff CMP dword ptr [0x00a0f6e0],-0x1` / `005e13d2 MOV EAX,[0x00a0f6e0]`: a global debug override returned UNCLAMPED. Initial value -1 in the exe (`.data` raw read). No writer anywhere in the dump (grep over all `.asm`). A DLL that sets it forces every GetReputation / GetIsEnemy / perception hostility test to that value.
2. Lookup failures (`0x51C080`/`0x53DFB0`, no faction manager `+0x10054`) return 50 (`005e1413 MOV EAX,0x32`).
3. T is an AOE (`005e1457 MOVZX EDX,byte [ECX+8] ... CMP EDX,EAX` with `[0x99447A]` = 11): replaced by its creator (`005e1483 MOV EDX,[ECX+0x288]` -> `[EBP+8]`). S/this is an AOE (`vt+0x50` != 0, `005e1497..005e149b`): recursion with `this` = creator (`005e150a CALL 0x5E13C0`; the two pushed args are reused by the recursive call, `vt+0x10` is a no-arg AsSWSObject).
4. Either faction lookup fails -> 50 (`005e155b`); same object id -> 100 (`005e1576 MOV EAX,0x64` after `005e1574 JNZ`).
5. S faction invalid (`0x664650` = 0, i.e. 0/PC) and T faction valid: roles swapped (`005e15a1..005e15bf`), so (PC, f) pairs are symmetric.
6. T is a creature (`vt+0x30`, `005e15d1`): `0x5D0D00(S id, S faction)`: both `creature+0x11AC != 0` -> 100 (`005d0d52..005d0d70`); else a flagged side's faction is replaced by 0 (`005d0d8b MOV [EBP-4],0` for T, `005d0daa MOV [EBP-0xC],0` for S) then `Get(S faction, T faction)` (`005d0ddd CALL 0x664580`; pushes `[ebp-4]` then `[ebp-0xC]`, so arg1 = S, arg2 = T).
7. T is a placeable / encounter / door-class (`vt+0x48 / 0x5C / 0x18 / 0x40`, `005e1603..005e163d`): direct matrix lookup `005e164a CALL 0x664580` with NO party remap. Any other class falls through with 0 (hostile).
8. Clamp 0..100 (`005e1656..005e166e`); not applied to override / 50 / 100 early returns.
`+0x11AC` here is read as a bare flag by `0x5D0D00` (`005d0d49 MOV EAX,[EDX+0x11ac]`); the semantics of the flag and the correct "in the active party" test are AI5's question. Operational consequence for AI6: a companion with `+0x11AC == 0` is judged by its OWN faction row (not the PC row) and vs another flagged party member returns the plain matrix value, not 100.
Thresholds (CONFIRMED asm): enemy `rep <= 10` (`0067c564 CMP EAX,0xa / SETLE`), friend `rep >= 90` (`0067c5a3 CMP EAX,0x5a / SETGE`), neutral 11..89 (`0067c5bf/c5c5`). GetIsEnemy additionally requires, for a PLACEABLE target (`vt+0x48`), `placeable+0x398 != 0` (`0067c545 MOV EDX,[ECX+0x398]`; census writer `0x5F2C1B`, client reader `CSWCPlaceable::IsHostile 0x8411A9`): plain placeables are never enemies. Argument order: command pops oTarget first, then oSource (`0067c44e..0067c492`); `this` = oTarget's game object, arg = oSource (`0067c55d` ECX = `[EBP-0x1C]`), i.e. GetIsEnemy(T, S) = "S considers T an enemy". GetReputation(src, tgt) (cmd 208) pops source first and calls `tgt.GetReputation(src)` (`00687e91`).

### Q4. Flip propagation and cost: CONFIRMED
- No cache: hostility is recomputed at every consumer (Q2 list), so any flip is seen by the next consumer call; nothing to invalidate.
- AddMember `0x6D3330(objId, bSuppressMsg)`: already member -> return (`006d336f..006d3378`); old faction `RemoveMember 0x6D3530`; unless `bSuppressMsg`, `0x6D37D0` sends a client update to every member (loop `FUN_006471d0`, O(members)); `0x5210A0` appends id; `006d33c8 MOV [EDX+0x78],EAX`; then a client message for the object.
