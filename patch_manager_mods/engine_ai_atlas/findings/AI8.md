# AI8 Effects and AoE as they gate AI (wave 2), 2026-10-02

Summary (5 lines)
1. `+0xFF5` (SetState id) and `+0xFF4` (sight bits) do NOT gate `AIUpdate 0x569320` or `RunActions 0x5D56B0` directly (field_census --all: no hit in either). The real gates live in the action handlers and the `Add*Actions` entries: `+0x1114` = 16-bit allowed-action mask (bit 2 legs, 4+0x80 melee, 8 spells, 0x40 awake-flag mirrored to the client; AND-ed by type 0x17 effects, init 0xFFFF, death 0) and `+0xEC` = commandable flag (`ClearAllActions` only works when it is 1; script `Action*` commands are dropped when it is 0).
2. SetState map complete: 1 confused, 2 frightened, 3 droid stun, 4 stunned, 5 paralyzed, 6 sleep, 7 choke, 8 horrified, 9 force-push stagger, 0xA whirlwind, 0xD force jump, 0xE knockdown, 0xF crush, 0x10 droid confused, 0x12 mind trick, 0x13 droid scramble; 0xB, 0xC, 0x11 have no creator in the exe. A higher id replaces a lower one (`CMP [EBP-0x1C],ECX / JLE` at 0x59D957); only 1, 2, 0xB run a per-heartbeat state script (`StateScripts.2da` rows 3, 2, 1 via the switch at 0x56BB87); states 1, 3-10, 0xE-0x13 run slot 6 (OnEndRound) when the internal type-9 effect is removed.
3. `GetHasSpellEffect 0x67E670` = linear scan of the object's effect list (`+0x148/+0x14C`) for `effect+0x1C == nSpell`; `+0x1C` is stamped by `CGameEffect::SetCreator 0x5E5EA0` from the creator creature's `+0xFF8`, which `EventHandler 0x56EFD0` sets to the cast spell id around the spell script. No creator/duration filter; every member that received a copy shows it; Battle Meditation skips droids; effects made outside a spell script carry -1 and never match.
4. AoE objects: script table at `+0x2A0` = [heartbeat, user, enter, exit]; heartbeat = `>= 6000` ms stamp test inside `0x62C360` (AI level 0 object, first beat only primes the stamp); enter/exit = event 10 payload 0xC/0xD (delta 0), posted by `0x5C2930` from every walker step (`0x5C25E0` -> `InSubAreas 0x54D180`, O(sub-areas in the area) per step) and by `0x62E320` for a following aura.
5. EFFOVF CONFIRMED: `ApplyEffect 0x544210` has no dedup or cap; `LoadGameEffect 0x5E5510` loop `0x5E58F3..0x5E5945` is bounded by the GFF IntList length, not by `NumIntegers` (`+0x30`); reach = save load (`CSWSObject::LoadEffectList`) and `LoadGameDefinedStructure` only. Also new: `GetEffectType` returns script type 0 for states 7, 8, 9, 0xA, 0xF (scripts cannot see them); a stunned/non-commandable creature silently drops every script `Action*` and ignores `ClearAllActions`.

Sources: `.asm`/`.c` in `ROOT/decomp`, constants and jump tables read from `backups/vanilla_clean/swkotor2.exe` through the PE section table (.text 0x401000 raw 0x400, .rdata 0x986000 raw 0x584C00). Command table decoded from `InitializeCommands 0x665F50` (`CALL`-less stores `*(table + 0xC)[id*4] = FUN`) joined with the declaration order of `vanilla/nwscript.nss` (877 declarations = the 0x36D table size, anchors checked against the `// N:` comments). Wave-1 facts used as given (GATE_wave1.md section 1, AI4 action table, AI3 +0xFF5 correction).

## (b) Findings

### Q1. Which effects block or replace AI actions, and where
**CONFIRMED (with a correction to the brief): `+0xFF5` and `+0xFF4` do not gate `AIUpdate` or `RunActions`.**
- `field_census.py --offset 0xFF5 --all`: 32 hits in 10 functions, none in 0x569320 / 0x5D56B0. Readers: `AddAttackActions 0x568540` (0x5686AA, 0x5686C2, 0x568769, 0x568781), `SpawnInHeartbeatPerception 0x56B8A0` (0x56BAEB, 0x56BB65), `DoPerceptionUpdateOnCreature 0x576DC0` (0x5776A2, 0x5776C0), `RecomputeAmbientAnimationState 0x57A990` (14 compares), `OnApplyKnockdown 0x59BAB7`, `IsDebilitated 0x6DAA13/0x6DAA27/0x6DAA3C`, client `OnObjectSelected 0x7996D7`. ### Q2. GetHasSpellEffect semantics (R2 L2 risk)
**CONFIRMED: matches by the effect's `+0x1C` spell id, no creator filter, shows on every member that received an effect.**
- `0x67E670` pops (spell, object), resolves the object (`0x51C080` + `0x53DFB0`, found == 0), requires `vtbl+0x10 != 0` (CSWSObject view), calls `0x5476C0`, pushes the int result. `0x5476C0`: `if (param_2 != -1) for (i < *(this+0x14C)) if (*(*(*(this+0x148)+i*4)+0x1c) == param_2) return 1;` (asm `00547706 MOV EAX,[EDX+0x1C] / 0054770f CMP ECX,[EBP+8] / 00547714 MOV EAX,1`). O(E) per call, no side effect.
- Where `+0x1C` comes from: `CGameEffect::SetCreator 0x5E5EA0` (called by every `EffectXxx` command and by `EffectLinkEffects 0x6755A0`): `*(param_1+0x1c) = (**(code**)(*piVar3+0xb8))()` = `GetEffectSpellId` of the creator = creature `+0xFF8` (`00563350`). `+0xFF8` is -1 (ctor `005627b6`) except while a spell script runs: `EventHandler 0x56EFD0` (event id `[0x992440]` = 0x13) calls `SetEffectSpellId(payload[0])` (`0056fc64`), sets `+0x106C=1`, `+0x1070=payload+0x28`, runs the script (`0056fce2`), then `SetEffectSpellId(-1)` (`0056fcfd`). Effects built outside a spell script (plain AI scripts, heartbeat code) carry -1 and never match. Saved/loaded as GFF `SpellId` (`005e5510`, `*(param_1+0x1c) = uVar3`) and copied by `CopyEffect` (`005e5085 MOV ECX,[EAX+0x1C] / 005e5088 MOV [EDX+0x1C],ECX`), so it survives saves.
- Links: `OnApplyLink 0x5A1680` applies `+0x28` and `+0x2C` children as separate effects and returns 1 (the link shell is freed), so the target's list holds the children, each stamped at its own `EffectXxx()` call inside the spell script, i.e. with the cast spell id.
- Battle Meditation (vanilla `k_inc_force.nss` 3972-4027): effects are built once (`eLink1`, `SetEffectIcon(eLink1, 67)`), then for `nCnt` 0..2 `GetPartyMemberByIndex(nCnt)`: `if valid && GetRacialType != RACIAL_TYPE_DROID` -> `ApplyEffectToObject(DURATION_TYPE_TEMPORARY, eLink1, oParty, fDuration)`. So: it shows on every NON-DROID active-party member (0..2), not on droids (a droid target never reports it, so any "already active on the target" test false-negatives for droids), and it does not show on the 4th+ member. Force Valor / Fury-style `FORCE_POWER_FORCE_MIND` (k_inc_force 1853-1890) applies to `IsObjectPartyMember` creatures within 30 m. Both use the caster's spell id, so `GetHasSpellEffect(FORCE_POWER_BATTLE_MEDITATION_PC /_IMPROVED_ /_MASTER_)` is the right family test (R2 L2a), per member.
- SPECULATIVE: the same `eLink1` object is applied to up to 3 members; the VM pop (`0x6FDAB0` -> `0x702F20` -> host `vtbl+0x20`, not read) must hand out a copy per call (a shared pointer would be double-owned by `0x544210`); vanilla does exactly this loop, which supports copy semantics.
- Caveat for L2: removal scripts match by id too (`Sp_RemoveRelatedPowers`, `GetEffectSpellId(eAOE)` at k_inc_force 6123-6133), so a lower tier cast while a higher one is active is not applied (`Sp_BetterRelatedPowerExists`); the test must use the whole family (as R2 does).

### Q3. AoE object triggers
**CONFIRMED.** Script table of the AoE object at `+0x2A0`, 8 bytes per slot: slot 0 heartbeat, slot 1 user-defined, slot 2 OnObjEnter, slot 3 OnObjExit (`SaveEffect 0x62DEC0` string order "OnHeartbeat","OnUserDefined","OnObjEnter","OnObjExit"). `OnApplyAreaOfEffect 0x59F150` maps `EffectAreaOfEffect(id, sOnEnter, sHeartbeat, sOnExit)` as string 0 -> slot 2 (`0059f2b4`), string 1 -> slot 0 (`0059f359`), string 2 -> slot 3 (`0059f409`); the AoE spell id is the effect's `+0x1C` (`(**(code**)(*local_14+0xbc))(*(param_2+0x1c))`), the AoE follows its host (`0x62D540(host id)`, `+0x28C`) and `FUN_0062d750(int0)` loads radius/width from the area-effect row.
- Registration: `0062c13b CALL 0x51E040` preceded by `PUSH 0` = AI level 0 (like items, AI4). `0x62C360` runs once per scheduler pass of level 0.
- Heartbeat (in `0x62C360`): `FUN_0051af60(now - +0x2C0/+0x2C4)` -> ms; `if (5999 < local_8) { if (+0x2C4 != 0) RunScript(this+0x2A0, id, 1); stamp = now }` (`0062c440 CMP [EBP-4],0x1770`, `0062c453 JZ 0x62C493`). The first pass only primes the stamp, so the first script call comes >= 6 s later; afterwards the period is 6000 ms rounded up to the level-0 per-object update interval (AI4 AIQ cost model). It runs even for an AoE whose host moved.
- Follow: `if (+0x28C != INVALID && byte +0x270 == 0)` (`+0x270` = shape byte, written by `SetShape 0x62D410`): host position copied, `0x62E320(&pos)` (posts enter/exit for the new position) and `SetPosition` (0x543F50); host gone -> post event `[0x992420]` (0xB, destroy) to itself.
- Duration: `+0x2CC == 1` (ctor sets 2 at `0062c118`; `SetDuration 0x62D6F0` changes it): `+0x2C8` is decremented by `dt` (`+0xD0`) each pass, expiry posts event 0xB.
- Enter/exit: event id `[0x99241C]` = 0xA, payload word 0xC = enter, 0xD = exit (0x1E is posted for the second sub-area class in `0x5C2930`, lines 114/189). The AoE `EventHandler 0x62C630` consumes it: 0xC -> `+0x290 = payload object` (LastEntered) then `RunScript(+0x2B0)` (`0062c6ec`); 0xD -> `+0x294 = payload object` (LastLeft) then `RunScript(+0x2B8)` (`0062c763`); event 0xB -> destroy. Posters, all delta-0 (`FUN_0051c280(0,0,..)`/`0x51E170`): `0x5C2930` (diff of the creature's sub-area list vs the new one; called by `0x5C25E0` from `WalkUpdateLocation 0x5C3460`, `QuickWalk 0x5C3F70`, ForcePushed walker `0x5C5EF0`, `DriveUpdateLocation 0x5CE9D0`, `0x539E30`, `0x6E3A40`; plus `UpdateSubareasOnJumpPosition 0x5C2770` for jumps), `0x62E320` (AoE creation `0x62C800`, `JumpToPoint 0x62EB70`, follow in `0x62C360`), and area entry `0x522BF0` (payload 0xC to the area). `0x5C25E0` early-outs cheaply only when the creature is in no sub-area and none is at the new position (`local_2c = 0 < +0x374`, `local_14 = 0x54D180(...)`).
- Cost: `CSWSArea::InSubAreas 0x54D180` loops the whole `area+0x1A4` list (triggers, AoEs, others; per entry two virtual calls plus `0x62D280` / `0x623B90` / `0x61FC60` / `0x61D910`) once per walker step of every moving creature: O(number of sub-area objects in the area) per step. Each AoE adds one level-0 object to AIQ n.
- Script-visible: `GetExitingObject` (id 26, `0x682C30`) switches on the object type and for type 0xB (AoE) returns `+0x294` (`FUN_00682c30.c case 0xb: local_8 = *(undefined4*)(iVar2 + 0x294)`); `GetEnteringObject` (id 25, `0x67C6F0`) is its sibling for `+0x290`; `GetFirstInPersistentObject`/`GetNextInPersistentObject` (0x67EB50) use `0x62D280`; `GetAreaOfEffectCreator` id 264.
- Verdict: heartbeat 6 s level-0 quantised, enter/exit event-driven per step. SPECULATIVE: the per-object level-0 interval in a busy area (AI4).

### Q4. EFFOVF
**CONFIRMED (both), with reach.**
- No dedup/cap: `0x544210` computes the sorted position (`while (i < count && list[i]->type <= eff->type) i++`) and `FUN_00414280(param_2,local_10)` inserts; the only early exit is the handler verdict `FUN_0051efd0 == DAT_00995f18` (reject + free). Nothing compares an existing entry (no spell/creator/duration test). Permanent / instant-type effects (`flags&7 != 1`) are never expired by `0x544AD0` (`if ((*(ushort*)(local_1c+10) & 7) == DAT_009967b4)` is the only removal test). `UpdateEffectList` is O(E) per AIUpdate (restarts the index after a removal). The VM `ApplyEffectToObject 0x66D780` has no count guard either. Reach: any script that re-applies a permanent or long effect every heartbeat/round (spell scripts re-cast, item property scripts, `k_inc_*` buffs). Observed mitigation: `Sp_RemoveRelatedPowers` before application in the force-power scripts.
- LoadGameEffect: `0x5E5510`: `005e56fc CALL 0x5E4DD0` (`SetNumIntegers(NumIntegers)`: `new(n*4)` + memset), then for the ordinary effect (`005e58dc CMP EAX,1`): `while (local_50 < FUN_00718810(IntList))` -> `005e5940 CALL 0x5E4E80` (SetInteger: `*(int*)(*(this+0x34)+idx*4) = v`, no bounds). The legacy type-0x26 branch (`005e5719 CMP EAX,[0x995FB4]`, NumIntegers < 0x15) is bounded by construction (it reads `NumIntegers-6` plus 6 values, then `005e58a1 CALL 0x5E4DD0` resizes to 0x15), so it is not an overflow. Guard `0 < *(param_1+6)` only skips the loop for NumIntegers 0. Overflow when the saved IntList is longer than `NumIntegers` (heap write past `new(NumIntegers*4)`). Reach: callers `0x5205F0`, `CSWSObject::LoadEffectList 0x5406E0` (`005407b4`), `LoadGameDefinedStructure 0x669370` (`00669408`): save-game / module-state load only; a vanilla writer emits both from the same count, so only corrupt or externally edited saves trigger it. Read side: `GetInteger 0x5E4E60` unchecked too (handlers read index 0 to 7 of effects loaded with a smaller `NumIntegers`).
