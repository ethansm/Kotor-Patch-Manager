# R8: containers and strings (Steam swkotor2.exe, sha256 6a522e71...)

## 5-line summary
1. CExoString = `{char* buf; uint cap}` (8 bytes). Every value-returning method (ToLower 0x734690, Substr 0x734a00, Left 0x734500, Right 0x734870, operator+ 0x733df0) does `new temp` + copy-ctor 0x7335f0 (second `new`) + free temp = 2 allocs per call; 0x7337c0 (assign) and 0x7335f0 (copy) each do `strlen`+`new`. Census a1 attribution of the 737k temporaries: 0x7337c0 assign ~295k, 0x7335f0 copy-ctor ~233k, ToLower ~42k+, Substr 42k, ctor(char*) 23k, Format 20k, ctor(buf,n) 22k, assign(char*) 6k.
2. Biggest single producer = the per-portrait action-bar refresh 0x74cfe0 -> populators 0x77e650 -> 0x77a9e0/0x77c510->0x77bcf0 (and ~35 sibling callers). They call SetSize(count+1) = 0x58C3B0 which ALWAYS reallocates the 0x3C-byte entry array to exactly n+1 and deep-copies every CExoString (0x58C540 -> 0x58C700 -> 0x7337c0): O(k^2) allocs per rebuild. Census: 98,968 string allocs from 0x58C700, 23,246 array allocs from 0x58C540 in 2,917 rebuilds.
3. Growth policy: every CExoArrayList<T> template `Add` (0x4491C0, 0x40E060, 0x511820, 0x5E7600, 0x5E1720, 0x507DE0, 0x729C30, 0x84C120, 0x83EA60, 0x511930) is doubling from 16 (`local_18 = 0x10 / param_1[2] << 1`). The +1 growth is ONLY through the SetSize wrappers (0x58C3B0 x40 sites, 0x40DFE0, 0x451730, 0x463D40, 0x762AC0, 0x8FE670) when callers pass `count + 1`. CExoString concat/insert allocate exactly len (no slack), but assign/vsprintf reuse the buffer when cap fits.
4. O(n^2): sorted directory listing 0x737540 (binary search calling ToLower 0x734690 per probe = 2 allocs + strcmp) then 0x7395D0 insert shifts every later CExoString with 0x7337c0 deep copies; run ~21,179 times in the Override scan 0x723220 (GetResTypeFromFile 0x712C90 / GetResRefFromFile 0x712BE0 also Substr+assign per file). 2DA `GetInt(row, colName)` 0x71BCF0 does a linear `_stricmp` scan over all columns (0x71AEF0) per lookup and callers build a `CExoString("COLNAME")` (alloc) per call.
5. Top-30 fan-in identified below (13 high, 11 med); DB-ready rows at the end. Hook points (`55 8B EC ...` prologues, all >=5 stolen bytes, no relative branch) given in section (c).

## (b) Findings

### F1. SetSize(count+1) is exact-fit +1 with full deep copy, in 40 call sites (0x58C3B0)
- Decompile 0x58C3B0: `if (param_2 == 0) { free } else { FUN_0058c540(param_2); } param_1[1] = param_2;`
- 0x58C540: `param_1[2] = param_2; ... FUN_00919723(... uVar2*0x3c + 4 ...)`; `for (local_18=0; local_18 < param_1[1]; ...) FUN_0058c700(local_18*0x3c + iVar1);` then `FID_conflict__vector_deleting_destructor_(3)` on the old array (destructs every old CExoString).
- Callers pass `count + 1` (greps over decomp/: `FUN_0058c3b0(local_2c + 1)` x10, `(local_20 + 1)` x4, `(param_1[1] + 1)`, ...). Callers: 0x7B40F0 (x12, GetDefaultActions-style radial target menu, 6909 B), 0x779850 (x4), 0x842D40 (x3), 0x87BEC0 (x3), 0x87E8A0 (x2), 0x58A610 (x2), 0x77A9E0, 0x77BCF0, 0x77C1B0, 0x77C340, 0x77E1F0, 0x778940, 0x778BA0, 0x779E00, 0x77A030, 0x8427A0, 0x843500, 0x8495C0, 0x87C590, 0x87ECD0.
- Cost for building k entries: sum(0..k-1) = k(k-1)/2 CExoString copy-assigns (each `strlen`+`new`+`strcpy` because the freshly constructed target has buf==NULL) + k array allocs + k vector-deleting-destructors (one `delete` per string).
- Census (menu->in-game, 67,610 frames): a2 0x58C715 (inside 0x58C700) 98,968 allocs / 1.6 MB, a1 0x73386F; a2 0x58C412 (SetSize->SetAllocated array `new`) 23,246 allocs / 3.41 MB (sizes 145..512 B, i.e. 2-8 entries); 20,419 item formats (a2 0x77BE55, a1 0x7343AE) and 2,917 populates (5,834 = 2x2917 array allocs from a2 0x58C412 bucket 16..). Ratio 98,968/2,917 ~ 34 string deep copies per refresh.
- Trigger: 0x74CFE0 loop `for (local_8 = 0; local_8 < 7; ...) { for(...) FUN_007ecfa0(); *(param_1+0x7c+local_8*0xc) = 0; FUN_0077e650(local_8, ...); }` clears count (not array) then repopulates all 7 categories each refresh; db_functions calls it per-frame per portrait. 2,917 rebuilds vs 67,610 frames means most frames early-out (menu open stops the HUD tick, lesson 144), but during gameplay it is one rebuild per portrait tick.
- Fix idea (not applied): make 0x58C3B0 grow geometrically (`if (n <= cap) count=n; else SetAllocated(max(n,cap*2,16))`) and keep the 7337c0 copy-loop; `speculative`: entry array is referenced only via [ptr,count,cap] triples at portrait+0x78..0xC stride, and callers write `*param_2 + off + idx*0x3c` after SetSize, so capacity>count is safe.

### F2. CExoString value-returning methods = 2 allocs + 1 free each
- 0x734690 ToLower: `local_18 = FUN_00919723(local_14)` (new@0x734730), char loop, `FUN_007335f0(&local_18)` (copy into hidden return at 0x73483b, second new), `FUN_00733780()` (free temp). Same shape 0x734a00 (new@0x734b12), 0x734870 (0x73498e), 0x734500 (0x73461e), 0x733df0 (three branches). Return-by-value is compiled with an explicit temp because the function builds into a local then copy-constructs into the sret slot (no NRVO).
- Census: a1 0x73363D (copy-ctor `new` return) 232,522 allocs; callers by a2 function: 0x734690 (ToLower) 90,037, 0x737540 64,758, 0x734A00 48,598, 0x849270 17,310, 0x733DF0 (operator+) 11,819, 8,655 x2 from 0x849270-family (a2 0x8492AE/0x849346).
- No slack: concat allocates `len1+len2+1` exactly, so `a+b+c` = 4 news, 3 frees (operator+ result of first + second temp).

### F3. Directory listing + Override scan is O(n^2) string work (0x737540, 0x7395D0, 0x723220)
- 0x737540: for param_5==1 sorted insert: `while (local_198 = local_198/2, local_19c < local_194) { FUN_00734690(); iVar5 = FUN_00733bd0(); FUN_00733780(); ... }` = one ToLower (2 allocs, 1 free) per probe, then after probing 1 more ToLower for equal check, then `FUN_007335f0(local_184); FUN_007395d0();`.
- 0x7395D0 Insert: `FUN_0040e060();` (Add at tail) then `for (; param_4 < local_14; local_14 = local_14 + -1) { FUN_007337c0(); }` = shift every element after the insert point with a CExoString assign (alloc if dest cap too small).
- Census: 0x40E0F2 (0x40E060 tail assign) 21,612 allocs, 0x40E26C (0x40E170 grow copy, doubling) 33,813, ToLower 44,179 news, 0x712C90/0x712BE0 21,179 + 21,157 calls (a2 0x712D0F/0x712D28, 0x712C4F). File count ~21,179: the Override scan of the modded install. It runs inside the measured window, so an Override rescan (0x723220, referencing "OVERRIDE:" 0x99415C) happens during menu->game; `speculative`: once at startup if the capture began before the main menu, else every module load.
- 0x712C90: `FUN_00734190(0x2e,0)`, `FUN_00734a00(local_28,local_14 + 1,3)`, `FUN_007337c0(uVar2)`, `FUN_007360c0(local_1c)` = 3+ allocs per file for a 3-char extension lookup.
- Cheap wins (`speculative`): compare using a case-insensitive `_stricmp` instead of ToLower, sort once (qsort on char*) instead of binary insert with deep-copy shift.

### F4. Doubling containers (no action needed) and where +1 does not occur
- Add (doubling from 16): 0x4491C0 (CExoPtrList, `local_c = 0x10 / << 1`), 0x40E060, 0x511820/0x511930, 0x5E7600, 0x5E1720, 0x507DE0, 0x729C30, 0x84C120, 0x83EA60 (all show `if (param_1[2] == 0) local_1c = 0x10; else local_1c = param_1[2] << 1;`).
- SetAllocated implementations (13 template instances, each `_eh_vector_constructor_iterator_(...)` + copy loop + vector_deleting_destructor): 0x40E170 (8 B), 0x451A80 (4), 0x464040 (0x14), 0x4641A0 (0x20), 0x474230 (0xC), 0x508000 (0x18), 0x511B90 (0x18), 0x52E920 (0x10), 0x58C540 (0x3C), 0x5E17E0 (8), 0x729D60 (0xC), 0x884050 (0x18), 0x8FE4F0 (0xC). - SetSize(n) wrapper sites: 0x58C3B0 (40 sites, +1), 0x40DFE0 (7 sites: `FUN_0040dfe0(param_2 + 1)` in one), 0x451730 (5 sites, `FUN_00451730(*(param_1+0x88))`), 0x463D40 (3), 0x762AC0 and 0x8FE670 (1 each, `FUN_..(*(param_1+4))` = exact count).
- CExoString itself: no capacity policy (no +1/x2): assign reuses buffer if `param_1[1] >= strlen+1`, else free+new exact; `Format` uses a global 1 KB scratch `DAT_00a7ea80` grown by +0x400 with `free`+`new` inside the retry loop (0x734270 lines `DAT_00a7ea84 = DAT_00a7ea84 + 0x400;`), one-time cost.

### F5. 2DA column-name lookup is linear-with-stricmp and callers allocate the name each call
- 0x71AEF0: `for (local_8 = 0; local_8 < *(int *)(param_1 + 0x28); ...) { ... __stricmp(*(param_1+0x48)+..., _Str2) ... }` per `GetInt(row, colName)` (0x71BCF0, fan-in 473). Text-mode branch (0x3C==0) calls 0x734D60 per column which recomputes `_strlen` of both.
- 0x77A9E0 per row: `FUN_00733570("NAME_STRREF")` and `FUN_00733570("AISTATE")` each allocate 12/8 bytes: 14,585 + 8,785(0x710EC6 site) + 11,668 allocs in the census (a2 0x77AB3C, 0x77AC37). Also 0x606C30 `"MAXSINGLEITEMVALUE"` 8,742 allocs (a2 0x606CA2).
- Fix idea (`speculative`): cache column index in a static after first lookup or pass `const char*` overloads (0x71BCF0 takes CExoString& only).
