# R3: texture / model / GL memory lifetime (Steam swkotor2.exe 6a522e71)

## 5-line summary
1. ROOT CAUSE of the 195 MB: `CAurTextureBasic` uses the CResTPC pixel buffer zero-copy (`tex+0x44` = CRes+0x3C, Demand held, never memcpy'd). After upload `BuildAndStoreTexture` 0x4260E0 only calls FreeImage (vtable+0xB4 = 0x425160) when `vtable+0x30()` (= `tex+0xE9`, "loaded via the TPC path") is ZERO (`TEST ECX,ECX / JNZ 0x4261E6` at 0x4261D4). TPC textures always have `+0xE9==1`, so the Demand reference is kept until texture destruction / Reset. Non-TPC (TGA) textures are freed right after upload. It is not for mip regeneration, TXI, or re-upload: none of those need the buffer (see F2).
2. Releasing after upload is mechanically safe: the release path exists and is proven for TGA (FreeImage 0x425160 -> 0x421C40 -> callback DAT_00A1BBC0 = 0x93BAD0 -> tag 0xBBF lookup -> 0x93EA10 -> Release 0x7112B0/0x7130B0 + delete of the 0x1C wrapper); reload after Reset (0x423990) re-Demands via 0x4252C0. One-byte patch candidate: 0x4261D4 `75 10` -> `90 90`. Only real risk = post-upload readers of `GetImage` (vtable+0x3C, 0x422640) on TPC textures (F3, needs a runtime counter first).
3. G1 (glFinish): 0x4265E9 `CALL 0x4845A0` -> 0x4265F5 `CALL [0x9862C4]` (glFinish) runs at the top of every glImage (once per texture, not per mip). Gate = `(mask & 0x100000)==0x100000` where bit 0x100000 (`DAT_009F60BC`) is set by `GL_ATI_text_fragment_shader` OR `GL_ARB_fragment_program` (0x431BFF-0x431C10), so it is ON for every modern driver. Skip = change `JZ 0x4265FB` (0x4265F3, `74 06`) to `EB 06`; functionally harmless (pure sync), all textures of a frame are flushed in one burst by 0x427F30 -> 0x427810.
4. M1 (gluBuild2DMipmaps): only the NON-TPC path (TGA/uncompressed, 0x433CD0) and cube faces (0x432FA0) use it; the TPC path uses the pre-baked mip chain (0x434350 glTexImage2D/compressed per level) so the TPC mip chain IS used. In 0x433CD0 the cheap GPU path (`GL_GENERATE_MIPMAP`, 0x8191) is chosen only if `FUN_00484A60()` is true, and that is forced FALSE whenever bit 0x100000 is set (i.e. always on modern GL), so every TGA texture pays a CPU gluBuild2DMipmaps (or the engine's own 0x4337B0 loop for sub-image / 16-bit).
5. No texture-id-indexed array in K2: `[0xA1BB84]` (max GL tex id) is recomputed from scratch in 0x427810/0x427970 (not monotonic) and its only reader 0x427A60 (from 0x495760) has its result discarded (`MOV [EBP-8],EAX`, never read). MDL/MDX: loader 0x5122E0 memcpy's both blobs into private new[] buffers and closes the stream via release callback 0x93C130 (tag 0x7D2 MDL / 0xBC0 MDX -> 0x93EF40/0x93F180 -> Release), so model resman buffers are NOT retained by design.

## (b) Findings

### F1. TPC texture pixel buffers (CResTPC data) are held until the texture object dies (the 195 MB)
Chain (all read from the dump):
1. `0x4252C0` LoadImage calls loader `0x4219A0`, which first tries `PTR_FUN_009F4788` = `0x93B9C0` (installed at `0x93B650`: `PTR_FUN_009f4788 = FUN_0093b9c0;`). On success: `*param_10 = 1;` -> `tex+0xE9 = 1` ("TPC path"). It stores the returned pointer `param_1[0x11] = iVar4;` (`tex+0x44`).
2. `0x93B9C0` -> `0x93E880` (wrapper object, `new(0x1C)`) -> `0x93FFB0`: `iVar2 = FUN_007111e0();` (= Demand 0x711C20) then returns `FUN_00455820()` = `*(CRes+0x3C)`, and writes `*puVar1 = 0xbbf; *(undefined4 *)(puVar1 + 1) = param_1;` at `data + mipChainBytes + 4 + txiSize`. There is no memcpy: `tex+0x44` IS the resman buffer. Failure branches call `FUN_007112b0()` (Release); the success branch never releases.
3. Upload: `0x4260E0` -> `0x4265E0` `glImage` -> `[0xE9]!=0 -> 0x434350` (pre-baked mips). Then end of `0x4260E0`:
```
004261c5  8b11        MOV EDX,dword ptr [ECX]
004261ca  8b4230      MOV EAX,dword ptr [EDX + 0x30]     ; vt+0x30 = 0x422010 -> tex+0xE9
004261cd  ffd0        CALL EAX
004261cf  0fb6c8      MOVZX ECX,AL
004261d2  85c9        TEST ECX,ECX
004261d4  7510        JNZ 0x004261e6                     ; TPC (E9==1): skip FreeImage
004261d6..004261e4      MOV EDX,[EAX+0xB4] ; CALL EDX     ; vt+0xB4 = 0x425160 FreeImage
```
Decompile: `cVar1 = (**(code **)(*param_1 + 0x30))(); if (cVar1 == '\0') { (**(code **)(*param_1 + 0xb4))(); }`. vtable read from vanilla exe at 0x988094: slot 0x30 = 0x422010, slot 0xB4 = 0x425160 (verified by dumping the .rdata dwords).
4. The only places FreeImage runs for a TPC texture: `~CAurTextureBasic` 0x423480 (`FUN_00425160();`), `Reset` 0x423990 (`(**(code **)(*param_1 + 0xb4))();`), and the prologue of the next LoadImage (0x4252C0/0x425800). Textures live as long as any owner holds them (see F5), so the TPC buffers of every live model/GUI texture stay resident: this matches "195 MB live Demand-referenced CResTPC".
5. TGA textures ([0xE9]==0) take the `FreeImage` branch: `0x425160` computes the tag position and calls `0x421C40` -> `DAT_00A1BBC0 (0x93BAD0)` -> `0x93DAD0 -> 0x93EA10`: `FUN_00941520()` (Release when `+8!=0 && refcnt>0`) and deletes the wrapper if refcnt < 1. So the release machinery is exercised on every TGA texture already.

Why nothing needs the buffer (checked, not just assumed):
* Mip regeneration: TPC path uploads the stored chain (`0x434350`), no GLU. Not needed.
* TXI: the tag sits after the pixel data, TXI text is parsed at load (`[0xd]`/`[0xe]` controller objects, `0x424B10`); `4260E0` only uses `tex+0x44` before the FreeImage point (`FUN_00483ac0(param_1[0x11],...)` average colour at 0x426187, fed by the still-present buffer).
* Re-upload / downsample: `glImage` is called from only `0x4260E0` and `0x422D50` (proxy with explicit buffer, temporary `+0x44`); `0x4258B0` ApplyDownSampleLevel is a bare `RET`. Quality change goes through `0x427DE0` -> `Reset 0x423990` (frees + `+0xE4=0`) -> reload through `0x4252C0` which does its own FreeImage + fresh Demand. The retained buffer is never the source of a re-upload.
* GL context loss: no path re-uploads (only the two glImage callers above).

Conclusion: forgotten Release, gated by the `TEST ECX,ECX / JNZ` at 0x4261D4 (Steam build; K1 GOG likely has the same test, speculative). The "reason" is probably the 3D-object side channel `GetImage` (F3) rather than any correctness need of the upload path (speculative).

### F2. Safety of releasing TPC buffers after upload
Proposed patch (for a later phase, not applied): NOP the branch, 0x4261D4 `75 10` -> `90 90`, so `FreeImage` runs for TPC exactly as for TGA. Side effects of `FreeImage` (0x425160, verified): `tex+0xEA=0`, `tex+0x44=0`, callback release (`tex+0xE7` cleared by 0x421C40), `~wrapper` (refcnt<1). `tex+0xE9` stays 1, `tex+0xE4` stays 1 (image "processed").
Checks that the release will actually find its tag (else silent leak of the Demand ref): writer (0x93FFB0) puts the tag at `data + mipBytes + 4 + [CRes+0x38]` with `mipBytes` = sum over `mipCnt-1` levels using `(w+3)>>2 * (h+3)>>2 * (8|16)` (DXT1/DXT5), x6 for cube; reader (0x425160) recomputes identical bytes from `tex+0x68/0x6C/0x74/0x5C/0xD2` and passes `tex+0x60,+0x64` (= CRes+0x30 / CRes+0x38). `0x4261F0 EnsureMinimumImageShape` modifies `+0x68/+0x6C` only when `+0x44==0`, so dims are unchanged while the buffer exists. OK.
Risks (residual):
* R-a: post-upload `GetImage` (vtable slot 0x3C -> `tex+0x44`) consumers, they would now receive NULL for TPC textures exactly as they already do for TGA. Non-unit candidates that read pixels: `0x48FF30` (`_memcpy(*(param_1+0x34), GetImage(), w*h*bpp)`, would crash on NULL), `0x491C40`, `0x4907F0`, `0x492460` (mask/height style processing, call `GetImage` then read), `0x496080` (checks `if (local_60 == 0)` -> fallback, tolerant), `0x74FB20` (GUI). These are vtable-only (callers= empty), so who instantiates them is unknown (speculative). They must be measured (section c, counter C4).
* R-b: `0x4265E0` guards: if ever invoked with `+0x44==0` it does `param_1[0x16]=0` (zeroes GL name field `+0x58`, leaking the GL texture). Both callers guard (`CMP dword ptr [EDX+0x44],0x0 / JZ` at 0x42613D; `0x422D50` `if (iVar2 != 0)`), so unreachable after a FreeImage.
* R-c: Reset path (0x423990) after early free calls FreeImage again: `0x425160` starts with `CMP dword ptr [EAX+0x44],0` -> no double release.
* R-d: relocation of the processed-texture wrapper: refcnt handling (`FUN_00711250` = `[this+4]`) uses the same code as TGA, so no new state.

### F3. Where the budget/quality system fits (context for the reference)
`0x427DE0` (called with a byte budget from the video options function 0x78D6A0 at init `0x93B650`/shutdown `0x426C30`): `FUN_00428fc0` copies the list, `Reset`s every texture in it (`FUN_00423990()`), then `0x427B60` evicts by bumping downsample levels until the estimated GL size (`0x425DB0`, `param_1[0x3B]`) fits, then `0x427810` rebuilds. Because `ApplyDownSampleLevel` (0x4258B0) is a stub in this build, the downsample level has no effect on pixels; the "GL size" accounting (`DAT_00A1BBA0`) covers only GL memory, not the CPU pixel buffers, so it cannot see the 195 MB (open question Q1).

### F4. G1: glFinish per texture (exact path)
```
004265e9  e8b2df0500   CALL 0x004845a0        ; FUN_004845A0(): cached DAT_009F6100 == -1 ? (FUN_004843c0()?1:0)
004265ee  0fb6c0       MOVZX EAX,AL
004265f1  85c0         TEST EAX,EAX
004265f3  7406         JZ 0x004265fb          ; 74 06
004265f5  ff15c4629800 CALL dword ptr [0x009862c4]   ; glFinish
```
* Gate: `FUN_004843C0() = ((DAT_009F60BC & DAT_00A32DF8) == DAT_009F60BC) & _DAT_009F60EC`. Initial values read from the vanilla exe: `9F60BC=0x00100000`, `9F60EC=0x1` (never written: globals.tsv shows no writers, only 0x4843F2 and 0x48466E read it), `9F6100=0xFFFFFFFF` (uninitialised sentinel; first call fills 0/1).
* Bit `0x100000` is OR'd by `0x4317D0` for two extensions: `if (FUN_00484b20("GL_ATI_text_fragment_shader") ) mask |= DAT_009f60bc;` (0x431B9F..0x431BAB) and `if (FUN_00484b20("GL_ARB_fragment_program")) mask |= DAT_009f60e4 | DAT_009f60bc;` (0x431BF3..0x431C10). Every current driver (NVIDIA, Mesa compat, Wine) exposes ARB_fragment_program in the compat profile, so glFinish is unconditionally ON (speculative on the concrete driver, but the `DAT_009F6100` value is a one-shot readable).
* Rate: once at each `glImage` entry = once per texture (not per mip/tile/face); callers are `0x4260E0` (queued build, loop in `0x427810`, invoked each frame from `0x427F30`<-`0x46C2B0` at 0x46C3AD without a cap) and `0x422D50` (dynamic sub-updates via vtable). Static count on a load: equals the number of textures created between two frame ticks; the whole pending list `DAT_00A1BC30` is drained in one frame.
* Same gate also used at `0x46C2B0` (frame start, result unused except priming the cache), `0x4A1070` (0x4A11AD), `0x4C3430` (5 sites 0x4C8F67..0x4C959B): those are render features, do not touch them.
* Effect of skipping: `glFinish` only blocks until the GL queue has drained; the following GL calls are unaffected in semantics. It does not fence a resource shared with another context here (single context; the second context handles in `0x435720` are for render-to-texture shutdown). Safe minimal patch: 0x4265F3 `74 06` -> `EB 06` (also 2 bytes; leaves `0x4845A0` prime side effect at 0x4265E9 intact).

### F5. M1: gluBuild2DMipmaps callers, buffers, cost
* `0x433CD0` (uncompressed / TGA, dispatched when `vt+0x30()==0` from 0x4265E0): 
  - tile extract: if the texture is an atlas (`vt+0x5C != 1 || vt+0x60 != 1`) `local_34 = FUN_00484100(...)` allocates a sub-rectangle copy, freed at the end: `if (local_34 != local_38) FUN_009196fd(local_34);`.
  - mip path: `iVar3 = FUN_00484a60(); if (iVar3 == 0) { if ((param_2 == '\0') && (local_14 != 2)) gluBuild2DMipmaps(0xde1,local_60,local_24,local_40,local_78,local_68,local_c); else FUN_004337b0(local_24,local_40,local_14,local_c,param_2); } else { glTexParameteri(0xde1,0x8191,1); glTexImage2D(...); }`.
  - `FUN_00484a60()` = true only when `GL_SGIS_generate_mipmap` (`9F60B8`, 0x80000) present AND bit `9F60BC` absent: `if ((DAT_00a32df8 & DAT_009f60bc) == 0) {... }else DAT_009f6134 = 0`. Since `9F60BC` is set by ARB_fragment_program on any modern driver, it returns 0 -> the CPU mip build is taken for every TGA texture.
  - `0x4337B0` (used for sub-image updates or `bpp==2`): `FUN_0091d288(w*h*bpp)` temp (or `0x481F60` resample to a power-of-2 square), memcpy, then per-level `glTexImage2D` in a while loop, temp freed with `FUN_009196fd`.
  - `gluBuild2DMipmaps` itself allocates/frees internal scratch inside GLU (size ~ w*h*bpp for the first level, NPOT rescale); cost O(w*h*bpp*4/3) on the CPU, in the game thread, in the frame that flushes the pending list (order of magnitude several ms per 1024x1024 RGBA; speculative).
* `0x432FA0` (cube faces, [0xDF]!=0 and not compressed): per face `FUN_004264B0` face rotate copy (new[]/free) plus `gluBuild2DMipmaps` per face (only when mip flag `vt+0x70`).
* `0x432CE0`: one-time 256x256 LA texture (guarded by `glIsTexture(DAT_00A32E00)`): 65536 x 2 `FUN_0091C860` (pow) calls + gluBuild2DMipmaps; init cost only. `0x436250`: normalisation cube map (`0x427110` from `0x4260E0`/`0x427330`), one time.
* TPC mip chain: used, not discarded (`0x434350`: `local_80 = vt+0x58()` mip count; loop `glTexImage2D(0xde1,local_6c,...,local_70)` with `local_70 += local_78` per level, or `(*DAT_00a32d04)(0xde1,level,fmt)` compressed variant in 0x433CD0). So "use pre-baked mips" already holds for TPC; the opportunity is (i) GPU `GL_GENERATE_MIPMAP` for TGA (F5 patch: force `0x484A60` to return 1 when `GL_SGIS_generate_mipmap` is present, POT only; speculative on NPOT correctness), or (ii) converting TGA -> TPC offline (data-side).

### F6. Texture creation/deletion, module change, monotonic growth (Q1, Q4)
* GL texture names: created only in `0x4265E0` (per tile: `glGenTextures(w*h tiles, param_1[0x10])`, ptr array new[] `FUN_0091D288`), `0x427110` (norm cube), `0x432CE0`, `0x435600`, `0x436B90`, `0x436FB0`, and one-time renderer init `0x43BB50` (8) / `0x43C290` (4+) called from GL init `0x476BE0`. Deletes: per texture in `~CAurTextureBasic` 0x423480 (`glDeleteTextures(tiles, param_1[0x10]); FUN_0091c6aa(param_1[0x10]);`) and `Reset` 0x423990; bulk in `0x435720` (renderer shutdown, 20 sites). Display lists: `glGenLists(0x80)` (font) at 0x4743C0, `glDeleteLists` at 0x474460 guarded by `DAT_00A201DC`. No glGenBuffers/VBO import in the lists (VBO via extension pointers; not analysed).
* No global "module unload walks the texture table" exists: the only whole-table walkers are `0x427DE0` and `0x427D90` (Reset all; callers 0x78D6A0 video-options, 0x93B650 init, 0x426C30 shutdown). Textures die through owners: `0x4276A0` (`if (param_1[2]==0) delete`) is called by ~60 owner destructors (model/mesh/GUI, e.g. 0x50C7A0 triangle bin, 0x511DB0, 0x4DB0A0), `0x4741E0` (safe-pointer Set) unlinks. A leaked owner therefore pins both the GL texture and its (F1) CPU buffer. The live-texture counter is `DAT_00A1BBE0` (++ in ctor 0x423000, -- in dtor 0x423480).
* `[0xA1BB84]` (max texture id): written to 0 then rescanned as max over live `tex+0x40[]` GL names in `0x427810` (0x4278AE, 0x42795B) and `0x427970` (0x427980, 0x427A45), so it is not monotonic. Only reader `0x427A60` -> `0x495760` (asm: `CALL 0x00427A60 / MOV dword ptr [EBP + -0x8],EAX` then never read again). No array in K2 is sized or indexed by it; mesh buckets are `std::map<texid,vector*>` (wave 1). The K1 5000-entry bucket problem has no counterpart in the code reached from this batch. Other per-texture arrays: the name-hash sorted list `DAT_00A1BC60/64` and ordered list `DAT_00A1BC6C/70` are growable vectors (`0x4491C0`, doubling from 16 via `0x449320`); bounds are `< DAT_00A1BC64` loops (`0x4269F0`), no fixed capacity.

### F7. MDL/MDX ownership (Q5)
`0x5122E0`(reader, `ret 12`): `*param_1 = *psVar1` sizes, `_Src = FUN_004762F0(*param_1, param_2)` (mem stream: returns `param_2[3]` cursor and advances, no copy; FILE stream: `new + fread`), then `_Dst = FUN_00919723(*param_1); _memcpy(_Dst,_Src,*param_1);` and the same for the MDX blob (`local_20`). Parse (`0x5124D0` or `0x512750`), then `FUN_00475EA0(param_2,0)` (stream close -> release callback `DAT_00A30830 = 0x93C130`) and `FUN_00475E50(param_3)`, `FUN_009196FD(local_20)`. `_Dst` is handed to the parser (owner: model), `local_20` freed here. The 6.6-12.9 MB blobs in the census are therefore the model-owned copies (`_Dst`), and the resman side is released by `0x93C130 -> 0x93DF20/0x93DF60 -> 0x93EF40/0x93F180 -> 0x941520` after verifying the tag word (`*psVar2 == 0x7d2` / `0xbc0`). If the tag check fails (e.g. wrong offset when the stream was FILE-based) the release silently does nothing: not observed here, so no leak claim.

## (d) Open questions
1. Does the texture budget (`0x427DE0`, `DAT_009F475C`) get set to a finite value for TPC textures, and does it account CPU buffers? `0x425DB0` computes GL-size only; `ApplyDownSampleLevel` is a stub so budget eviction never changes pixels. Value of `DAT_009F475C` and `DAT_009F4758` at runtime unknown (data reads in the exe are 0 at file level; runtime-set).
2. Which callers use `GetImage` after upload (F2 R-a)? Classes at 0x48/0x49 (vtable-only) not instantiated in any direct call in the callgraph; a vtable/xref dump of `0x48FF30`, `0x4907F0`, `0x491C40`, `0x492460` would answer it statically.
3. `0x4276A0` deletes the BASIC texture when `proxy[2]==0`; is `[2]` the shared owner count for all proxies of that basic? (If proxies of one basic can be freed independently, sharing may be broken elsewhere.) Needs `0x474370/0x49B820` list semantics.
4. The `vt+0x1C` / `vt+0x20` / `vt+0x50` / `vt+0x90` virtual calls in `0x433CD0` (bump-map / compressed helpers) were not resolved; slots read from the vtable at 0x988094 can be mapped to functions if a later batch needs them.
5. Does the GL context expose `GL_ARB_fragment_program` on the target (Proton/NVIDIA)? Read `DAT_00A32DF8 & 0x100000` at runtime; if 0, G1 is already off and M1's cheap path already on, and the patches in F4/F5 are moot.
6. Non-TPC uncompressed TGA textures: census attribution between CResTPC/CResTGA/CResPLT was only argued from wave 1 (`+0x24 != 0`); the C1 counter separates them by `tex+0xE9`.
