### 5. Other TX interactions re-checked
* Free timing: FreeImage releases the resman Demand (`0x421C40 -> 0x93BAD0`), U5 L4/KT: after TX the Demand is dropped at flush so KT's dangling `CRes+0x14` window closes for TPC (U5). No double release: `+0x44=0` at `004252b0` makes later FreeImage calls no-ops.
* `+0xE9` is NOT cleared by FreeImage (T1 F4): E9 stays 1 after TX free, so a later glImage (only via controller/explicit buffer paths) still dispatches to the TPC uploader consistent with the stored format fields; irrelevant because no re-upload without a rebuild.
* Thread/reentrancy: 0x4260E0 runs on the main thread from the flush loop 0x427810; FreeImage's release goes through the resman functions used by vanilla for the same buffers; no reentrancy added.
