# U3: AI master / pathfinding / combat round / effects (server tick, per-request allocs, list growth, effect lifetime)

## Summary (5 lines)
1. AI scheduling is time-sliced round-robin, one `CServerAIMaster::UpdateState` (0x51d790) per server MainLoop pass (called once at 0x53396e): 10,000 us total budget (`MOV [EBP-0x18],0x2710`), 5 priority lists (4..0), levels 4..1 get 60% of the remaining budget (`PUSH 0x3c ... PUSH 0x64`), level 0 the rest; per-list cursor persists across ticks (0x51d1c0), QPC re-read after EVERY object (0x51dbf0), objects at most once per tick. Budget can be overrun by one object; >=75,000 us logs (0x51dcb5 `PUSH 0x124f8`).
2. Hidden O(n^2): the per-object pre-pass `for (i<count)` at 0x51d84b-0x51d9ec sits INSIDE the do/while that updates one object per iteration (loop-back `JC 0x0051d842` at 0x51dd1c) -> n scans of n objects per level per tick (cheap body; heavy `0x5c3f70` call only for creatures with [obj+0x220]!=0 that are mid-move). It consumes the same 6 ms budget, so large areas starve low-priority AI.
3. Pathfinding is time-sliced to 1000 us per request per call (`[0x9944c4]=1000` -> `[0xA7E0D0]` by 0x983dc0), single entry 0x55ab30 (only caller 0x5BFC00 AIActionMoveToPoint), restartable state machine; buffers are NOT pooled: per search `new` of 8*(dist+36)+16 B x2, 0x2000 B DFS table (0x555D00), 0x90 B successor array PER grid node (0x551F50) and path-point arrays 4*N. Per-creature CPathfindInformation = 0x278 B (0x561F30). The pathinfo Shutdown 0x6F99F0 does not free +0x18C/+0x1B4/+0x1D8/+0x200 -> leak of a few KB if a creature dies mid-search (small).
4. Effects: per-object array at obj+0x148/+0x14C, sorted insert by type, no stacking dedup, expiry scanned every AI tick (O(E), restarts at 0 after each removal -> O(E^2) worst case); add/remove are symmetric (ApplyEffect 0x544210 / RemoveEffect 0x544640 / dtor loop 0x53F050); handler dispatch bounds-checked (< 0x76). Combat round is bounded (action list < 4, attack array of 5, cleared at round end). No leak or unbounded growth found in either; runtime census shows AI/effects negligible (85 live effect blocks / 2.7 KB).
5. Robustness: CGameEffect GetInteger/SetInteger (0x5E4E60/0x5E4E80) have no bounds check and LoadGameEffect's IntList loop (0x5E5510) is bounded by the list length, not NumIntegers (heap overflow on a crafted/corrupt save); CombatRound loads OnHandAttacks/OffHandAttacks unclamped (0x592840) while GetAttack (0x5908C0) only clamps below 0 (SPECULATIVE reachability). Hook points for tick time, per-object AI time, pathfind time/result and live effect counts are listed in (c).

Method: static only (decomp + asm under ROOT). Constants read from the vanilla exe (sha256 6a522e71..., backups/vanilla_clean, read-only) with a PE reader. Mapper outputs: `findings/U3_map_{CServerAIMaster,CSWSCombatRound,CGameEffect,CSWSAreaOfEffectObject,CSWSEffectListHandler,CSWSObject,CPathfind}.tsv`.
