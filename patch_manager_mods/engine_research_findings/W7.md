**V5. Patch (primary): 0x668FE0, 1 byte.**
- Stolen/changed bytes: `7D` -> `73` at 0x668FE0; byte `30` unchanged. Encoding: `73 cb` = JAE/JNC rel8; target = next instruction 0x668FE2 + 0x30 = 0x669012 (identical to the original). ModRM none.
- Flag semantics: `CMP [EBP+8],0x36D` computes id - 0x36D: CF = (id <u 0x36D). JAE jumps when CF=0, i.e. id >=u 0x36D, which includes every negative id (>= 0x80000000 unsigned after MOVSX). Ids 0..0x36C keep CF=1 and fall through. Behaviour for non-negative ids is bit-identical to JGE.
- Branch-target scan (no instruction boundary is changed, this is only to show nothing lands inside):
  `grep -rE "(J[A-Z]+|CALL|JMP) +0x0*(668fd9|668fda|668fdb|668fdc|668fdd|668fde|668fdf|668fe0|668fe1)\b" decomp/*/*.asm` -> empty ("scan1 done"). Calibration of the regex: the same pattern for `669012` returns exactly `00668fe0 JGE` and `00668fef JZ`. No switch/jump table in 0x668FD0.
- Live regs/flags after the site: JGE/JAE consumes the flags; fall-through reads none (`00668fe2 MOV EAX,[EBP-8]`); the taken path `MOV EAX,0xfffff82e` writes EAX only. Nothing clobbered.
- Hook cost: zero (in place).

**V6. Patch (optional, source-level, equivalent): 0x700276, 1 byte.** `0F BF 55 8C` (MOVSX EDX,word ptr [EBP-0x74]) -> `0F B7 55 8C` (MOVZX EDX,word ptr [EBP-0x74]). Same length, same ModRM (0x55 = mod 01, reg EDX, rm EBP), disp8 0x8C. Then ids 0x8000-0xFFFF arrive as positive 0x8000-0xFFFF and the UNPATCHED signed check already rejects them. Scan: `grep -rE "(J[A-Z]+|CALL|JMP) +0x0*(700275|700276|700277|700278|700279)\b" decomp/*/*.asm` -> empty ("scan2 done"); 0x700275 is mid-block (0x700270 is the JNZ target of 0x700264, 0x700274 is a plain PUSH). Recommendation: apply V5 (protects every caller of slot +8 and also the handler never sees a negative id because it is rejected); V6 additionally is harmless. Applying only one is sufficient.

**F2. Budget [CONFIRMED double charge].** `resman+8` is decremented at 0x712F5E..0x712F64 on EVERY Malloc entry; it is restored only on NULL (`00712fe6 CMP [EAX+0x10],0 / 00712ff5 ADD EDX,[EAX+0x18]`) and in FreeResourceData (`00712131 ADD EDX,[EAX+0x18]`, skipped for source type 1: `007120eb CMP EDX,1 / 007120ee JZ 0x0071213a`). A failed Service charges the budget once and refunds nothing; the retry charges again; one eventual free refunds once. Net per failed attempt: -size (budget under-counts, which makes FreeChunk 0x712160 evict earlier). Note the signed budget is already negative on LAA builds (R1), so there is no new hazard, only slightly more eviction.

**F3. Which restypes can fail [partly CONFIRMED].**
- Short read (type 0/2 sync): the key table gives the size (`param_2[6] = vtbl+0x24`) but the file (BIF/ERF/MOD/RIM) is shorter: a truncated or mis-sized archive (a mod that ships a broken .mod/.rim/.erf, or an interrupted copy). Any restype in such an archive.
- 0-byte file: `FUN_00919723(0)` is non-NULL (MSVC malloc(0) returns a block), read 0 == 0, so for sync Service a 0-byte resource passes the short-read test; whether it fails is decided by vtbl+0x10 of the class. In 0x7133A0 async a 0-byte/unopenable file returns 0 BEFORE Malloc (T3: `if (local_24 == 0) {... free file; return 0}`), no buffer, no FS leak (that is CR territory).
- OnResourceServiced == 0 (vtbl+0x10, slot 4): CResTPC 0x945F20 returns 0 when `+0x10 == 0` and in the branches where `+0x40`/`+0x3C` are already non-zero (`if (*(int *)(param_1 + 0x40) == 0) { if (*(int *)(param_1 + 0x3c) == 0) {...} else ...` `uVar1 = 0`); first service of a clean CRes returns 1 without validating header values. So for TPC the failing case is a RE-service with stale `+0x3C/+0x40` (statically possible if vtbl+0xC called from 0x711FE0 does not clear them; vtable not dumped: SPECULATIVE). Other classes (TGA 0x9452C0 family, PLT, GFF, 2DA) were not checked: SPECULATIVE.
- Adjacent robustness (not part of W7, SPECULATIVE reach): 0x945F20 computes `local_c / local_8 == 6` with `local_8 = *(ushort *)(hdr + 8)` unchecked (corrupt compressed TPC with width 0 -> #DE). Only reached for `**(int **)(param_1 + 0x40) != 0` (compressed).

Dangling interior pointers: classes that cache pointers into the buffer (TPC `+0x3C/+0x40/+0x44`) keep stale values after the free exactly as they keep them today (today the old buffer simply leaks and the new one replaces `+0x10`); no new reader of freed memory is created beyond what the stale fields already imply (SPECULATIVE; vtbl+0xC not read).
