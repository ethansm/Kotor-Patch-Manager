# U2 - Miles sound system (MSS32 / MSS32MIDI), static analysis (Steam swkotor2.exe, base 0x400000)

## Summary (5 lines)
1. Sample handles are POOLED, not per-play: AIL_allocate_sample_handle has exactly 2 call sites (0x705850, 0x7058EC, both in Initialize 0x7051C0), releases only in Initialize/ShutDown (0x705409, 0x7054A6, 0x7059E4, 0x705C75, 0x705D07). No leak path for sample handles; NULL allocate is checked (shrinks the voice count, no crash). Live INI = 32 3D + 32 2D voices (2D upper half is released at init; only 16 2D voices + 16 stream slots).
2. WAV data is NOT copied: Miles plays straight from the CResWave buffer (`_AIL_set_sample_file(handle, CRes->vtbl[+0x14](), 0)` at 0x707D1C-ish), so the CRes is held Demanded from 0x70EC89 (Demand) until 0x70ECB0 (Release, via source stop 0x70FB90 AFTER AIL_end_sample). Demand/Release balance in runA (RT 4: demN 506 / relN 506). Brief's "1-2 WAV evictions per load" is WRONG: runA launch 2 shows 148 WAV evictions (156 allocs, 9.3 MB raw) in the ~3000 frames after a load, and 285 evictions / 223 re-demands-within-60s over the session; resident ends at 0.
3. Decompressed ADPCM/MP3(BMU) audio lives in Miles-allocated memory that resman does not charge: 0x722A30 -> `FUN_007120c0` frees the raw buffer, credits `resman+8 += CRes+0x18`, zeroes `CRes+0x18`; freed later only by 0x7229C0 (`_AIL_mem_free_lock`). Budget/eviction accounting under-counts WAV memory (size of the decoded copy is not in RT 4 allocB).
4. Per frame (frame loop -> MainLoop 0x781BE0 -> 0x783EE0 -> CExoSound::Render 0x70B8F0 -> 0x705D70): NO per-source AIL_set_sample_3D_position per frame (only at play 0x707E2C and on SetPosition 0x70FD73). Per frame by construction: <=2 listener AIL calls (only if changed), 1 volume_pan (+reverb) per positioned streaming source (0x70E2E0), ~2-3 AIL_sample_status per playing sample, 1 AIL_stream_status per stream, a 3 ms time-sliced occlusion pass (0x707050, budget `[+0xC4]=3`), and 9 full walks of the source lists in Render. No malloc in Render itself (list-node pushes via 0x54AA10 are per-event).
5. Bugs/robustness: (a) ReInitialize (options "Force Software"/EAX toggle, 0x7DB680 -> 0x70B9B0 -> 0x7051C0) tears everything down then falls into `AIL_quick_shutdown` and returns 0 (0x7054CE -> 0x70552C -> 0x705562): sound stays dead until a second call (CONFIRMED control flow); (b) CExoSound ctor 0x70B4E0 ignores Initialize's return, so a CExoSound with dead Miles exists and Render still calls listener AIL functions with an uninitialised dig handle (0x7082D0 `local_8`); (c) PlayOneShotSound 0x708360 writes `local_34[10]` after an unchecked `new(0xA8)`; (d) VO WAV header probe reads `[data+0x1D6]` with no size check (0x722B0C). DAT_00a10768 is 1 in .data (verified in the exe), so the mp3 branch (".mp3" ASI) of 0x70CAA0/0x722A30 is the LIVE one (relevant to k2-mp3-playback-fix; not analysed).

Method note: I read swkotor2.exe .data bytes read-only (python) only to learn the initial value of DAT_00a10768 and some string bytes. No files modified. Mapper outputs: `U2_map_CExoSoundInternal.tsv`, `U2_map_CExoSound.tsv`, `U2_map_CExoSoundSourceInternal.tsv`, `U2_map_CExoStreamingSoundSource.tsv`, `U2_map_CSWCSoundObjectCSWCAmbi.tsv` (the CSWC* mapping row set is partly weak; the CExoSound* ones were confirmed by decompile as noted below). CSWSSoundObject class: not mapped (SPECULATIVE: server side has no Miles calls; no AIL import is called outside 0x70xxxx/0x72xxxx/0x40CC70).

#### F1 - WAV re-demand churn is large, contradicts the brief (CONFIRMED from runA, med impact)
runA launch 2 (`inputs/runA_perflab_metrics.txt`, RT 4 = restype WAV: allocN allocB evictN evictB freeN freeB relN relZero demN redem60 resident):

- end of launch 2 (metric 44): `RT 4 335 12991304 285 12222426 335 12991304 506 502 506 223 0`. Demand 506 = Release 506 (`relN`), `relZero` 502: refcount hits 0 on release (WAVs are not shared while playing).
Consistent with static: Demand held only while a source is bound (0x70EC89..0x70ECB0); after Release refcount is 0 and FreeChunk may evict (R1: evicts refcount-0 only); with `over_budget` rising continuously (`RES malloc=14211 over_budget=12857`), every WAV is evicted as soon as the next allocation needs space, so repeating sounds (UI clicks, footsteps, combat) are re-read and re-decoded each time. Absolute cost small (13 MB raw / 35 min, ~223 re-reads); Demand wait was 0. A reference-hold cache for restype 4 would remove the reload, but it is a policy choice (SPECULATIVE benefit; not measured).
Answer to Q2 "consistent?": the resident ~0 yes; "1-2 per load" no (148 within seconds after a load: area LoadSounds creates/plays many sources, 0x527580 CSWSArea::LoadSounds 0x2C0 x 69 per R2).

#### F2 - decoded audio bypasses resman accounting (CONFIRMED mechanism; size effect SPECULATIVE)
0x722A30 asm: `00722aac  83c008  ADD EAX,0x8 ; 00722ab0  ff15dc649800  CALL dword ptr [0x009864dc]` (`AIL_decompress_ASI`) then `00722ad9 52 PUSH EDX ; 00722ada 8b0d90b4a100 MOV ECX,[0x00a1b490] ; 00722ae0 e8dbf5feff CALL 0x007120c0` and `00722aee 894810 MOV [EAX+0x10],ECX` (CRes+0x10 = Miles buffer). 0x7120C0 frees the raw buffer and does `*(int *)(param_1 + 8) = *(int *)(param_1 + 8) + *(int *)(param_2 + 0x18); *(undefined4 *)(param_2 + 0x18) = 0;`: the raw size is credited back and the CRes size field is zeroed, so the (4x-10x larger, SPECULATIVE factor) decoded copy is never charged to the resman budget. Same for ADPCM (`CALL 0x7120c0` at the other sites). So `RT 4 allocB` (12.99 MB) under-reports real WAV heap; eviction pressure from WAVs is invisible to FreeChunk. Impact low-med (WAVs are transient).

#### F5 - CRT FILE held by parked streaming sources (SPECULATIVE; low-med)
0x70DD10 `_AIL_close_stream_4(*param_1); *param_1 = 0;` leaves `[+0x4F*4]` (FILE*) open; closed only at dtor (0x70BF80) or the next OpenStream (0x70CAA0 else-branch top). ### Axis 2 - per-frame / per-tick cost (Q3)
