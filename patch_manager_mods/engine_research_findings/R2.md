# R2 - allocation hot sites (census_by_a2, 67610 frames, 1,881,147 allocs, 257 MB live)

## 5-line summary
1. ~66% of all allocs are two transient families with ~0 live bytes: CExoString ctor/copy/assign/ToLower (top-40-by-count rows sum to 737k allocs = 39% of 1.88M, 10 MB) and the 32-byte std::map node (516k allocs = 27%, `FUN_00474110` new(n<<5)); the map nodes are per-frame render-pass `map<uint,vector<T*>>` inserts made by `operator[]` READS (0x472630) in 0x465F90/0x4662E0/0x466700, plus 119k 64-byte vector buffers (0x473F40->0x4643A0).
2. Action-bar rebuild `FUN_0074CFE0` (already in DB as per-portrait per-frame refresh) drives ~236k allocs (12.5%): it re-populates all 7 categories every call through `CExoArray<0x3C-byte entry>::SetAllocated` 0x58C540, which grows one slot at a time and deep-copies every CExoString (98,968 copies via 0x58C700). 5834 executions (GetBehaviors 0x77AC37: 11668 = 2 x 5834).
3. 0x427520 miss path CORRECTED: a 0x18-byte CAurTexture handle is allocated on EVERY 0x4274E0 call (23757 allocs, 12082 live); a 0xF4 CAurTextureBasic record (+0x30 sub-object, +list slot) only on a name miss (392 allocs, 341 live, 1.65%). Records are the cache (sorted global array DAT_00A1BC60, O(N) linear hash scan); they have a real dtor 0x423480, growth is bounded by distinct texture names, not by module loads.
4. Several census a2 values are STALE (mid-instruction 0x58444D; 0x45FFAB is a 28-byte site but the block is 54920 B; 0x4B5E47 is a glActiveTextureARB call; 0x561445/0x739981 are wrappers). 0x5122E0 is the binary-MDL loader (`new(*param_1)` = model blob kept live, `new(param_1[1])` = MDX copy freed at 0x5122E0 end): 0x51206E = 41 blobs (6.6 MB live) + 43 transient MDX copies (9.3 MB).
5. Oversized fixed buffers: 256 KB shared I/O chunk buffer (0x401CF0 in CAppManager ctor chain, used by save copy loops 0x7216C0/0x722530), 2 x 128 KB net-layer ring-buffer objects (0x2007C at 0x5363A0 and 0x788D90, single-player too), 124.8 KB CServerExoAppInternal (0x51BC20), 2 x 85 KB CGuiInGame sub-objects (0x7BE4C0, re-created in 0x7CFCA0). alloc_sites.tsv misses every `new[]` via the 11-byte thunk 0x91D288 (41 caller fns, e.g. GL buffer pool 0x429F00).

Conventions: `hist idx i` = floor(log2(size)) - 3 (8B->0, 24B->1, 32B->2, 64B->3, 244B->4, >=256KB->15; verified on 0x4275C1, 0x473B68, 0x473F80, 0x4275A0-row 0xF4). "a2 valid" = the instruction ending at a2 is a CALL to an allocator or to a function whose size arg matches the block size.

### Q2. Per-frame / transient garbage (alloc count high, live low)
1. **Render-pass bucket maps (0x465F90, 0x4662E0, 0x466700)**: 516,197 nodes of 32 B (7.6 per frame of 67610) + 118,969 vector buffers of 64 B (1.76/frame) + others; live 177+247 at snapshot. Mechanism (quoted):
   - list build `uVar2 = FUN_00427970(uVar1,uVar2); FUN_0049b760(uVar2);` then for every texture id `local_4c = *(undefined4 *)(local_1c + local_20 * 4); iVar3 = FUN_00472630(&local_4c); if (*(int *)(iVar3 + 4) != 0)` (0x465F90 lines ~57-62).

Quote: `if (param_2 == 0) { ... Growth is bounded by the number of distinct texture names ever referenced (about 244 B + 48 B + 8 B + list slot each, ~100 KB now), not by module loads; no evidence of unbounded growth. Handles are owned by their users; live 12,082 x 24 B = 290 KB.
