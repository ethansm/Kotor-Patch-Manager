# R4: save/load path and GFF (CERFFile::WriteResource_2 SL, 0x5122E0)

## Summary (5 lines)
1. SL (WriteResource_2 0x721BB0 "never freed") is REFUTED: the buffer at [EBP-0x10] is stored into the local 12-byte holder at [EBP-0x1C] (+8 = data ptr, `MOV [EBP-0x14],ECX` at 0x721D67) whose destructor 0x722650 -> 0x722670 calls `_free` (via 0x9196FD) on it at every exit (0x721E30 normal path). The db_functions.tsv row 00721bb0 ("NEVER freed") is wrong. Do NOT install a K1-style free hook: it would double free.
2. Additionally the leaking branch (`CMP [EBP+0x14],0 / JZ 0x721D1B`, flag param_5 == 0) is dead in K2: all 3 callers (0x55CB50, 0x529DD0, 0x55DB00<-0x55BB80) pass flag = 1, so the GFF serialises straight into the file via 0x71A670 and no per-resource copy exists. Leak per save through this function = 0 bytes.
3. Sizes written per save (formula from 0x71ACB0): IFO 0x7DE "Module" + ARE 0x7DC per area + GIT 0x7E7 per area; each = 0x38 + 0xC*structs + 0xC*fields + 0x10*labels + fielddata + fieldindices + listindices. Written with fwrite, not held. The save function 0x53AF20 (new 0xA0 GFF, new 0xD0 CERFFile) frees both (vtable dtor / 0x720C20+0x9196FD): balanced.
4. 0x5122E0 is NOT save code: it is the binary model (MDL + MDX) loader (called via 0x511FB0 <- 0x511F50 <- 0x48E160 model-by-name loader, and 0x512130 <- 0x48E2A0). The 12.9 MB / 5 blocks and 6.6 MB / 39 blocks are the MDL blobs (`new(*param_1)` at 0x512376), which become the live model object (fixed up in place by 0x5124D0), owned by the model cache (sorted array DAT_00a1ffa8/ffac); the MDX copy is freed at the end of 0x5122E0. Census a2 0x58444D is not a return address (mid-instruction in FUN_00582010), a stale stack value; the trustworthy a2 is 0x51206E (return into 0x511FB0).
5. No confirmed leak found on the save path; remaining candidates are speculative (not audited: 0x55B830, 0x534600, 0x8529E0, 0x7D1940, exception paths).

## (b) Findings

### F1. SL refuted: the buffer IS freed (holder destructor)
Alloc, copy, write (asm, WriteResource_2):
```
00721d1e  e85d520000  CALL 0x00726f80        ; size = srcObj+0x18
00721d34  50          PUSH EAX
00721d35  e8e9791f00  CALL 0x00919723        ; operator new(size)
00721d3d  8945ac      MOV [EBP-0x54],EAX
00721d43  8955f0      MOV [EBP-0x10],EDX     ; buf
00721d52  e8492ecfff  CALL 0x00414ba0        ; src data
00721d5c  e83fbe1f00  CALL 0x0091dba0        ; memcpy(buf, src, size)
00721d64  8b4df0      MOV ECX,[EBP-0x10]
00721d67  894dec      MOV [EBP-0x14],ECX     ; holder(+8) = buf   (holder base = EBP-0x1C)
00721d8a  8d4de4      LEA ECX,[EBP-0x1C]
00721d8d  e84e080000  CALL 0x007225e0        ; write (fwrite copy, no retain)
```
Ownership: the holder at [EBP-0x1C] has ctor `00721bea LEA ECX,[EBP-0x1C]; CALL 0x007224c0` (zeroes +0,+4,+8) and `[EBP-0x18]=size` (0x721D29), `[EBP-0x14]=buf`. Every path to RET calls its dtor before the epilogue:
```
00721e30  e81b080000  CALL 0x00722650   ; ECX=[EBP-0x1C]  (normal path, after 0x721D92..0x721DF9 -> JMP 0x721E22)
00721c18  CALL 0x00722650  (early exit: idx >= max, holder empty)
00721e09  CALL 0x00722650  (no file: holder empty)
```
0x722650 -> 0x722670: `CMP dword ptr [EAX+8],0` / `MOV EDX,[ECX+8]` / `PUSH EAX` / `CALL 0x009196fd` / `MOV [ECX+8],0`. 0x9196FD -> `JMP 0x0091c6b5` (_free). So buf is freed at 0x721E30 on the normal path. The only unwinding not covered statically is a C++ exception (SEH table 0x9605C8 is present; speculative). 0x7225E0 confirms no ownership transfer: it only does `FUN_00739a30(param_1[2], param_1[1], 1)` = `_fwrite(buf,size,1,FILE*)` (0x739A30) and header writes.
The K1 fix (hook right after the write, K1 0x5dde32) was needed because K1's equivalent code lacked the holder destructor or had a differently laid-out buffer; the K2 layout differs (speculative reason). Recommend correcting `db_functions.tsv` row 00721bb0.

### F2. The leaking branch is dead: all callers pass flag = 1
`00721c7f CMP dword ptr [EBP+0x14],0x0 ; JZ 0x00721d1b` (0x721D1B = the copy branch). Callers:
- 0x55CB50: `FUN_00721bb0("Module",0x7de,param_1,1,0xffffffff)` (flag 1, IFO).
- 0x529DD0: `0052a4ca PUSH -1; 0052a4cc PUSH 1; PUSH [EBP-0x50]; 0052a4d2 PUSH 0x7e7 (GIT); CALL 0x721bb0` (flag 1).
- 0x55DB00: flag = its param_4; only caller 0x55BB80 passes `0055bbe1 PUSH 1; PUSH 0x7dc (ARE)` (flag 1). 0x55DB00 callers list = 0x55BB80 only.
Hence the flag==0 path (raw byte-buffer, IFO/ARE/GIT source objects with data ptr from 0x414BA0) is never taken by any static caller (indirect calls not seen: `grep 00721bb0 callgraph.tsv` shows only the 3 CALL rows).

### F3. What a save writes and the per-save byte model
Flag=1 path: `0071a8b0` (Compact) then `0071acb0` (size) then `0071a670` (writes header 0x38, struct table, field table, label table, field data, field indices, list indices with fwrite to the ERF FILE*). No malloc per resource. Serialised size per resource (0x71ACB0):
`size = 0x38 + 0xC*nStructs(+0xC) + 0xC*nFields(+0x14) + 0x10*nLabels(+0x1C) + fieldDataBytes(+0x24) + fieldIdxBytes(+0x2C) + listIdxBytes(+0x34)`.
Per save: ERF total = sum over {IFO "Module" (0x55CB50), ARE per loaded area (0x55DB00, only executed when `*(param_1+0x220)==0`), GIT per area (0x529DD0)}; these are file bytes, not heap. Heap that is transient: per-resource Compact() allocs (0x71A8B0 `FUN_00919723(...)`, old freed by `FUN_009196fd(*(param_1+100))`; balanced). Leak bytes per save through this path: 0. No static estimate of GIT size possible (varies with object count; speculative: hundreds of KB per big area).
Other save-time allocations in 0x53AF20 (the save entry; alloc sites 0x53B338 `new(0xA0)` = GFF freed by vtable dtor `(**(code**)*local_3c)(1)` at line ~471; 0x53C268 `new(0xD0)` = CERFFile freed at `FUN_00720c20(); FUN_009196fd(local_290)` line 514) are balanced. 0x7211E0 `new(4)` (file holder at +0xAC) is freed by 0x721E70 (`FUN_00739880(); FUN_009196fd(iVar1)`), called after 0x7221C0 in 0x53AF20.

### F4. 0x5122E0 = binary model loader, not save data
```
005122e0 FUN_005122e0(size_t* param_1,...):  *param_1 = *psVar1 (MDL size), param_1[1] = *psVar1 (MDX size)
00512376  e8a8734000  CALL 0x00919723   ; new(*param_1)  -> _Dst   [a1 = 0x51237B]
0051237b  ...
          _memcpy(_Dst,_Src,*param_1);
          local_20 = FUN_00919723(param_1[1]); _memcpy(local_20,local_38,param_1[1])  [a1 = 0x5123F7]
          local_1c = FUN_005124d0(_Dst,local_20,param_2)   (or 0x512750 if param_4 != 0)
          FUN_009196fd(local_20);   ; only the MDX copy is freed
```
`_Dst` is passed to 0x5124D0, which rebases pointers in place (`param_2[10] = (int)param_2 + param_2[10]`, `*param_2 = FUN_00452890`), i.e. `_Dst` becomes the live model object; its "sibling" MDX data is copied again via `FUN_00432ee0/FUN_00432f10` (a second, separately owned buffer at param_2[0x2B]). So the census "live" 12.9 MB (a2 0x58444D, 5 blocks, avg 2.58 MB) and 6.6 MB (a2 0x51206E, 39 blocks, avg 170 KB) are resident models (MDL blobs). Owner: model cache/registry (sorted array DAT_00a1ffa8, count DAT_00a1ffac, searched by name in 0x48E2A0; 0x48E160 uses DAT_00a32e04 as current-load list). Destruction: object vtable[0] `FUN_00452890` -> 0x452BE0 (frees nodes, DAT_00a1dee0 counters). Whether module change frees them is speculative (not traced; check callers of vtable dtor 0x452890 and DAT_00a1ffa8 users 0x9835C0/0x984E30).
Census note: a2 = 0x58444D falls inside `00584449 8b9528f9ffff MOV EDX,...` (bytes 0x584449..0x58444E): not an instruction boundary/return address; treat as a stale-stack value (lesson 155 caution). 0x51206E is a valid return (after `00512069 CALL 0x005122e0`). The true grouping for the 12.9 MB should use a1 = 0x51237B (the `new(*param_1)` site), 5 blocks. The chain 0x58444D lies in the huge FUN_00582010 (11617 bytes), which is the ONLY related function near it; it does not call 0x5122E0 (callees list does not include it), supporting "stale".

### F5. Other save-path leaks
None confirmed. Checked balanced: 0x53AF20 allocs, 0x721E70, 0x720C20/0x720CB0 (entries freed: `FUN_00722650(); FUN_009196fd(iVar1)`), 0x55BB80 (`FUN_00720c20(); FUN_009196fd(iVar1)`; `Free(); FUN_009196fd(iVar1)`), 0x55CB50 (vtable dtor), 0x529DD0 (vtable dtor at end). Not audited: 0x55B830, 0x534600, 0x8529E0, 0x7D1940 (other savers using the same CERFFile), 0x855F30 (SCREENSHOT/"savenfo"), 0x52F610 (`%s%06d - %s%sScreen`). 0x7226C0 (var alloc, string set) frees the old buffer first; fine.

### F6. The fix hook (only if F1/F2 were wrong; NOT recommended)
Hypothetical site: 0x721D92 (after `CALL 0x7225E0` at 0x721D8D). Bytes `6a00 8b4598` (PUSH 0; MOV EAX,[EBP-0x68]) = 5 bytes, no relative branches. Caveat: 0x721D92 is also the JMP target of the flag!=0 path (`00721d19 eb77 JMP 0x721d92`), where [EBP-0x10] is uninitialised, so a hook must test `CMP dword ptr [EBP+0x14],0 / JNE skip`. Free = 0x9196FD (verified above; __cdecl, 1 arg, `add esp,4`). This would double free because 0x722670 frees the same pointer at 0x721E30. Do not install.
