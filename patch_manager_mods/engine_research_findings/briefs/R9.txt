BATCH R9: name transfer for the functions touched by R1-R8.
Inputs: findings/R1..R8.md (read their function tables and every FUN_ address they mention without a confident name), inputs/gog_functions.tsv (GOG names; GOG addresses differ from Steam by a per-region delta, lesson 160: resman region +0xF66A0, WriteResource region +0xF6xxxx; texture region -0x3F2800 etc.), inputs/name_map.tsv (existing transfers), strings.tsv (string anchors: assert/error strings often name the function or class), callgraph.tsv (shape).
Method: FIRST run the GOG->Steam mapper (CONTRACT.md) for every GOG class that plausibly owns the targets (e.g. 'CAurTriangleBin|CAurTexture|CAurModel|CERFFile|CResGFF|CExoString|CExoArrayList|CSWGuiManager|CClientExoApp|CServerExoApp' - find class names in gog_functions.tsv), take `vote` rows that land on target addresses, and confirm drift rows by ret N + neighbours. THEN for each still-unnamed target Steam function, (1) look for a string anchor naming it; (2) find the nearest already-named Steam functions (name_map) in the same region and the GOG neighbourhood of their GOG names, estimate the local delta, and check the candidate GOG function at steam_addr - delta: GOG param_size_bytes must equal Steam `ret N` (header of the .c file) and neighbouring functions should also line up; (3) confirm by callgraph shape (a named callee/caller relation that also holds in GOG names) where possible.
Output: function table rows `steam_addr | proposed name | confidence | evidence (anchor string / delta + neighbours / ret-N match)`, one row per target, plus a list of targets you could not name. Do not repeat names already in name_map.tsv unless you found them wrong (flag those).
