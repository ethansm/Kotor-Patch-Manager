# R7: per-frame costs (main loop 0x407920, client MainLoop 0x781be0, render, GUI, syscalls, F1/F2)

## 5-line summary
1. F2 limiter is dormant by static evidence and the main loop (0x407e30..0x4085e3) has NO throttle at all: no Sleep on the normal path (Sleep(0) at 0x408479 only if [0xA1B704]!=0, which has no writer), so frame pacing = SwapBuffers/V-Sync only; if [0xA1B710]>0 the wait is a pure QPC spin (0x40852a..0x4085c5, no yield). Runtime proof = read [0xA1B710] and [0xA1B704] once (plus optional spin counter at 0x408550).
2. Render-bucket map churn quantified from the census: 342,961 node allocs at a2 0x473b68 (5.07/frame) + 173,236 at stale a2 0x4b5e47 (a1 0x474166 identical, so same node allocator, 2.56/frame) = 7.63 x 32 B nodes/frame (516,197 total, 16.5 MB churned); plus bucket vector doubling 118,969 allocs at 0x473f80 (1.76/frame, 8.0 MB). Each of the 3 bucket fns (0x465F90/0x4662E0/0x466700) also re-runs the O(sum w*h) texture-id scan 0x427970 (3x per frame).
3. Action-bar refresh 0x74CFE0 is driven per frame from MainLoop 0x78382E (`if (!GuiManager::Contains(hud panel)) RePopulateMainInterface`): 5834 calls; alloc counts scale exactly with it (0x77AC37 = 11,668 = 2.0x, 0x77BE55 = 20,419 = 3.5x, 0x77AB3C = 14,585 = 2.5x, 0x77BFC3 = 29,110 ~ 5.0x); ~13 heap allocs/call incl. sprintf-style "%s (%d)" strings, ~76k allocs / 1.2 MB in the run.
4. Per-frame O(n): scene render 0x499610 runs `_strcmp(name, "c_FocusGob")` for every scene object with [obj+0x84]!=0 (0x4999F4..0x499A02) plus 5 more linear walks of the scene object list; GUI manager Update/Draw (0x411870/0x4113a0) walk the panel list twice each with a nested linear IndexOf (0x410830); GlobalMemoryStatus runs 2x/frame in game via 0x478A20 (called at 0x4113A0 entry and 0x78262C) and each call also runs the texture-manager tick 0x427F30; ~17 QPC-wrapper (0x736220) calls/frame; SteamAPI_RunCallbacks + PeekMessageA once per loop iteration. No GetAsyncKeyState, no per-frame GetFileAttributes/FindFirstFile found.
5. F1: 0x798820 loop is 0x798A20..0x798A90 (`CALL 0x798C00; CMP EAX,1; JNZ exit` ... `JMP 0x798A20`), never yields; it only pumps messages at iteration 500 and, when [this+0x254]==1, pumps ONCE then never again (flag [EBP-0x20]=1 blocks the 500-branch), and it only runs in the area-finish block (flag [+0x288]) or from 0x7A0FB0/0x78E250, not every frame. Patch/hook site 0x798A87 (9 bytes, no rel): `8B 4D F0 83 C1 01 89 4D F0`.

### 6. F1: PlayMovies busy-wait loop
Loop (asm 0x798A20..0x798A90):
```
00798a20  8b4d84          MOV ECX,dword ptr [EBP + -0x7c]
00798a23  e8d8010000      CALL 0x00798c00                  ; IsMoviePlaying -> [movie+0x30]
00798a28  83f801          CMP EAX,0x1
00798a2b  7565            JNZ 0x00798a92                   ; exit when status != 1
00798a2d  817df0f4010000  CMP dword ptr [EBP + -0x10],0x1f4
...
00798a42  e8a90ac7ff      CALL 0x004094f0                  ; message pump (only at count==500 and flags clear)
00798a53  83 7d 98 01     CMP [this+0x254]==1 -> 00798a72 CALL 0x0093b550 (skip movie) ; [EBP-0x20]=1
00798a87  8b4df0          MOV ECX,dword ptr [EBP + -0x10]
00798a8a  83c101          ADD ECX,0x1
00798a8d  894df0          MOV dword ptr [EBP + -0x10],ECX
00798a90  eb8e            JMP 0x00798a20
```
No Sleep, no yield, no update of the movie player inside the loop (the status field [movie+0x30] must be advanced by another thread or callback). Message pump is reached only when the counter equals exactly 500 AND [EBP-0x14]==0 AND [EBP-0x20]==0; once `[this+0x254]==1` sets [EBP-0x20]=1 the pump never runs again, so the window stops processing messages for the rest of the movie (Alt-Tab/close unresponsive; also Wine may think the app hung). It executes only inside the MainLoop area-finish block (gated by `[this+0x288] && [this+0x18] && FUN_0078cee0()`; [+0x288] set at 0x78?? `*(undefined4 *)(param_1 + 0x288) = 1;` and cleared at end of frame `if (local_18 != 0) *(undefined4 *)(param_1 + 0x288) = 0;`) and from 0x7A0FB0 / 0x78E250. So it is not per frame in normal play; it is the one place in the engine with an unbounded spin.
Yielding patch would go at 0x798A87 (9 bytes, no relative branch): `8B 4D F0 83 C1 01 89 4D F0` -> detour that calls Sleep(1) (and optionally 0x4094F0 every N) then executes the stolen three instructions and returns to 0x798A90. Do not implement without go-ahead.
