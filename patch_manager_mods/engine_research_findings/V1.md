# V1 - Dialogue letterbox sizing (K1 "K7") on K2 Steam swkotor2.exe (sha256 6a522e71...)

Summary (5 lines)
1. K2 has the SAME mechanism as K1: bar = trunc((H - trunc(W / 2.3333330154418945)) / 2.0). The double at 0x009A7D30 (bytes `00 00 00 80 AA AA 02 40`) is read by exactly 7 `FDIV double ptr [0x009a7d30]` sites (6 sizing sites + one dead computation in 0x8BAF10). W and H are the `short`s at GUI-manager +0x6C/+0x6E, copied from the display mode `DAT_009f42a4/DAT_009f42a8`.
2. Numbers: 800x600 -> 129, 1920x1080 -> 129, 3440x1440 -> **-17**, 3840x1600 (user) -> **-22**, 5120x1440 -> **-377**. Zero at exactly 7:3; negative for any wider screen. The user's 3840x1600 is past the threshold, so the top bar target height, the bottom bar height and the NPC-line label default height are all negative.
3. K2 differs from K1 in three ways that blunt the damage: (a) the bottom bar's top edge and the reply panel are clamped with `H - max(bar, 100*fs)`; (b) the reply panel / `LB_REPLIES` heights are scaled by a width-tier factor `fs = 1 + 0.5*floor((W-1022)/1024)` (fs = 2.0 at 3840 -> 200 px panel, 196 px list), not a fixed 100/98; (c) `SetReply` replaces a negative label height with the text height. The bars themselves are NOT clamped (heights stay negative): vanilla look at >21:9 = no bars (SPECULATIVE whether a stray strip is drawn).
4. Verdict BUG (geometry, confirmed arithmetically; visible severity low-medium and SPECULATIVE until a log of the rects at conversation start). Cheapest fix = one 8-byte data write at 0x009A7D30 (c' = 1.5*W/H gives the KMRP bar = H/6), or re-point the 4-byte operand of the 7 FDIV sites. No live hook overlaps (the 4 `semi-transparent-letterbox` hooks are alpha-only and >=0xC0 bytes away from every site).
5. Dialogue GUI is NOT laid out by the GUI file alone: the engine overrides x/y/w of the panel and lists in the ctor/Reset (so the path is reached); vanilla `dialog_p.gui` (640x480 units, read from chitin.key with the repo's pykotor) has panel (48,378,544,100), LBL_MESSAGE (0,0,544,100), LB_REPLIES (0,0,544,98), and the repo's ultrawide generator does not touch it. `0x4113A0` (the lead) is the GUI-manager draw loop whose glScissor block is a 4:3 *pillarbox*, unrelated to the dialogue letterbox.

Constants not present in the dump were read from the vanilla exe `~/Games/KOTOR2_Mod_Workspace/backups/vanilla_clean/swkotor2.exe` (sha256 verified = 6a522e71631dcee9...; read-only; PE section map parsed with python, RVA = VA - 0x400000).

### B1. The constant and the formula (CONFIRMED)

Constant: `FDIV double ptr [0x009a7d30]` occurs at exactly 7 addresses (grep of all `decomp/*/*.asm`):

| site | function | asm |
|---|---|---|
| 0x008BACE9 | SetTop | `008bace9  dc35307d9a00  FDIV double ptr [0x009a7d30]` |
| 0x008BADE9 | SetBottom | `008bade9  dc35307d9a00  FDIV double ptr [0x009a7d30]` |
| 0x008BAF6E | SetFull (result dead) | `008baf6e  dc35307d9a00  FDIV double ptr [0x009a7d30]` |
| 0x008BB6A9 | DialogTop ctor | `008bb6a9  dc35307d9a00  FDIV double ptr [0x009a7d30]` |
| 0x008BB9A6 | DialogTop::SetReply | `008bb9a6  dc35307d9a00  FDIV double ptr [0x009a7d30]` |

| 0x008BC467 | DialogCinematic::Reset | `008bc467  dc35307d9a00  FDIV double ptr [0x009a7d30]` |

Value: bytes at VA 0x009A7D30 in the vanilla exe = `00 00 00 80 AA AA 02 40` -> little-endian 0x4002AAAA80000000 = **2.3333330154418945** (= the float32 2.333333f widened; one ulp under 7/3, same as K1). `0x009A7D3C` (12 bytes later) is `CSWGuiDialogTop::vftable` (`008bb61a c7013c7d9a00 MOV [ECX],0x9a7d3c`), so the double sits in .rdata just before the vtable. No other code reads 0x9A7D30 (grep of `0x009a7d30]` finds only these 7).

Other constants read: `FDIV double ptr [0x00987490]` = 2.0 (`00 00 00 00 00 00 00 40`); `FMUL double ptr [0x0098ba38]` = 100.0 (`00 00 00 00 00 00 59 40`); `FMUL float ptr [0x0098c014]` = 0.5f (`00 00 00 3F`).

Formula, SetTop (0x8BACA0), quoting decomp and asm:
```
decomp: sVar1 = *(short *)(*(int *)(param_1 + 0x1c) + 0x6e);     // H
        iVar4 = (int)*(short *)(*(int *)(param_1 + 0x1c) + 0x6c); // W

        uVar2 = FUN_0091c860(sVar1 - iVar3,iVar4);                // bar = ftol((H - X) / 2.0)
asm:    008bacd2 0fbf486e  MOVSX ECX,word ptr [EAX+0x6e]   ; H
        008bace6 db45ec    FILD dword ptr [EBP-0x14]       ; W
        008bace9 dc35307d9a00 FDIV double ptr [0x009a7d30] ; W / 2.333333
        008bacef e86c1b0600 CALL 0x0091c860                ; X = trunc
        008bacfa 2b55fc    SUB EDX,[EBP-4]                 ; H - X
        008bad00 db45e8    FILD [EBP-0x18]
        008bad03 dc3590749800 FDIV double ptr [0x00987490] ; / 2.0
        008bad09 e8521b0600 CALL 0x0091c860                ; bar = trunc

```
SetTop stores: target rect +0x68=0 (x), +0x6C=0 (y), +0x70=W, +0x74=bar; start rect +0x04=0, +0x08=0, +0x0C=W, **+0x10=0**; `[this+0x88]=1`; `_DAT_00a309b4 = [this+0x10]` (= 0) (asm `008bad8c a3b409a300 MOV [0x00a309b4],EAX`).

SetBottom (0x8BADA0): same two ftols (`008badef`, `008bae09`), then `008bae1e 89507c MOV [EAX+0x7c],EDX` (=H), `008bae31 89416c MOV [ECX+0x6c],EAX` (H - bar), `CALL 0x00479ab0` (fs), then the clamp (B3). Start rect: `+0x08 = H` (`008baecd 895008`), `+0x04=0`, `+0x0C=W`, `+0x10 = bar` (`008baef0 894810 MOV [EAX+0x10],ECX`, ECX = `[EBP-0xC]` = bar), target h `+0x74 = bar` (`008baebd 895174 MOV [ECX+0x74],EDX`), `[this+0x88]=2`, `_DAT_00a309b8 = [this+0x8]` (= H).

Rounding: both divisions go through `FUN_0091c860` = truncation toward zero (`CVTTSD2SI`, asm `0091c875 f20f2c0424`); a negative (H-X)/2 therefore rounds toward zero (e.g. -45/2 -> -22).

### B2. How W and H reach the functions (CONFIRMED)
- Panels read W/H as `short`s at `[guiManager+0x6C]` (W) and `[guiManager+0x6E]` (H), e.g. asm `008bacd2 0fbf486e MOVSX ECX,word ptr [EAX+0x6e]` and `008bacdf 0fbf486c MOVSX ECX,word ptr [EAX+0x6c]`.
- The manager pointer is `[panel+0x1C]`, lazily fetched in SetTop/SetBottom/SetFull via `FUN_0073fea0` on `[[0x00a1b4a4]+4]`: asm `008bacb2 8b0da4b4a100 MOV ECX,[0x00a1b4a4]` / `008bacb8 8b5104 MOV EDX,[ECX+4]` / `008bacc1 e8da51e8ff CALL 0x0073fea0`; `0073fea0` returns `[[client+4]+0x274]`.
- The shorts are written only by `FUN_00411a80` (`MOV word ptr [ECX+0x6c],DX` at `00411aaa`; `[ECX+0x6e]` in the same function). Its callers pass the display-mode globals: `0078dda7 CALL 0x00411a80` with `[0x009f42a8]`/`[0x009f42a4]` pushed (asm `0078dd93 8b0da8429f00 MOV ECX,[0x009f42a8]`, `0078dd9a 8b15a4429f00 MOV EDX,[0x009f42a4]`) and `0078a20f e86c78c8ff CALL 0x00411a80` (startup, same globals).

### B3. Reply panel height, clamp and width tier (CONFIRMED; this is where K2 differs from K1)

`FUN_00479ab0` (0x479AB0), asm 00479ab6-00479aff: `fs = 1.0f + 0.5f * floor(max(W - 0x3FE, 0) / 1024)` (the `CDQ/AND EDX,0x3ff/ADD/SAR 0xa` is a signed divide by 1024; arguments are non-negative here). Tiers: W < 2046 -> 1.0; 2046..3069 -> 1.5; 3070..4093 -> 2.0; 4094..5117 -> 2.5; 5118..6141 -> 3.0.

DialogCinematic ctor (0x8BBA80): panel rect (x, y, w, h) = (48, y, W-96, ftol(100*fs)):
```
asm: 008bbbd2 CALL 0x00411f30           ; margins 0x30 (x) / 0x24 (y) -> [EBP-0x2C] / [EBP-0x18]
     008bbbf6 8955ac  MOV [EBP-0x54],EDX ; rect.x = 0x30
     008bbc2b CALL 0x0091c860 ; 008bbc30 03855cffffff ADD EAX,[EBP-0xA4]=H ; 008bbc39 d1f8 SAR EAX,1
                              ; y0 = (X + H)/2          (X = ftol(W/2.333333), H - (H-X)/2)
     008bbc4c/52  rect.w = W - 2*0x30  ( [EBP-0x4C] )
     008bbc55 c745b864000000 MOV [EBP-0x48],0x64     ; base height 100
     008bbc5c CALL 0x00479ab0 ; FSTP [EBP-0x44]      ; fs
     008bbc64..008bbc8b  FILD y0 ; FILD H ; FLD fs ; FMUL 100.0 ; FSUBP ; FCOMPP ; TEST AH,0x41
     008bbc92 750b JNZ 0x008bbc9f   ; taken if (H - 100fs) <= y0
         not taken : y = y0 ; taken : y = H - 100*fs        => y = min(y0, H - 100fs)
     008bbccf CALL 0x0091c860 -> y ; 008bbcd7 FILD [EBP-0x48] ; 008bbcda FMUL [EBP-0x44] ; CALL 0x0091c860 -> h = ftol(100*fs)
     008bbd08..0x...: list rect = existing LB_REPLIES rect with h = ftol(h * fs)   (008bbd08 db45cc FILD [EBP-0x34]; 008bbd0b d84dbc FMUL [EBP-0x44])
```
FCOMPP flag reasoning: after `FILD y0; FILD H; FLD fs; FMUL 100.0; FSUBP` the stack is ST0 = H-100fs, ST1 = y0; `FCOMPP` compares ST0 with ST1; `TEST AH,0x41` (C3|C0) is zero only when ST0 > ST1, which falls through to the store of y0; otherwise the branch stores H-100fs. So y = min(y0, H-100fs). The same sequence is at Reset `008bc4a9..008bc4f6`, and in SetBottom `008bae3f..008bae8f` (there it clamps the bottom bar's top edge: `[+0x6C] = ftol(min(H - bar, H - 100*fs))`).

Vanilla `dialog_p.gui` values (read with the repo's pykotor from chitin.key; there is no `dialog*.gui` in the install's Override and `scripts/generate_ultrawide_gui_overrides.py` has no `dialog` entry): root panel (left,top,w,h) = (48, 378, 544, 100); `LBL_MESSAGE` (0,0,544,100); `LB_REPLIES` (0,0,544,98). The ctor/Reset override the root x/y/w/h and `SetExtent` 0x8BC050 forces both children's widths to the panel width, so the engine path is always reached; the file contributes only the 98/100 heights and the child x/y.

### B5. What negative bars do on this install (partly SPECULATIVE)
- Top bar (SetTop): target h `[+0x74] = bar = -22`, start `[+0x10] = 0`. Draw 0x8BB260 case 1: `if (param_1[4] < param_1[0x1d])` is `0 < -22` = false, so `param_1[0x23] = 1` (animation done at once) and `local_10 = param_1[0x1d]` = -22 is passed to the vtable `+4` SetExtent (asm `008bb260` body; decomp lines `local_10 = param_1[0x1d]; if (param_1[4] < param_1[0x1d]) {...} else { param_1[0x23] = 1; } (**(code **)(*param_1 + 4))(&local_1c); _DAT_00a309b4 = param_1[4];`). The panel is therefore given a rect with height -22. Whether the fill quad is clipped, drawn flipped (above the screen for the top bar: invisible) is **SPECULATIVE**; I did not read the control SetExtent/draw.

## (e) Verdict

**V1 (dialogue letterbox sizing): BUG** (geometry confirmed; visible severity UNCLEAR/low-medium on this install until the rect log).
- Decisive arithmetic: bar = trunc((H - trunc(W / 2.3333330154418945)) / 2.0) (`008bace9`, `008bade9`; constant bytes `00 00 00 80 AA AA 02 40` at 0x9A7D30). 3840x1600 -> X = trunc(1645.714) = 1645, bar = trunc(-45/2) = -22; 3440x1440 -> -17; 5120x1440 -> -377; 1920x1080 and 800x600 -> 129.
- Mitigations already in K2 (so the K1 symptom "subtitle and replies vanish" is probably NOT present): bottom edge/panel clamp `H - max(bar, 100fs)` (`008bae64..008bae8f`, `008bbc92`), NPC label height replaced by text height (`008bb97e`), reply panel scaled with `fs` (`00479ab0`).
- Still wrong: negative target heights are stored (`008bad48 MOV [ECX+0x74],EDX`, `008baebd MOV [ECX+0x74],EDX`, `008baef0 MOV [EAX+0x10],ECX`), the letterbox disappears at > 21:9 (by design of the 7/3 band: bar = 0 at exactly 7:3), and possibly a stray strip is drawn (SPECULATIVE).

Hook feasibility (for the BUG):
- **Fix A (preferred, data):** write the double `1.5*W/H` over 0x009A7D30 (8 bytes; `.rdata`, needs VirtualProtect). `original_bytes = 00 00 00 80 AA AA 02 40`. W,H known at start and on resolution change (`0x78DBF0`, `0x411A80`); the six sizing sites run at dialogue show / `ResetInterfaceForSize`, so one write after the mode is set is enough; bar becomes trunc(2H/3)... = H/6 exactly (rounding of the double division could give X off by 1, same bar after truncation in the 5 test cases). No branch or instruction is touched; shared by all 7 readers (the 7th, 0x8BAF6E, is dead). Fix sketch: constant rewrite. Variant "keep vanilla below 21:9": write 7/3 when `W/H <= 7/3`, else 1.5*W/H.
- **Fix B (code, per site):** rewrite the 4-byte absolute operand of each of the 7 `FDIV double ptr [0x009a7d30]` instructions (6 bytes `DC 35 30 7D 9A 00`; one whole instruction, no relative branch, instruction boundary) to point at a DLL-owned double. Sites and file offsets: 0x008BACE9, 0x008BADE9, 0x008BAF6E, 0x008BB6A9, 0x008BB9A6, 0x008BBC25, 0x008BC467 (each `original_bytes = DC 35 30 7D 9A 00`; the operand to change is the last 4 bytes). Use this if the .rdata page must not be written.
- Optional companion: keep `fs` scaling (`0x479AB0`) as is; for 5120x1440 raise the bar or cap `fs` (not needed for the user's 3840x1600).
- **Live-hook overlap:** none (+-8 bytes) with `live_hooks_2026-09-30g.tsv` (see B7).
