Static only. ROOT = `~/Games/KOTOR2_Mod_Workspace/ghidra_dumps/steam_6a522e71/`. Builds on R5 (GUIID, TD), T3 (SS), V6 (TD binary/text), CONTRACT Phase 6. ## Summary (5 lines)
1. GUIID: `0x40F620` pads the panel control list with NULLs up to the control's GFF `ID` (`while (*(param_1+0x28) < iVar6) FUN_0083ea60(0);`), no upper bound; id 0x7FFFFFFF doubles the list 16,32,... (4 B/slot) until a ~2 GB `new` throws bad_alloc = process death. Live data: 52 loose GUIs, 1378 control ids, max 150 (vanilla `equip_p.gui` 48). FIX: 6-byte in-place patch at `0x40F972` (`83 7D B0 00 7C 6C` -> `C1 E9 0C 75 6D 90`) rejects id >= 4096 (and negatives) through the existing negative-id exit `0x40F9E4`.
2. SS-a: `WriteTGA 0x482BD0` never NULL-tests `_fopen` (`0x482C28`/`0x482C30`); the first `_fwrite(...,NULL)` goes `__invalid_parameter` -> `__invoke_watson` = process termination. All callers are `void` and ignore failure. FIX needs a code cave (7 stolen bytes `0x482C30..0x482C36` -> `E9 rel32 90 90`; cave = store, `TEST EAX,EAX`, `JNZ +2`, `LEAVE; RET`, `PUSH EAX`, `JMP 0x482C37`). Trigger realism LOW (read-only/missing directory, disk/permission failure).
3. SS-b: `CaptureScreenToTGA 0x4289D0` derefs a NULL camera (`0x428B71..0x428B7C`) if `FindObject("camera")` fails: FIX = 2-byte patch `74 11` -> `74 55` at `0x428B31` (skip the camera re-render). SS-c: output dims `[EBP-0xC]/[EBP-8]` are uninitialised when padded viewport width <= height (`0x428AE8 JLE`): FIX = NOP the 2-byte JLE (`7E 2D` -> `90 90`). Both LOW realism (save path always has a camera; w <= h means a square/portrait window); F-key path `0x428D70` has neither defect and is gated by `DAT_00a106bc` (no writer found).
4. TD: `C2DA::NextToken 0x71C180` has NO destination bound (only the remaining-input bound `*param_2`); its ONLY caller `0x71C3D0` passes the same 256-byte buffer `[EBP-0x12C]` at all 8 sites, and the stack cookie IS present in `0x71C3D0` (`0x71C3E7`..`0x71C3EE`, check `0x71CF76 CALL 0x009196ee`), correcting R5's "unknown". Token >= 256 chars first overwrites the cookie (index 256..259), >= 0x120 chars the SEH record. Text-format 2DAs only (all 424 vanilla + 37 live override 2DAs are binary), except a >255-char COLUMN NAME which overflows on both paths (V6).
5. TD FIX (no cave, no behaviour change for tokens <= 255): rewrite the two 37-byte store+advance blocks (`0x71C243..0x71C267`, `0x71C2C9..0x71C2ED`) so the dst pointer advances with `CMP dword [EBP-8],0xFF` + `ADC dword [EBP+0x10],0` (CF = len < 255): longer tokens keep their first 255 chars, the cell index 255 holds the NUL, and the whole token is still consumed (no re-tokenising of the tail, so column alignment is preserved).
