# V5: QueryPerformanceCounter / QueryPerformanceFrequency / timeGetTime / GetTickCount, and whether any K2 frame-pacing path depends on counter magnitude (lead L7, Peixoto's Jade Empire fix)

Static analysis only (ROOT = `ghidra_dumps/steam_6a522e71/`, vanilla exe constants read read-only). Format per CONTRACT + V_BRIEFS (e) Verdict, (f) Unnamed functions.

## 5-line summary
1. VERDICT NO BUG for frame pacing: all 7 QPC/QPF import sites are accounted for; every one that matters funnels through ONE wrapper `Timer::Now` 0x73B810 (via 0x736220, 91 call sites in 44 functions) which returns a **64-bit integer in microseconds** (`FILD qword counter; FMUL double (1e6/freq); _ftol2-style 0x91C896`, 0x73B834-0x73B83D). No K2 code converts an absolute counter to float32 or to a 32-bit value and then differences it.
2. Frame dt is a DELTA: world clock Update 0x51A860 accumulates `(QPC_now - QPC_last) * scale / 100` in 64-bit (`SUB ESI,[ECX+0x1C] / SBB EDI,[ECX+0x20]`, 0x51A89E-0x51A8A4), MainLoop 0x781BE0 reads `GetDelta 0x51A940` (cur - prev) and does `FILD dword / FDIV 1e6 -> float [0x9F62B0]` (0x782519-0x782525). The frame-limit spin (0x407920 0x40852A-0x4085C5) subtracts two int64 values first (0x40805F-0x4080B7 pattern) then multiplies by 0.001 in x87 and stores a float of a SMALL ms delta. Peixoto-style "make QPC relative to process start" would be a no-op here.
3. K2 does have its own timer-source selection: ctor 0x73B720 `QueryPerformanceFrequency` success -> mode 1 (QPC); failure -> `Now()` falls back to `GetTickCount()*1000` (0x73B856-0x73B861). It never picks timeGetTime for pacing; timeGetTime (3 sites) is FPS-overlay + one cosmetic pulse (0x46C2C7), GetTickCount (20 sites) is RNG seed / 32-bit ms stamps.
4. Real (but non-pacing) magnitude limits found: (a) 0x650D40 `QPC*1000000` in `__allmul` overflows int64 at QPC >= 9.22e12 (10 MHz: 10.7 days since QPC origin; 3 GHz: 51 min) - profiling stat only, no reader of the result float [0xA7E0F8]; (b) ~25 sites store `Now()/1000` as 32-bit ms (wrap 49.7 d) and use modular `now - prev` (safe) while 3 sites (0x880510, 0x8805A0, 0x87FE20) compare absolute `GetTickCount` ms with `start+dur` (wrap-unsafe once per 49.7 d of host uptime; UI timers); (c) 0x51A860 uses unsigned `__aulldiv` on a possibly-negative product (non-monotonic QPC would give a dt spike; SPECULATIVE trigger).
5. Perf-lab measurement is optional (NO BUG verdict is static-complete): log QPF value + first QPC at 0x73B744/0x73B82B and the post-frame dt at 0x78259F to confirm freq (expected 10 MHz, SPECULATIVE) and monotonic, magnitude-independent dt. Section (c).

### 3. Frame dt and pacing consumers (answers the Peixoto question)

**3a. Gameplay dt (world clock).** Per frame 0x781BE0 calls Update 0x51A860 at 0x7823A8 / 0x7823C9 / 0x7823D7 (callgraph.tsv), then reads GetDelta:
```
0078250e CALL 0x0051a940 ; 00782513 MOV [EBP-0x2d0],EAX ; 00782519 FILD dword [..] ; 0078251f FDIV double [0x00996518] ; 00782525 FSTP float [0x009f62b0]
decompile: iVar5 = FUN_0051a940(); _DAT_009f62b0 = (float)iVar5 / (float)_DAT_00996518;      (line 225-226 equivalent at 0x782588/0x78259F)
```
GetDelta = `cur - prev` (0x51A940: `iVar1 = *(uint *)(param_1 + 0xc) - *(uint *)(param_1 + 0x14);`), where Update first does `+0x14 := +0xC` (asm 0x51A871-0x51A87A) then `+0xC += delta`. Update's increment (asm):
```
0051a89b MOV ESI,[EBP-8]  0051a89e SUB ESI,[ECX+0x1C]  0051a8a4 SBB EDI,[ECX+0x20]      ; 64-bit QPC_now - QPC_last (us)
0051a8b2 CALL 0x0091fc30 (__allmul: delta * scale(+8, default 100))   0051a8bd CALL 0x0091d220 (__aulldiv /100)
0051a8c5 ADD EAX,[ECX+0xC]  0051a8cb ADC ECX,EDX  0051a8dc MOV [EAX+0x1C],ECX ...        ; clock += ; last = now
```
Everything is a 64-bit integer difference of two Now() values before it ever touches a float; the float (`[0x9F62B0]`) is `(float)(int)(delta_us)/1e6`, i.e. seconds of one frame (e.g. 16667 us -> 0.016667). Conversion of the absolute value to float never occurs on this path. **Initial value:** ctor 0x51A770 seeds +0xC/+0x10 with `Now()` (absolute us since QPC origin) and +0x1C/+0x20 with a second `Now()`; so the world clock STARTS at an absolute magnitude, and consumers that use the clock itself (0x51A920) do integer math only: 0x51AC30 (`__aulldiv(clock,1000)`, `__aullrem/__aulldiv(ms, +0x3C)` where +0x3C = hours-per-day*0x15F900 ms, 0x51A800), `printf("%d ...", ms)` loggers (0x40A160, 0x40A460, 0x774BC0, 0x781840), and `*(undefined8*)(clock2 + 0x14) = 0x51A920()` copies (0x781FB2.. etc.). No float conversion of the clock (all 19 callers of 0x51A920 read via callgraph; none converts to float). Calendar base is re-anchored against the same clock (0x51AC30), so the initial offset cancels (`*(int *)(param_1 + 0x30) = param_2 - iVar2;` then reads add the clock back); how a SAVED game's base interacts with a different clock origin on the next process is `speculative` (not pacing, not examined).

### 5. timeGetTime pulse (0x49CC50) - the only place a Windows-uptime ms value feeds a float
```
local_7c = (uint)(longlong)ROUND((double)DAT_00a73688 / _DAT_00989ec0);          // 0x49CCFD FILD qword (hi=0) ; 0x49CD00 FDIV double [0x989ec0] = 8.0

local_14 = (float)fVar1 * (float)_DAT_0098c1d8 + (float)_DAT_009875a8;           // 0.25 * sin + 0.75
```
`DAT_00a73688` is set once per Scene::Render (0x46C2C7). The ms is widened to double (exact), divided, rounded, masked to 8 bits **before** the float multiply, so the float only ever sees 0..255; wrap of timeGetTime at 2^32 ms changes the pulse phase once. Cosmetic (a 0.5..1.0 alpha/brightness pulse), not pacing.

### 6. Does any frame-pacing path depend on QPC magnitude?
No. Enumerated pacing/dt consumers: (i) world clock dt (3a) - 64-bit difference first; (ii) F2 limiter (3c) - 64-bit difference first, only the single epoch=0 pass sees the absolute value and it errs toward "exit"; (iii) V-Sync/SwapBuffers (R7) - not timer based; (iv) section timers (3b) - display only; (v) time-budget loops (3d) - deltas. The mechanism in Peixoto's Jade Empire case (a large absolute QPC in a lossy conversion before subtraction) has no K2 counterpart: the only absolute-to-narrow conversions are `/1000` to 32-bit ms followed by modular subtraction (3e), the 8-bit-masked timeGetTime pulse (5), and the profiling `*1e6` int64 overflow (4). Making QPC relative to process start would therefore not change K2's frame rate (a "relative QPC" shim would also shift the world-clock seed 0x51A770 and the 0x5363A0 stamps, equally harmless).

Residual pacing-adjacent risk (not magnitude): 0x51A860 uses unsigned `__aulldiv` on `delta*scale`: a **negative** QPC delta (non-monotonic counter across cores/VM) becomes ~1.8e17 after `/100`, whose low 32 bits then feed `(float)iVar5 / 1e6` as a garbage dt for that frame. Whether Proton's QPC can step backwards is SPECULATIVE (Wine implements QPC from a monotonic clock; no evidence here).

## (e) Verdict
- Q1 "any frame-pacing path whose behaviour depends on QPC magnitude?": **NO BUG**. Decisive code: `Now()` returns int64 us (0x73B834-0x73B83D); dt = `cur - prev` in 64-bit (0x51A89E-0x51A8A4, 0x51A940) then `(float)(int delta)/1e6` (0x782519-0x782525); limiter and section timers subtract int64 first (0x40805F-0x4080B7, 0x4084DE-0x408524). Arithmetic: counter 1.008e12 (28 h @ 10 MHz) -> 1.008e11 us, exact in double (< 9.0e15) and in int64; a float32 of that would have ulp 8192 us, but no such conversion exists.
- Q2 "timer-source selection exists?": **found**: QPF success -> QPC else GetTickCount*1000 (0x73B72D / 0x73B73E / 0x73B856); timeGetTime is never the pacing source.
- Q3 "Peixoto's fix (QPC relative to process start) transferable to K2?": **NO BUG / not applicable** (K2 already differences in int64).
- Q4 profiling clock 0x650D40: **minor BUG (cosmetic, harmless)**: `QPC*1e6` int64 overflow at QPC >= 9.22e12 (10 MHz: 10.7 days; 3 GHz: 51 min); result float has no reader. Not worth a patch.
- Q5 absolute 32-bit GetTickCount comparisons (0x880510, 0x8805A0, 0x87FE20): **latent, UNCLEAR** impact (UI timers, 49.7-day uptime wrap only; Wine origin SPECULATIVE).
- Q6 negative-QPC-delta dt spike at 0x51A860 (`__aulldiv` unsigned): **UNCLEAR** (needs a non-monotonic counter; SPECULATIVE).
