## Wine harness for hooks that read fixed engine addresses (`harness/smoke_probe13.cpp`)
Wine fills 0x810000-0xB4A000, so `VirtualAlloc` at 0xA1B000 fails (487). Trick: link the harness exe dynamically at the default base with a 7 MB `.bss` array so its own image covers 0x400000-0xB00000 (engine globals and a stub at 0x40BCF0 become ordinary memory; `VirtualProtect` the stub page RWX); `-static-libgcc -static-libstdc++` (a plain dynamic MinGW exe dies silently under WINEDEBUG=-all). Never call `GetWindowText` on a window of the same process from a watchdog thread (blocks on the stalled main thread).


### perf-lab 0.2.0 harness (`harness/smoke_perflab2.cpp`)
Same `.bss` trick, but the harness must NOT link libstdc++ statically: that grows `.text` past 0x4261CF and the TX experiment would patch the harness's own code (check `objdump -h`: `.bss` must start below 0x420000). Build `i686-w64-mingw32-g++ -O1 -o smoke_perflab2.exe smoke_perflab2.cpp -lgdi32 -lglu32` and copy `libstdc++-6.dll`, `libgcc_s_dw2-1.dll` (`/usr/lib/gcc/i686-w64-mingw32/13-win32/`) and `libwinpthread-1.dll` (`/usr/i686-w64-mingw32/lib/`) next to it (the DLLs present, a dynamic exe runs fine). Run `smoke_perflab2.exe off`, `refuse`, `run` (each exit 0). Result 2026-09-30 (kpatch DLL md5 `cac5201b1c02b69b6a13556f3fb02792`): all pass; handler cost bucket/movie 6 ns, GetImage 26 ns, resman hooks ~0.8-1 us (SafeRead VirtualQuery of the key entry; thousands of calls per load = a few ms).

## perf-lab 0.3.0 (Phase 4, 2026-09-30)
Source `perflab/` (39 hooks: the 17 of 0.2.0 + 22 counters from batches U1/U4/U5/U6; sites and operands are commented in `kotor2-steam-aspyr.hooks.toml`). New keys in `perflab_debug.txt` (each defaults to the value of `metrics`): `live`, `br`, `kt`, `vm`, `misc`. New lines in every `perflab_metrics.txt` block:
- `HOOKCOST_BY <handler> calls= cycles= samples=`: handler-body cost per hook (rdtsc, 1 in 64 sampled; the KPM wrapper is not included). In run A the 0.2.0 average was ~6,100 cycles, likely the SafeRead VirtualQuery in the resman hooks (`beginScope()` clears the region cache on every call).
- `LIVE textures= gl_bytes_est= models= mesh_node_bytes= gob_instances= node_objects= scenes= focus_dummies= emitters=`: engine globals 0xA1BBE0/0xA1BBA0/0xA1FFAC/0xA1DEE0/0xA1FF68/0xA1FF60/0xA200F4/0xA20030/0xA7BD28.
- `NAMES <table> distinct= overflow=` + `NAME <table> <count> <name> ra=<caller>` (top 32), tables `tga_load` (resman TGA Malloc by key-entry resref), `build` (BuildAndStoreTexture by texture name +0x7C), `gui_setter1/2` (0x414870/0x4160BD), `tex_miss` (0x427609), `txi_via_tpc`, `script`; `BRRING <tick> <table> <name> ra=` = last 64 BR events (the first lines of a burst name the culprit).
- `KT async_start async_bytes destroy_table still_in_demand uaf_write release_ok txi_via_tpc unload`, `TEXLIFE requeue requeue_built freeimage freeimage_tpc freeimage_tpc_buf freeimage_tga_buf tex_dtor`, `REQUEUECALLER ra n`.
- `VM run_script exec_cmd exec_bad_id instr_limit delay_cmd adc_enter adc_handoff adc_leak_upper`, `VMCMD id:count ...` (16 most used command ids).
- `NET send bytes max_len ovf_test ovf_hit | SCENE focus_dummy scene_dtor`.
- A metrics block with event `UNLOAD` is written at every server UnloadModule (0x5315E0), and `perflab_log.txt` now prints the experiment-site bytes even when tx/g1skip are off.
