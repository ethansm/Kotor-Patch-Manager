## Wine harness for hooks that read fixed engine addresses (originally `smoke_probe13.cpp`, now `harness/retired/`; the same trick is used by probe14 and the others)
Wine fills 0x810000-0xB4A000, so `VirtualAlloc` at 0xA1B000 fails (487). Trick: link the harness exe dynamically at the default base with a 7 MB `.bss` array so its own image covers 0x400000-0xB00000 (engine globals and a stub at 0x40BCF0 become ordinary memory; `VirtualProtect` the stub page RWX); `-static-libgcc -static-libstdc++` (a plain dynamic MinGW exe dies silently under WINEDEBUG=-all). Never call `GetWindowText` on a window of the same process from a watchdog thread (blocks on the stalled main thread).


### perf-lab 0.2.0 harness (`harness/smoke_perflab2.cpp`)

Build `i686-w64-mingw32-g++ -O1 -o smoke_perflab2.exe smoke_perflab2.cpp -lgdi32 -lglu32` and copy `libstdc++-6.dll`, `libgcc_s_dw2-1.dll` (`/usr/lib/gcc/i686-w64-mingw32/13-win32/`) and `libwinpthread-1.dll` (`/usr/i686-w64-mingw32/lib/`) next to it (the DLLs present, a dynamic exe runs fine). ## perf-lab 0.4.0 (hwmip=1, hardware mipmaps; W2/M1 in `../engine_research_findings/W2.md`)
Key in `perflab_debug.txt`: `hwmip=0|1` (default 0, parsed like `tx`). The attach line prints `hwmip=ON|OFF`; the `#METRICS` header gets ` hwmip=<0|1>` appended at its end. Experiment, off by default.
- **Install.** The gluBuild2DMipmaps IAT hook (all 4 engine call sites go through thunk 0x93B430 -> IAT 0x986024) is installed once by `installGluHook()` when `metrics=1` OR `hwmip=1` (so `hwmip=1` works with `metrics=0`). `patchIat` writes the original into `rGluMip` BEFORE it flips the IAT slot, so the hook can never run with `rGluMip == NULL`; a second install is a no-op. `perflab_log.txt` gets `hwmip: gluBuild2DMipmaps IAT hook ON|FAILED`.
- **Behaviour (hwmip=1).** Eligible = w,h > 0 and powers of two, both <= GL_MAX_TEXTURE_SIZE, type GL_UNSIGNED_BYTE (0x1401), target GL_TEXTURE_2D (0x0DE1) or a cube face (0x8515..0x851A), data != NULL. Otherwise the real GLU call runs (counted by reason). 2D: drain glGetError (max 16), `glTexImage2D(level 0)` + `glGenerateMipmap(0x0DE1)`; without glGenerateMipmap: `glTexParameteri(0x0DE1, GL_GENERATE_MIPMAP 0x8191, 1)` before the upload and `0` right after (the engine's later glTexSubImage2D path 0x4337B0 must not regenerate). Any GL error after the sequence: `hwmip_glerror`++ and the real GLU call re-uploads every level. Entry points are resolved lazily on the first eligible call (render thread, context current): glTexImage2D / glTexParameteri / glGetError / glGetIntegerv from opengl32.dll, glGenerateMipmap (else glGenerateMipmapEXT) via wglGetProcAddress (NULL and 1,2,3,-1 = unavailable), GL_MAX_TEXTURE_SIZE (0x0D33) cached; if that fails hwmip permanently falls back to GLU (`hwmip_fallback_nogl`, logged once). Return value: 0 on the HW path, GLU's value on fallback. The mipN/mipQpc/mipPixels timing wraps both paths. hwmip=0: straight `rGluMip`, as in 0.3.0.
- **Cube maps.** No deferred replay is possible (the pixel pointers die at return) and a deferred `glGenerateMipmap(0x8513)` would leave the cube without mips whenever a face fell back, the set was incomplete, or the generate failed. So every cube face (0x8515..0x851A, any order) is a self-contained call, with or without glGenerateMipmap: if eligible, drain errors, `glTexParameteri(0x8513, GL_GENERATE_MIPMAP, 1)`, `glTexImage2D(face, level 0)`, `glTexParameteri(0x8513, GL_GENERATE_MIPMAP, 0)`; GL 1.4 regenerates the levels of the face just modified, so each face is complete when its call returns. Ineligible faces, and faces with a GL error after the sequence, go to the real GLU call for that face only (all its levels). No state is kept between calls and `glGenerateMipmap(0x8513)` is never called.
- **Counters** (plain globals, independent of `metrics`): `hwmip_calls` (every hook call while hwmip is on), `hwmip_hw` (2D uploads done on HW only; cube faces count in `hwmip_cube`), `hwmip_fallback_npot` (also w/h <= 0), `_size`, `_type`, `_target`, `_null` (data == NULL; own counter), `_nogl` (GL entry points unavailable), `hwmip_glerror` (HW sequence errors, 2D or cube face), `hwmip_cube` (cube FACES done on HW), `hwmip_cube_fallback` (cube faces that went to GLU for any reason, ineligible or GL error; the reason is also counted in its own counter). They are appended, as ` key=value`, in that order, to the END of the `GL ...` metrics line (always, zeros when hwmip is off; existing fields and order unchanged) and logged as `HWMIP <event> hwmip_calls=.. hwmip_hw=..` in `perflab_log.txt` at every metrics write and at every FLUSH, so `hwmip=1, metrics=0` is observable. One-time event lines: `HWMIP GL resolved: ...` (which entry points, which path, max size), resolve failure, first GL error fallback.
- **Fix found while testing:** with `alloc=0`, `writeReport()`/`writeSnapshot()` dereferenced the NULL site table at the first flush (helper thread crash); both now return early when no table exists.
- **Harness** `harness/smoke_hwmip.cpp` (modes `run` = hwmip=1 metrics=0, `metrics` = hwmip=1 metrics=1, `off` = metrics=1 only = 0.3.0 behaviour, `bare` = nothing hooked). It calls `gluBuild2DMipmaps` through its own IAT with stub GL entry points and a stub for the real GLU function injected by the harness-only exports `PerfLabTestSetGl` / `PerfLabTestHwmipCounters` / `PerfLabTestRGluMip` / `PerfLabTestResolveEntries` (in `exports.def`, inert in the game; the stubs log calls in order). Cases: 2D POT, NPOT, NULL, over-max size, GL error after the upload and from glGenerateMipmap, cube faces in both engine orders with and without glGenerateMipmap (per-face texparam sequence, no generate call), cube faces with an NPOT / erroring / NULL / wrong-type face (GLU for that face only), cube faces interleaved with 2D calls, 2D texparam path, type/target mismatch, stale-error drain, header/GL-line formats, HWMIP log lines, `rGluMip` ordering. Build and run as for 0.2.0 (`-lgdi32 -lglu32`, no .bss pad needed).

## perf-lab 0.5.0 (measurement only; 53 hooks = the 46 of 0.4.0 + 7 EVT detours)
Everything below is a counter or a copy on a hook, formatted by the helper thread (hooks never do I/O; every engine pointer goes through SafeRead). New group key `ev` in `perflab_debug.txt` (default = value of `metrics`; `ev=0` switches off EVT, TPCTOP and RESTOP). Tags are exactly `MOD`/`module=`, `EVT`, `TPCTOP`, `RESTOP`, `VA`, `HWV`, `HWVFB` (the analyzer drops `NAME`, `VQ `, `RES `, `G `, `# `, `VMCMD`, `*CALLER`). Existing lines only grew at the END.
- **MOD** (no hook): every `#METRICS` header ends with ` module=<name>`: `app=*(0xA1B4A4)`, `client=*(app+4)`, `internal=*(client+4)`, `mod=*(internal+0x18)`, name = CExoString c_str at `mod+0x38`, at most 31 printable chars. `-` = no module (main menu) or empty name, `?` = chain unreadable (e.g. before the app exists).
- **EVT** (7 detours, entry prologues checked with `hookbytes.py`): server SaveGame 0x52F610 (`save`: `[esp+4]` int slot, `[esp+8]` CExoString* name), server LoadGame 0x52FB80 (`load`: slot, name; `[esp+0xC]` module CExoString* is not recorded), QuickLoad 0x7D0F50 (`qload`), QuickSave 0x7A06B0 (`qsave`), DoPCAutosave 0x53AF20 (`autosave`), OptionsSave 0x740B40 (`optsave`), SoundOptionsApply 0x70B9B0 (`sndapply`); QuickLoad, QuickSave, DoPCAutosave, OptionsSave and SoundOptionsApply take no parameters (slot=-1, name=-). Each handler: counter + a 64-entry ring `{seq, tick (GetTickCount), kind, slot, name[32]}`; the producer index is `InterlockedIncrement`, `seq` (index+1) is stored last, so the helper skips half-written entries. Per metrics block: `EVT kind=<k> tick=<t> slot=<s> name=<n|->` for every entry new since the previous block, then `EVT counts save= load= qsave= qload= autosave= optsave= sndapply=` (cumulative; ` lost=<n>` appended only when more than 64 events arrived between two blocks or an entry was overwritten while being read). Names are cut at 31 chars, non-printable bytes become `?`. With `ev=0` or `metrics=0` the handlers return before touching anything. **Never hook 0x73F6F0 (4-byte prologue).**
- **TPCTOP / RESTOP**: a pointer-keyed open-addressing table (16384 slots, 512 KB, VirtualAlloc'd at attach; usable live capacity 15872) of `{CRes, size = *(CRes+0x18), restype, resref[17]}`. Insert in `PerfLabResMalloc` (resref = the 16 bytes at `*(CRes+0x14)`, NOT NUL-terminated, lower-cased; restype `-1` when there is no key entry), removal in `PerfLabResFreeData` after the engine's own "really frees" test (same pair that drives `RT resident`). A spinlock (`InterlockedCompareExchange`, spin then `SwitchToThread`) guards every access because the Malloc callers are not proven main-thread-only; a removal whose next slot is empty turns the slot and any tombstones before it back into empty slots, so tombstones do not accumulate. Inserts past the capacity or whose probe (max 1024) finds no slot count in `overflow` and are dropped (a later free of such a CRes finds nothing). The table is written only in the `LOAD_DOWN` (load-screen DOWN edge) and `UNLOAD` (server UnloadModule) blocks: the helper copies the live entries into a scratch buffer under the lock (one scan of the table) and sorts outside it. Lines: `TPCTOP n=<TPC count> total_mb=<x.y> [overflow=<n, cumulative>]`, up to 20 `TPCTOP <rank> kb=<size/1024> name=<resref>` (restype 3007, size descending, name as tie-break), up to 10 `RESTOP <rank> type=<restype> kb=<k> name=<resref>` across all restypes. `n`/`total_mb` are over TPC entries only.
- **VA**: every block (also `vq=0`): `VA free_mb= largest_free_mb= largest_free_at=0x%08x commit_mb= reserve_mb= regions=` (all regions, any state). It reuses the VirtualQuery walk of the VQ census (`scanVq`, shared with `writeVq`, whose lines are unchanged); with `vq=0` the walk still runs once per block (a few ms).
- **Ledger fields appended at the end of existing lines**: `RT ... redemB` (bytes of 60 s re-demands per restype; restype 4 = WAV churn); `KT ... txi_via_tpc_kb=` (the TXI hook 0x93BEA6 now also takes `[ebp-0x12C]` = the TPC resource wrapper found at 0x93BE6B; `wrapper+8` = its CRes, `CRes+0x18` = size, so this is the size of the whole TPC demanded to read its embedded TXI; NULL/unreadable wrappers add nothing); `BUILD ... requeue_tpc_retained_kb=`: **+0x44 on the texture is the raw pixel buffer, not an owner CRes**, so the size is derived with FreeImage's own formula (0x425160): level 0 = `[+0x5C]` bytes, each further level of the s16 mip count at `+0xD2` adds `ceil(w/4)*ceil(h/4)*blk` (w=`+0x68`, h=`+0x6C`, blk = 8 for format `[+0x74]==3`, 16 for 4; height/width == 6 means cube map: face height = h/6, total x6). Any other layout (format, `[+0x5C]` 0) counts 0 bytes while the count still increments, so the kb is a lower bound. `FRAME ... gms_calls= gms_ms=`: the exe imports `KERNEL32!GlobalMemoryStatus` (IAT 0x986128, called from the per-frame function 0x478A20 and from 0x711360), so it is IAT-hooked with metrics=1 (count + QPC time of the real call).
- **HWV** (hwmip=1): `HWV fmt_rgba= fmt_rgb= fmt_la= fmt_l= fmt_other= lvl1_ok= lvl1_bad= lvl1_first_bad=<target>/<w>/<got>` (`-` when none; targets hex) and `HWVFB <i> reason=<npot|size|type|target|null|nogl|glerror> target=0x.. w= h= fmt=0x.. type=0x..` for the first 8 calls that went to GLU. Format counts cover uploads that completed on the HW path (2D and cube faces). Level-1 check: right after a successful HW upload, in the same intercepted call and with the texture still bound, `glGetTexLevelParameteriv(target, 1, GL_TEXTURE_WIDTH)` (cube: the face target) must equal `max(1, w/2)`; first 16 uploads only, 1x1 skipped, followed by a `glGetError` drain; pure queries only, never a state change or deferred GL work. The function is resolved once from opengl32.dll (`GetProcAddress`); without it the check is off (counts stay 0). Written next to the HWMIP lines (`perflab_log.txt`, so also with metrics=0) and into the metrics block right after the `GL` line.
- **Harness** `harness/smoke_perflab5.cpp` (modes `run` / `off` / `noev`; row `perflab5` in `smokes.toml`): fake client chain with 2 module names / NULL module / unreadable chain, every EVT export with fake CExoStrings (ring, new-only listing, 100-event overrun -> `lost=36`), TPCTOP ordering / removal / tombstone churn / overflow (17000 live) / 4-thread storm with concurrent snapshots, VA with vq=0, ledger fields, HWV with a stub `glGetTexLevelParameteriv` (harness-only export `PerfLabTestSetGetTexLevel`, since `GetProcAddress(opengl32)` cannot be faked) incl. level-1 ok/bad, 1x1 skip, 16-check cap, 8-fallback cap and exact stub call order. - **Registry interfaces** (A-ids) use the RFC #180 registry from [`19_shared_logging_design.md`](../19_shared_logging_design.md). Call `require` lazily at first use, and keep the current local code as the fallback when the provider is not installed.
- **Common helpers** (B-ids) live in `Patches/Common` on the KPM fork. Edit them in `patch_manager_mods/_shared_src/` and sync with `scripts/check_shared_headers.py --sync`. New code includes `"SafeRead.h"`, not `"../_shared/SafeRead.h"`.
- **Rollout:** shared pieces are consolidated on our fork first. Each one goes upstream inside the first mod PR that uses it, so order this mod's PR after the PR that introduces anything it reuses. Migrating this patch needs its owner's go.
- **Logging:** move to `KpLog.h` channels and `kplog.ini` (doc 19 Phase 6). Keep the tag text exactly as it is, because the parsers depend on it.
- **A3 `k2.enginestate` (consumer):** the load-screen poll (`PerfLab.cpp:59-61`, `:723-753`, every 100 ms from the helper thread) duplicates the load-hang probe's. Use `require("k2.enginestate")` when present.
- **A4 event source:** the ApplyEffect/RemoveEffect hooks (0x544210/0x544640) could feed `k2.effects`, so the buff HUD stops polling.
- **B5 code-patch helpers:** `writeCode` (:445), `patchIat` (:234), and the TX cave builder (:460-475) shared with texture-memory-release.
- **Hand-coordinated sites (keep documented until a registry query replaces them):** robustness skips 0x726505 because of perf-lab's 0x72650B; perf-lab `tx=1` and texture-memory-release both write 0x4261CF (the second writer is refused by byte verification).
