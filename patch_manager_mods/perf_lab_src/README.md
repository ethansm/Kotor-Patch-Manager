## Full static dump (Phase 2, dump once then analyse text in parallel; ~5 min total)
Root `~/Games/KOTOR2_Mod_Workspace/ghidra_dumps/steam_6a522e71/` (outside the repo, ~0.5 GB). Scripts in `ghidra_scripts/`, all read-only, one headless run can chain several `-postScript X.java args`:

## Wine harness for hooks that read fixed engine addresses (originally `smoke_probe13.cpp`, now `harness/retired/`; the same trick is used by probe14 and the others)
Wine fills 0x810000-0xB4A000, so `VirtualAlloc` at 0xA1B000 fails (487). Trick: link the harness exe dynamically at the default base with a 7 MB `.bss` array so its own image covers 0x400000-0xB00000 (engine globals and a stub at 0x40BCF0 become ordinary memory; `VirtualProtect` the stub page RWX); `-static-libgcc -static-libstdc++` (a plain dynamic MinGW exe dies silently under WINEDEBUG=-all). Never call `GetWindowText` on a window of the same process from a watchdog thread (blocks on the stalled main thread).


### perf-lab 0.2.0 harness (`harness/smoke_perflab2.cpp`)
Same `.bss` trick, but the harness must NOT link libstdc++ statically: that grows `.text` past 0x4261CF and the TX experiment would patch the harness's own code (check `objdump -h`: `.bss` must start below 0x420000). Build `i686-w64-mingw32-g++ -O1 -o smoke_perflab2.exe smoke_perflab2.cpp -lgdi32 -lglu32` and copy `libstdc++-6.dll`, `libgcc_s_dw2-1.dll` (`/usr/lib/gcc/i686-w64-mingw32/13-win32/`) and `libwinpthread-1.dll` (`/usr/i686-w64-mingw32/lib/`) next to it (the DLLs present, a dynamic exe runs fine). Run `smoke_perflab2.exe off`, `refuse`, `run` (each exit 0). Result 2026-09-30 (kpatch DLL md5 `cac5201b1c02b69b6a13556f3fb02792`): all pass; handler cost bucket/movie 6 ns, GetImage 26 ns, resman hooks ~0.8-1 us (SafeRead VirtualQuery of the key entry; thousands of calls per load = a few ms).

## perf-lab 0.3.0 (Phase 4, 2026-09-30)

- `AI ticks max_n max_n_level obj_updates obj_ms obj_max_ms obj_slow10ms prepass_iter tick_ms_est tick_hist(<1,1-2,2-5,5-10,10-20,20-75,75-200,>=200 ms)` (tick time = entry -> last object post, estimated at the next entry; the epilogue is too short to hook), `PATH calls pending ok fail other ms max_ms | EFFECT apply remove`.
