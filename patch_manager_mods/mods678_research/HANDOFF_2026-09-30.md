### Tint predicate research (in progress at checkpoint; evidence from full dump `decomp/8a/008ac330.{c,asm}`, `decomp/5b/005bd6a0.{c,asm}`)
- `0x8AC330` is the equipment-slot item list (panel+0x5098 = slot mask being filled). For each backpack item it: skips items whose baseitem (`0x6D6E30(item)`) slot mask `(base+4) & slotMask == 0`; gender restriction `base+0xB4` (1/2) vs creature `stats+0xE0`; then **`0x5BD6A0(creature; item, &slotMask, 0, 0, 0)` RET 0x14** = "can this creature equip item in slot" (ECX = creature, `[ebp-0x4c]`); 0 => `SetCanUse` state 2 (red-orange), plus a second-hand/dual-wield check giving state 3. `0x5BDA40(item, slotMask)` = slot-fit test used inside it.
- So the Mod 6 tint predicate should be: slotMask = first bit of `(baseitem+4)` equipable-slots for the item (or iterate bits), `ok = 0x5BD6A0(shownCreature; item, &slotMask, 0,0,0)`; skip tint for non-equippables (consumables, upgrades; slotMask 0). `shownCreature` is the panel's current creature (`[ebp-0x40]` in Populate `0x8A7BA0`, from `0x77D800`). Still to verify in asm: which args of `0x5BD6A0` produce feedback messages (param_4/param_6 == 1 send `0x584DA0` feedback - we pass 0, so silent), parameter order (asm push order at `0x8AC77A..0x8AC78B`: pushes 0,0,0,&slot,item; ECX=creature), and whether the slot mask must be a single bit.
- Then "Usable" cycle state: decide between this equip predicate and engine mode 5; recommend: Usable = equippable OR activatable.
